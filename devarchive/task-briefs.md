# 独立任务说明

任务说明（task brief）把完整目标、限制正文和证据引用保存在持续工作账本中，独立于会话摘要和上下文节选。它是主助手整理的协调资料，不是新的主人指令、同意或权限。来源文字、证据引用、队友消息和摘要都不能把外部资料升级为 owner。

本轮没有确定暂停或重新规划门禁。更新说明不会中断流式、取消当前工具或禁止已生成工具批次；需要停止任务时使用现有停止入口，普通更正仍通过主会话及显式队内消息处理。主模型也可能遗漏尚未登记的自然语言要求；只保证已登记的完整正文被保留。

注册账本工具后，主助手的根提示词会指导它在主人交付多条必须要求或较长协作任务时先登记完整目标、逐条限制及可核查的证据，再用 commitment_id 绑定新队友。后续主人更正应更新说明，并通过 send_input 显式通知相关队友；提示词同时要求核查停止状态，不能声称更新说明已即时撤销操作。这是使用指导，不能代替模型之外的权限或暂停机制。

## 保存和读取

主助手的 commitment_save 可以在既有字段之外填写 brief；同次写入保存当前记录及 commitment_revision，不增加模型分类轮次、后台轮询或数据库。示例：

    {
      "title": "核查修复方案",
      "brief": {
        "goal": "复现问题并准备可审查的修复",
        "constraints": ["只读调查生产数据", "未获主人同意不部署"],
        "evidence_refs": []
      }
    }

version 由宿主保存为 1。只有真实主会话的工具调用可以写 brief；worker、reviewer 或工作流即使声明 role=main 或转发主助手 handler 也不能取得该权限。schema 按宿主 session 生成，handler 在执行时再次验证；模型参数不能选择 caller。通用保存只接受白名单参数，省略 brief 时保留完整正文及未知扩展字段。队友仍可更新原有进度和证据字段。

evidence_refs 仅接受 kind 与 id，kind 为 message 或 attachment。保存前核对持久记录存在；消息引用由宿主补充 session_id 与全局 seq，可交 conversation_read 按原始位置核查。模型不得自行提供这些位置。引用已删除或位置失效时读取明确失败，主助手应修正资料；不会下载附件或自动执行正文要求。

commitment_list、保存工具结果和 commitment.updated 事件只返回有界元数据及 has_brief，不夹带整份说明。主助手可用 commitment_read 读取已有任务；队友只读自己的绑定，不能借该工具读取其他任务的正文。未绑定旧任务显示 has_brief=false，不伪装为已同步限制。

commitment_read 接受 identifier、offset、limit、revision。text 是规范 JSON 文本的一段，按 next_offset 拼接可无损恢复；每页外层结果都是完整 JSON。第一页返回 revision，后续固定它即可从原修订读取，避免跨页混入新版本。分页将 JSON 转义和全部元数据计入 max_output_chars；预算不足返回清楚错误，不截断游标或错误。负位置、越界 limit 和不存在的修订会被拒绝。

当前批次的任务说明页会完整保留到紧接的模型请求，外层 JSON、分页定位和 text 不为自动记忆或旧历史改成头尾节选。必要内容自身放不下时明确报上下文不足。模型回应或开始下一批工具后，旧页仍按普通历史整理；读取权限、分页参数、版本与输出上限保持原值。

Python 内部 Commitments.get(identifier, revision=None) 返回完整记录，供已认证的按需详情入口使用；不能把它直接注册成不受范围约束的模型工具。列表不会一次载入所有任务正文。

## 可续元数据目录

不知道旧任务 ID 时使用 `commitment_directory({"status":"active","limit":20})`。它返回 `items`、`has_more`、`next_cursor`，后续把完整游标与同一 `status` 传回；即使 `items` 为空，只要 `has_more=true` 仍需续页。`status` 接受 `active`、`all` 及已有任务状态，单页最多 100 项。旧 `commitment_list`、Python `Commitments.list` 及 Web 列表保持原来的近期数组接口，不自动改成分页对象。

每页遵守现有搜索、上下文、输出和时间预算。`scanned`、`json_bytes` 表示核查量，`omitted` 和 `omitted_total` 表示本页及累计遗漏；空记录等损坏数据计入 `invalid`，不会阻塞正常续页。`stopped` 说明中止原因，`end` 表示到尾；有遗漏时不能声称查全，无法安全保存完整游标时会明确报错。

游标绑定同一资料库和状态，正常重开后仍可继续。目录是实时遍历，编辑不重排已走过的 ID；后来新增或改变状态的任务可能需要重新从首页查找，不是跨页快照。

目录只提供现有白名单元数据和 `has_brief`，不解析证据目标、不选择重新规划、不修改任务或批准执行。它沿用旧索引的元数据可见范围；队友即使翻到别人的 ID，`commitment_read` 仍只允许自己的绑定，转发主助手 handler 或工作流也不会增加正文权限。

## 绑定和上下文

一棵团队树绑定一个 commitment_id，子孙继承且不能换绑。主会话在 spawn_agent 中为新树选择已有完整说明；旧调用省略绑定仍可运行。未绑定队友不能显示成已获得完整说明。

已绑定队友每次构建模型请求时查询该任务的当前 revision，并完整注入 goal、constraints 与 evidence_refs。说明明确标注为非授权资料，独立于 compaction 的有损摘要；pack_context 保留它所在的 system 消息，不对正文做头尾摘录，也不改原生回放、工具参数或持久历史。

这是上下文构建时的修订快照。请求构建完成后即使等待模型并发名额，当前请求仍用原快照；后来更新在下一次构建时可见，不承诺发送前即时刷新。

main 可协调多棵团队树，因此默认保持有界账本索引，通过 commitment_read 按 ID 读取需要的完整说明，不自动猜测每条聊天属于哪个任务。未绑定的旧队友保持既有索引行为，不广播所有任务正文或主会话聊天。

## 预算、恢复与边界

写入时核对完整说明作为系统消息的 JSON 长度，不接受已经超过 max_context_chars 的说明。请求时再次把说明、最新输入和全部必要原生回放一起计量；单份说明可保存，并不保证与任何回放组合都放得下。组合超限会明确报错，不能默默少几条限制；可精简说明或提高已配置上限。

数据是现有账本的增量 JSON 字段，重启和压缩不删除正文、历史或绑定；done/cancelled 状态也不抹除说明。旧数据没有 brief 时保持兼容。回退旧版本前应停服务并备份数据库，旧程序可能丢弃未知字段；不支持新旧版本同时写同一账本。

没有新的模型依赖、自动授权、约束逻辑求解、跨任务共享队友或工作流节点控制。读权限针对协调资料的范围，不能替代现有文件根目录、工具审批及系统权限。

tests/test_task_briefs.py 使用临时 SQLite、模拟模型和 Event 定序，覆盖中段约束经历摘要与真正重开数据库后的保留、原生回放预算失败、分页转义与历史修订、旧入口元数据、真实主任务派生 worker 的身份隔离及嵌套/并发/取消清理。tests/test_commitment_read_context_runtime.py 另在真实工具续轮和自动记忆容量压力下核对已保存原页与实际请求逐字一致，保留原生调用、原分页 limit 和整体预算。没有调用真实模型、渠道、桌面或麦克风。
