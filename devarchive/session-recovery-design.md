# 会话恢复与当前执行

状态：2.13 A 已实现，通过独立后审查与完整本地验证，基于 `06ec350`，尚未发行。本片只修当前运行、可操作审批与可见工具状态；显示投影数据库、首屏字节预算、长期浏览器内存与原始 SSE 大帧仍属后续工作。

## 事实与许可

session/run/approval 对象、工具消息和已提交事件是持久证据。`Runtime.tasks/run_ids` 与 `Permissions.pending` 是当前进程仍拥有执行与等待者的证据；它们不会在重启时恢复。旧的 `run.started` 或 `approval.requested` 只能说明过去发生过相应动作，不能重新产生任务或批准许可。

队友的[命令结束续办](../docs/shell-sessions.md#命令结束后由原队友继续)登记同样只在当前实例内有效。等待和就绪不写入持久排队或待投递输入；只有真实新运行建立后，才保存绑定该运行的已交付工具事实。重启不会从登记回执或历史事实重建等待，也不会重新执行未知命令。若另有真实新输入，仍按原输入恢复规则处理；任务是否完成须另行核查。

`Permissions.resolve` 已同时要求未完成 future 与持久 pending 审批。显示接口必须按有效 future 的 ID 定位审批，再核验 session/run/status；不能先取最近 200 条审批再筛 pending，也不能仅从历史事件恢复审批按钮。提交审批仍由原权限门检查，快照不构成新的授权。

`Runtime._recover` 保持原有状态转换：未完成 session 变 idle，run/approval 变 interrupted；paused 不被改成自动继续。对实际变更把恢复事实与窄 `session.recovered` 事件同一事务提交，复用 `Store.event(objects=...)`。这样原页面从旧 SSE 位置恢复时也能结束假运行与旧审批。恢复事件不调用 `_repair_tail`、模型或工具，不发起重试。

## 快照与续接

在原 `/api/conversation` 增加 `live` 与精确十进制字符串 `after`，保留原消息和历史事件。`live` 包含主 session ID、核验过的当前执行 run ID、对应持久 run 的窄状态摘要及有效审批。没有真实任务时不得仅凭持久 running 字符串宣称正在运行。无活动 run 时，可用已加载历史中最后一个可验证 run ID 读取持久状态；不扫描全库猜测“最近运行”。

在同一无 await 的宿主步骤内读取事实和事件位置。当前 Runtime 使用单事件循环协作调度；此步骤不允许插入异步调用，未来若改为多写入进程，必须重新建立一致读取合同。[Python asyncio 文档](https://docs.python.org/3.13/library/asyncio-task.html#task-object)说明任务在等待时才让出事件循环。本合同不宣称跨多个独立 Runtime 共写资料库的一致性。

hydrate 先重放历史恢复文本和时间线，再用 `live` 盖定当前运行与审批。处理真实终态事件已经落盘、电脑清理尚未完成而持久 run 尚未最终写回的窗口：同一个 run 的可验证终态不会被暂存 running 行重新激活。没有活跃运行时，未完成流文本保留为中断片段，而不是继续动画。

会话 SSE 从该快照的 `after` 接续；全局管理失效仍沿用 2.12 在快照前捕获的位置。历史事件 ID 按字符串返回，不经 JavaScript 浮点数往返。reducer 保留快照位置下界，即使 SSE ID 被重置、旧帧重放，也不把已被当前事实覆盖的历史变成新操作。新快照与 SSE 都继续受 2.12 connection owner 约束，旧请求和旧连接不能覆盖当前状态。

`after` 是事件 ID，不是 epoch，也不是完整显示投影序号。资料库替换、备份回退和事件序号复用的 reset 协议不在本片保证范围。

## 工具结果

| 证据 | 显示规则 |
| --- | --- |
| 明确 `status=unknown` 或 `outcome=unknown` | 结果未知；即使带 error 也不称为已失败或未执行 |
| 明确 `not_executed`，或可验证的 completed/failed 结果 | 保留该终态，不因另一运行中断统一改成 unknown |
| 只有 started，运行已无当前执行所有者 | 结果未知，保留原调用与参数；先核查实际状态，不自动重做 |
| `_repair_tail` 合成的 interrupted/unknown 工具消息 | 在可见卡片缺乏可信终态时校正为未知，不重新执行 |

`tool.completed` 事件先于 `_execute` 的工具消息写入。崩溃可能留下真实终态事件却没有配对消息；下一次 `_repair_tail` 仍会补 unknown。该合成消息不能抹掉已提交的可信完成、失败或未执行证据。

事件名 `tool.completed` 本身不代表成功。旧结果可能因字符预算被截成不可解析 JSON；若无法验证结果且存在 unknown 恢复证据，应保守显示未知。新事件附上在截断前确定的结构化状态，避免通过解析被截断正文猜测结果。显示分类不改变工具调用、权限、模型历史、compaction 或执行重试语义。

本片只校正现有消息/事件窗口内可见工具；不保证找回窗口外全部工具，也不在本片建立跨 run/turn 的完整 invocation 投影键。

旧 provider 调用 ID 可能在后来批次复用。恢复只采用最近可见 assistant 批次的 unknown 收据，且不能以无法证明同批次的旧消息覆盖当前活跃工具。此限制避免旧结果染到新调用，不冒充完整 invocation 身份重构。

## 验收范围

- 合成 SQLite 重开后，idle/interrupted 持久事实压过旧 started/requested；旧审批提交仍被拒绝，且没有模型/工具调用。
- 远早于最近审批历史的有效 future 仍可见；done/cancelled future 与非 pending 行不可操作。
- 原页面保持旧游标跨进程重启后收到恢复事件；重复恢复无额外状态变更，也无执行。
- 快照位置之后立即完成、开始新 run、请求/解决审批的门控顺序均可接续；旧快照、旧连接、位置以下帧不复活历史。
- cleanup 暂停期间已知终态仍保留；真实活跃审批和部分文本继续恢复。
- unknown/status/outcome、not_executed、普通失败、可信完成、截断旧结果与合成 unknown 的优先级有直接回归。

所有本地验证经过 `scripts/check_local.py`，只用临时资料库、假任务/future 与可控 promises。结果另记；未进行真实模型、设备、外部集成或真实浏览器验收。
