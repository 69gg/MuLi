# 暂停、补充要求与继续任务

需要改变正在处理的事情时，先暂停对应任务，再补充要求、交给沐璃重新规划。任务说明中的目标、要求和已有依据会保留，不会因对话压缩或队友转述而被替换。

任务控制针对已经登记任务说明的工作及其关联队友，不会暂停主助手的所有聊天，也不影响其它独立任务。

## 在工作台操作

1. 打开团队列表，找到关联队友，点击“查看任务说明”。核对目标、要求和受影响的队友范围。
2. 点击“暂停任务树”。界面显示“已暂停后续操作”后，该任务尚未开始的写入、外发和电脑操作会被阻止。
3. 想继续时，点击“补充要求并交沐璃”，填写新增限制或下一步要求，再点击“交沐璃重新规划”。没有新增要求时可以留空。
4. 回到主对话查看沐璃的分析和新计划。主助手需要读取完整任务说明，在后续一轮确认计划并通知队友，任务才会继续。

“已交沐璃 · 仍暂停”表示重新规划请求已接收，不表示队友已经恢复执行。“新计划已确认”也不等于成果已经完成；可以继续查看队友状态、报告和实际证据。

补充要求会追加到原任务中，不会删除原目标或旧要求。若新旧要求冲突，请先让沐璃说明冲突并与你核对。确认计划不会跳过 ask、auto 或 yolo 的原有工具权限规则；需要人工批准的操作仍会等待批准。

## 在手机上操作

Telegram 和 OneBot/NapCat 的已绑定主人可以在私聊中发送：

```text
/任务
```

回复会列出可控制的任务，并给出可复制的操作指令。先复制对应的 `/暂停` 指令；收到暂停确认后，再使用其中的 `/调整` 指令，附上非空的补充要求。

```text
/暂停 <回执中的短码>
/调整 <暂停回执中的短码> 只生成本地草稿，暂不发送
```

上面的尖括号是占位说明，实际发送时使用回复里给出的完整短码。不要自己编造短码，也不要把另一个账户或聊天中的旧回执拿来使用。状态已变化或短码失效时，重新发送 `/任务` 获取当前指令。

这些命令由程序直接处理，不需要等待模型猜测你想控制哪个任务。控制确认发回原私聊；查询或在其它聊天窗口插话不会把既有回复自动改派过去。QQ 官方机器人和微信 iLink 目前没有这组任务控制命令。接入方式见[消息渠道](channels.md)。

## 暂停、停止和关闭页面的区别

- **暂停任务树**：保留原任务与要求，阻止尚未开始的新操作，便于补充要求后继续。读取资料仍可能继续。
- **停止队友或当前运行**：结束对应执行，不等于已经为任务登记了暂停和新要求；想调整整项工作时使用任务说明中的控制入口。
- **关闭网页或手机聊天**：不会暂停后台任务，也不会恢复已经暂停的任务。

已进入的 HTTP 请求、文件写入或桌面动作可能仍在收尾，暂停不能撤回已经发生的效果。看到“结果未知”时，先核查文件、投递记录或实际应用状态，再决定后续操作；不要把“重新规划”当作安全重试所有旧动作。

## 约定稍后继续

可以在暂停后明确告诉沐璃：“明早九点继续这项任务，还是交给原队友；过十点就不要开始。”这类一次性约定会绑定具体任务、原队友、当时的要求和回复来源。到期后仍需主助手读取说明、确认新计划，再由同一队友续办，原工具审批照常生效。

任务要求、队友身份或权限模式变化可能使约定失效；错过截止时间也不会自动开始。需要取消时，请沐璃查询并取消那条准确约定。它与“每周执行一份独立委托”不同，详见[提醒与主动事项](attention.md)。

## 常见情况

| 提示或状态 | 怎么处理 |
| --- | --- |
| 尚未登记任务说明 | 请沐璃先保存这件事的目标、限制与依据，再关联队友。普通聊天不自动变成可控制任务。 |
| 任务说明有更新 | 刷新并核对最新要求，再提交；不会自动替你接受变化。 |
| 此任务含活动工作流 | 先在工作流页停止该执行或等待结束，再暂停任务。当前不支持整棵活动工作流中途暂停后原地续跑。 |
| 提交结果待确认 | 使用界面的“重试原操作”，查询同一次提交的结果；不要同时新建相同操作。 |
| 主模型未配置或队列已满 | 先完成模型配置或等待空间，再重新提交要求；任务仍保持暂停。 |
| 重启后仍是暂停 | 这是正常状态。先查看已完成步骤和未知结果，再明确交给沐璃重新规划；重启不会自动批准旧计划。 |

要核对要求、成果与依据，见[任务核查](task-inspection.md)；要了解分工和队友进度，见[多 agent 协作](workflows.md)。
