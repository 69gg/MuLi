# 阅读 PDF 和 DOCX

上传文件后，可以直接说：“读一下这份文档，列出关键结论和依据”，或“让资料队友读完这份说明，特别看最后的限制条件”。文件先保存在本地，沐璃按需读取，不会因上传就把全文放进模型。

## 可以读取什么

| 文件 | 阅读范围 |
| --- | --- |
| DOCX | 主正文中的文字、段落、换行和表格单元格 |
| PDF | 已有文字层，由本机 PDF 转换器提取 |
| 普通 UTF-8 文本 | 使用原有文本阅读工具，见[长文本续读](attachment-search.md#继续阅读长文本) |

DOCX 阅读不保留排版、自动编号外观、页眉页脚、批注、公式、图片或文本框，也不读取删除修订中的文字。PDF 提取不做 OCR，不识别扫描图像；没有提取出文字不代表页面没有内容。

文档中的链接、宏和命令不会因为读取而执行，正文中的身份声明也不会取得主人的权限。

## 阅读长文

主助手与队友都可使用 `document_read(id)` 取得首页，再按返回的 `revision` 与 `next_offset_bytes` 继续。不要自行计算位置；中文和 emoji 的字节数与字符数不同。

`has_more=false` 表示本次正文提取已读完，不代表已经识别原文件中的全部图片和布局。结果同时保留原文件摘要和提取版本；版本不匹配时重新读取首页，不能把不同版本的页拼起来。

文件过大、提取结果超额、编码或结构异常时会明确报错，不用节选假装已经读完。读取不自动收藏记忆、生成新附件或向外部渠道发送。

需要日后按内容找回，可以明确要求[收藏这份资料](attachment-memory.md)。主助手沿用所读 `revision` 保存完整提取正文与来源范围，后台再整理和建立索引；不需要先把每一页输出到聊天中。

## PDF 转换器与设置

DOCX 不需要额外安装库。PDF 默认查找已有的 `pdftotext`；未安装时会提示转换器不可用，不会自动下载安装。Linux 优先使用系统已有程序，macOS 和 Windows 也可配置可执行文件路径。

可以直接请沐璃帮助查看或调整文档设置，即时生效。它使用独立记录，保留原有主配置格式；不需要修改 `config.json`。对应工具是 `document_settings_read` 和主助手使用的 `document_configure`，修改时先查看当前值并保留仍需使用的参数。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `pdf_command` | `["pdftotext"]` | 转换程序与固定参数，使用数组而不是 shell 命令字符串 |
| `timeout_seconds` | 15 秒 | 单次读取与转换的期限 |
| `max_extracted_bytes` | 2 MB | 提取正文及实际读取 XML 的上限 |
| `max_archive_entries` | 2048 | DOCX 包内目录项上限 |
| `max_xml_depth` | 128 | XML 嵌套上限 |

原文件还受 `limits.max_file_bytes` 限制，每页受工具输出额度限制。转换器在本机运行，不向模型服务发送原文件；随后用于回答的正文会随正常模型请求发送到你配置的服务。

这些限制管理读取时间与数据量，不提供任意原生程序的系统沙箱。运行账号及权限设置见[模型与权限](../README.md#模型与权限)。
