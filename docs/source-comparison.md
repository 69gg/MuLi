# 核对两份资料的变化

先明确[收藏](attachment-memory.md)两份资料，再对沐璃说：“把新版报名说明与之前那份比较，核对截止日期和材料要求改了哪里。”沐璃会先确认左右两份资料，不根据文件名或时间猜测新旧。

比较支持已收藏的 UTF-8 文本、PDF 文字层和 DOCX 主正文。结果按行列出新增、删除和替换的原文，保留双方来源及位置；可以再让沐璃读取对应上下文。空白、大小写和换行也算变化。PDF 图片、文档排版等不在正文比较范围内。

Windows 也沿用同一 UTF-8 比较协议，中文和表情不受系统管道编码影响，原有换行保持不变。

差异较多时分段返回，仍有后续结果就继续读取。没有读完不能据此判断“其它内容都没变”。超出当前来源、行数、输出或时间额度时会明确失败，不用节选冒充全文核对。

长资料可以说：“先只看两份说明的变化概览，再核对期限那一段。”概览给出新增、删除、替换的组数及受影响的整行数量，不带正文；沐璃可按返回位置读取关注的两侧原文。替换同时计入左侧移除和右侧加入，数量不代表重要程度；读完概览也不代表审阅过所有正文。大段差异放不进正文页时，仍可先取得位置，原有输入、行数和时间额度继续适用。

网页中可在来源目录选择左侧资料，再选择另一份“与所选比较”。每块变化都有“核对左侧此处原文”和“核对右侧此处原文”，从对应来源的准确位置分段阅读，也可选择“从头阅读”。空侧会说明此处没有对应正文；变化位置在末尾或该侧全文为空时会明确提示，不显示虚构的正文页。

原文中的“返回这段差异”会重新读取原来那段比较，并回到刚才的核对入口；关闭则回到最初的来源目录入口。遗忘或更新任一侧来源后，旧原文、比较和返回入口失效，需要重新核对。

比较沿用已有并行工作额度；容量满时稍后再试，不会不断排入后台。关闭服务或重配时会停止尚未完成的比较。

比较只读已经收藏的正文，不重新提取原文件、不调用检索或比较模型，也不自动改写记忆、书签或向手机发送。用于解释结果的原文仍会随普通对话发送到你配置的模型服务。原附件丢失后，已保存正文仍可比较；只有摘录卡而没有收藏旧稿时，无法还原整份旧文。

遗忘任一来源后，旧续查入口失效。重启后可以从首页重新比较；比较本身不建立额外的正文副本或资料版本库。

主助手和队友使用 `memory_compare_sources`，携带两份准确 `source_id` 与各自的来源 `revision`。需要继续时，保持左右顺序和版本，传入返回的 `next_cursor`；不要把原文件摘要或文档阅读版本当成来源版本。

已认证管理 API：`POST /api/memory/sources/compare`，正文为 `left_id`、`left_revision`、`right_id`、`right_revision`，以及可选的 `cursor`、`view`。`view` 默认 `changes`，返回差异正文；`overview` 返回无正文目录，首页另含 `totals`，续页须保持相同视图，游标不可混用。来源正文和版本可由[来源目录](memory-sources.md)查阅。

概览每侧的 `start_line` / `end_line` 是从零开始、左闭右开的行区间，按 LF 分行并保留 CR；末尾换行不额外生成一行。`offset_bytes` / `length_bytes` 是 UTF-8 原文区间，可用 `read_arguments` 交给 `memory_source`。零长度侧只是插入点，不读取虚构正文；非空段可按普通分页读取，读到该组结束字节即可，不以全文的 `has_more` 判断这组是否读完。
