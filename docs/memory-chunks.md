# 长资料的检索

收藏一份长资料后，可以直接问：“这份说明最后提到的验收条件是什么？”不必重新上传或把全文留在当前聊天里。

超过 12000 字符的来源会在后台分块，供已有的 `memory_query` 查询。即使关闭自动事实提炼，正文后半段仍可通过本地关键词检索；配置 embedding 后，这些块也参与语义检索。检索到的段落保留来源，继续用 `memory_source` 核对完整原文。

原文块属于资料摘录，不是新确认的事实。来源原来的身份和信任属性保持，文件里的指令、身份声明和偏好不会因此取得主人权限。

## 设置

可以请沐璃：“查看长资料的分块设置”，或“每块改成 3000 字符，其余保持”。主助手先用 `memory_chunk_settings_read` 查看，再用 `memory_chunk_configure` 保存完整设置，即时生效，不必修改主配置格式。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `chunk_chars` | 2000 | 每个原文块的最大字符数 |
| `overlap_chars` | 128 | 相邻块保留的重叠，必须小于块大小 |
| `max_chunks` | 64 | 单个来源的块数上限 |
| `batch_size` | 4 | 后台每批处理的条目数 |

字符数包含中文、英文和 emoji，不是模型 token 数。来源仍受原有全文上限约束；超过完整分块额度会明确失败，不把部分正文标为完成。当前作业或重建计划开始后，按冻结参数续接；普通作业保存的分块也沿用其原参数。对于由旧版完成的来源，以新请求键再次重建时会按当时策略重新规划，即使以前补过块；修改策略可能增加条目和请求量。

## 后台处理与重建

分块和向量请求由原后台任务处理，不阻塞对话。正常关闭后可以接续；失败重试会核对并复用已经成功写入的向量。请求已发送但尚未确认保存时，仍可能再次收费，不能保证外部请求只发生一次。

已完成的旧资料不会在开机或查询时自动全库补块。需要时明确要求为选中的来源[重建语义索引](memory-reindex.md)，同时补齐缺少的原文块。更换 embedding 后也需要明确选择重建，旧原文、事实和关系继续保留。

embedding 与 reranker 会把相应文本发送给你配置的服务，分块会增加索引条目和请求量。可以调整单批大小；没有配置 embedding 时仍可使用本地关键词查询。检索继续受候选、向量扫描及输出额度限制，建立全文索引不保证每次查询都能召回所有相关内容。

长来源已完整分块时，不会再为未修改的重复归档头部单独请求向量；归档记录仍然保留。模型提炼或用户更正的独立条目继续按其实际内容处理。

要求遗忘一个来源，会同时移除原文、块、向量和派生记忆；重开或重建不会使墓碑来源复活。附件库中的原文件仍需分别管理。
