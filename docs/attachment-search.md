# 查找已保存的附件

想找较早的文件、转写或视觉解释时，可以让沐璃按名称和来源查询附件库。`attachment_search` 能继续翻阅目录，不局限于最近的附件列表。

它只查目录元数据，不读取正文，也不确认文件此刻仍然存在。想按正文主题长期检索文本，需要先[明确收藏附件](attachment-memory.md)。

已经选定一份资料时，可直接[在正文里查找文字](attachment-find.md)，再阅读命中位置，不需要先收藏。

## 使用方式

例如：“找一下名字里含交接说明的附件”，或“查找这段录音已经保存的转写，不要重新转录”。

对应工具为 `attachment_search(source?, name_query="", cursor?, limit=20)`：

| 字段 | 用途 |
| --- | --- |
| `source` | 可选，精确匹配来源；不填则查全部来源 |
| `name_query` | 文件名包含的文字，默认空字符串 |
| `cursor` | 继续上一页时使用返回的 `next_cursor` |
| `limit` | 每页返回上限，默认 20，最多 100 |

名称和来源区分大小写；名称按字面匹配，`%`、`_` 不是通配符。筛选文字最多 120 个字符，空格也参与匹配。换筛选条件时从第一页重新查。

结果中的目录项提供附件 ID、名称、来源、类型、大小、摘要和下载入口，不直接提供文件正文。选中后再按资料类型读取。

PDF 和 DOCX 可用 `document_read` 继续读取提取正文，范围与配置见[文档阅读](document-reading.md)。

## 找回转写和视觉解释

**录音转写：** 按 `source="asr"`、`name_query="原音频ID"` 查找。取得工件 ID 与 `sha256` 后，用 `audio_transcript_read` 读取已保存的转写，并按回包继续翻页，不需要再次调用 ASR。

**视觉解释：** 只有看图时显式使用 `image_describe(..., archive=true)` 才会存档。可以按 `source="vision"`、`name_query="原图ID"` 找回，用工件 ID 与摘要调用 `attachment_read`，继续读取原提问、解释及原图版本，不再次调用视觉。

视觉解释用 `attachment_read` 的 `revision` 和 `offset_bytes` 续读；转写使用 `audio_transcript_read`。

历史视觉解释即使仍可读，也不证明原图现在存在或没有改变；解释本身仍是模型资料，不是主人确认的事实。

## 继续阅读长文本

普通 UTF-8 文本使用 `attachment_read(id, offset_bytes=0)` 取得带版本的首页。后续回传同一 `id`、返回的 `revision`，并把 `next_offset_bytes` 作为下一次的 `offset_bytes`；直到 `has_more=false` 才读完。位置按 UTF-8 字节计算，不是字符数，不能自行加减。也可以用目录摘要作为 `revision` 从首页读取。

不传分页参数时仍返回原有的 `id/content/truncated` 预览；`truncated=true` 表示只看到了部分正文，可重新显式读取首页。分页不会绕过文本读取上限：每页都会核验整个文件的版本、UTF-8 编码及二进制标记，正文和定位信息一同计入输出预算。版本变化、文件不可用或校验失败时会明确报错；不要把错误当成 EOF，也不要把不同版本的页拼接起来。

需要压缩或重开后找回某一位置，可以明确要求[保存续读书签](reading-bookmarks.md)；普通阅读不自动推进位置。

## 游标和有界行为

每次查询只处理一段目录。`has_more=true` 表示还有未检查的范围，不保证下一页一定有匹配项。即使本页 `items` 为空，也应沿 `next_cursor` 继续；只有 `has_more=false` 才表示本次目录范围已到末尾。

目录按附件 ID 续页，不按创建时间排序。查询期间新增文件可能需要刷新第一页才能看到；它不是固定快照。不要修改或拼接游标，也不要把另一组筛选的游标拿来继续。

目录记录可能对应已删除或变化的文件。读取时以实际文件与版本核验为准；出现明确错误时应先处理，不要把错误当成“没有更多结果”。

查询不会调用视觉、转写或模型，也不会自动收藏、发送或恢复执行。如何把选中的文件交给队友，见[资料交接](teammate-attachments.md)。
