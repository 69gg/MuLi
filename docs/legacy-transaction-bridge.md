# 失败迁入后的原服务事务

这是 V2 整合中的内部边界，尚未连接用户管理入口。

迁入 managed 模式失败并恢复 legacy 入口后，原服务仍需能够修改配置或重启。`prepare_legacy_after_managed` 为此创建一个新的 V1 generation，不改写已完成的 V2 历史。调用宿主必须先认证当前服务进程；函数自行核验实际 writer lease、同一 Store/main session、精确终态投影回执、完整格式标记、保留安装及当前解释器。

只接受 base 为 legacy 的 aborted 或 rolled_back。配置、unit 必须已经恢复到冻结的 base 字节，selector 必须缺席，两个 role 的快照均须完整。新记录使用当前 V1 安装清单身份，不把 V2 slot 摘要混作 V1 安装摘要。准备快照后再确认文件和数据库，最后才替换同一个 state.json；上一代仍保留。不覆盖手工修改，不恢复旧数据库，也不执行系统服务动作。

定向测试覆盖两种真实终态链、错误投影、配置/unit/selector/格式变化、八个写入前后中断位置，以及在 Settings 解析前拒绝超预算配置。17 项测试通过，独立只读复审通过；和协议、日志、控制器及 probe 合并检查共 253 项通过（5.33 秒、峰值 87 MiB）。所有检查使用统一资源守卫并串行运行。这些结果只证明内部边界，完整 A/B 入口仍需后续运行时整合验证。
