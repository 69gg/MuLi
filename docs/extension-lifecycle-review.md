# MCP / Skills 代际生命周期修复

本片修复首次扩展加载漏掉并发目录编辑，以及会话已观察到的 Skill 激活失效在旧文件恢复后自动复活的问题。实现范围只有扩展发布器、Skills 会话状态及两者的回归；不增加监视任务、不连接真实 MCP 服务，也不改变系统错误的来源路由。

## 首次加载必须对应读取过的来源

原实现先准备 MCP / Skills 候选，再发布，最后读取当前目录指纹并同时记为已加载和已观察指纹。MCP 握手、工具目录读取以及 Skills 文件读取都有等待点。如果文件在候选读取之后发生变化，最后一次扫描会把新来源记作旧候选的来源；监视器之后看到相同指纹，便不再排队。首次非法分片在 MCP 等待期间被修好，也可能被同样漏掉。

首次加载现在在准备前记录来源指纹，在发布前重新核验。来源变化时丢弃尚未发布的 MCP 候选，不把其中的 Skills 快照发布；任何未发布失败或取消都会清除待观察指纹，让后续扫描能重新排队，即使这是一次完整配置重建，且临时扫描错误恢复后来源指纹与上一代完全相同。校验到发布之间没有新的等待点，发布只记录已核验的来源指纹。

首次发现不可扫描的 MCP 目录或坏 Skills 来源仍允许 inline 工具和核心助手服务，但报告固定失败码，不声称获得了有效目录身份。准备前的指纹异常与来源准备分别降级，不能让 Skills 指纹错误跳过原本可用的 MCP 配置。成功恢复扫描后再准备新代。非法 YAML、非法 JSON 等未改变的失败来源仍遵守既有规则：不逐周期重新尝试连接；来源变化、目录通知或显式重试才触发新候选。

`tests/test_extensions.py` 的新门控覆盖：

- 首次 MCP 工具目录读取暂停时改写分片；包含原来合法和原来非法但现已修好的两种来源。
- Skills 完成正文读取后、返回快照前暂停，再修改文件。
- 启动监视器后等待一次实际成功发布，核对最终连接目录或 Skills 正文。等待使用有期限的事件，不用固定睡眠推断扫描已经发生。
- 不可扫描的初始目录仍保留 inline 工具，防止来源核验破坏首次启动的可用性。
- 发布前指纹复核期间关闭扩展时，候选被释放且不能发布，保留关闭后的生命周期边界。
- 坏 Skills 目录及 Skills 指纹抛出固定加载错误或 `OSError` 时，inline/core 工具仍可用；完整重建在最后一次扫描异常后，恢复相同来源仍会重新准备。

## 已观察的 Skill 失效不可自动复活

活跃指导按会话持久保存，修订由 `SKILL.md` 的原始字节摘要决定。原实现发现已激活项不存在或修订变化时，只在本轮上下文中过滤；只要目录还有其它 Skill，旧持久记录就留在数据库。恢复完全相同的旧文件后，摘要和正文再次匹配，旧激活会在没有新 `skill_read` 的情况下重新注入。

会话准备上下文并确实发现失效项时，现在立即持久保存过滤后的活跃集合。本轮仍给出 `changed_requires_reread_or_forget` 提示；恢复旧文件后需要重新调用 `skill_read`。其它有效指导继续保留，预算不足时仍完整保存并显式暂停，不因本片清除或截断。

这个清理只作用于正在准备上下文的会话，不在发布时扫描所有会话。如果删除或中间修订被发布后，该会话始终没有准备上下文，之后文件又恢复相同字节，原激活仍然有效；本片不把未观察到的中间状态当作永久撤销。

`tests/test_skills.py` 对主会话和 worker 分别覆盖“删除 / 改版 → 上下文失效提示 → 恢复原字节”，并检查仍需显式重读、其它有效激活保留。另有未观察中间变化的对照，以及失效清理与合法预算暂停并存的回归。主会话和团队继续共用已有的 Skills 上下文入口，不增加跨会话激活继承。

本片验证限临时文件、临时数据库和 fake MCP 客户端，不证明真实 MCP 服务器握手、外部账户权限、Windows 安全 Skills 文件读取或真实模型采纳指导的效果。既有“相同失败指纹不自动重复尝试”和“worker 结束不立即回收活跃指导”的边界保持不变。
