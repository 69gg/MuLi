# 2.40：最终模型请求中的记忆质量

状态：**2.40.0 已发布**。实现、受限全量后端回归、离线构建与独立后审完成；精确候选及 main 各十项、发行十三项全部成功，签名与 PyPI/GitHub 两构件元数据已核对。候选、main、发行和构件结果分别记录，不能以其中一项替代其余验收。

## 交付合同

复用已有分层记忆、来源、更正、冲突、遗忘、候选限制和两流公平分配。Runtime 在调用提供器前扣除本轮外层标题开销，共用完整 JSON 渲染器，不再对自动记忆结果直接切片。提供器整体超额即省略，普通一参数回调只调用一次；具名适配器显式接收预算与最新 user 的真实消息 ID。

仅排除可证明属于该输入的初始自动 episodic 副本，同源提炼事实、更正后条目、冲突资料和其它来源的相同文本继续可用。缓存排序保留，必要时仅一次有界本地补位，显式查询与持久内容不变。应用读取当前开关、预算和名额，不重配置后台 worker；无应用层的 fallback 共用相同渲染规则。

另整合独立格式读取失败观察：固定八个阶段、饱和整数毫秒及现有查询/VM 计数，单条最多 1024 bytes。保持原 1 秒、8 查询和清理失败优先，Store 仅传递读取器本次生成的 note。此片不宣称解释或修复原格式期限失败。

## 独立审查

独立 builder 先检查方案和实际代码，再编写四个真实 Runtime 请求验收。生产实现冻结后再作只读后审，发现合法 `max_candidates=3/context_limit=6` 下缓存与本地不同候选集合合并可超过候选上限的 P2。修复后初始结果、合并补位和返回均受 `min(context_limit,max_candidates)` 约束；小名额缓存也在当前名额内至多一次补位。新增确定性集合与真实 submit 名额 2→4 回归，保持缓存前缀、缓存原值与 worker 配置。独立复审确认 P2 闭合，未发现新 P1/P2；根另检查预算增长、最终完整请求、旧 callback、清理和错误转发边界。
