## macOS 退出清理

2.12 的 [发布矩阵 39442166058](https://github.com/69gg/MuLi/actions/runs/39442166058) 七项验证成功，macOS / Python 3.13 的输出合计预算测试失败：预期的输出超限 `ValueError` 在清理时被 `os.killpg(..., SIGKILL)` 的 `PermissionError` 覆盖。该作业其余 1661 项通过、31 项跳过；后续 prepare、PyPI 与 GitHub Release 全部跳过。未通过重跑掩盖失败，保留原标签。

[Apple XNU 的 killpg1 实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c) 在遍历进程组时跳过 zombie，找不到可发信号成员时，POSIX 路径返回 EPERM；找不到进程组才返回 ESRCH。这与短命子进程退出但尚未回收的窗口相符，原 CI 未保留进程状态，不能断言那次失败已观测到 zombie。Python 的 [asyncio subprocess](https://docs.python.org/3/library/asyncio-subprocess.html) 退出码和 wait 只证明直接子进程退出，不证明整个组已消失。

修复在信号权限失败时仍尝试回收拥有的直接子进程，继续有限排空并关闭管道，最多再等一秒回收。只有回收完成且信号 0 探测返回 ESRCH，才将那次权限错误视为已经消失的进程组；仍存在、仍拒绝探测或未能回收都报告原权限错误。不是直接吞掉 EPERM，也不因父进程退出而放弃清理持有管道的后代。

回归用真实小进程模拟组信号拒绝，由真实内核确认回收后的 ESRCH，验证仍返回原输出超限错误；另有受控对象验证权限失败后关闭管道、直接子进程回收、组仍在或不可探测时保留错误、回收无响应时有限退出。既有输出洪泛、TERM 宽限与父进程退出后遗留后代测试继续执行，不运行大规模压力测试。

独立静态后审查确认未吞掉真实权限失败；补入清理修复后全量 Python 1731 项通过、1 项 macOS 专用跳过，32.48 秒，受限 service 34.558 秒、CPU 27.359 秒、峰值 801.2 MiB、swap 0。Ruff、163 文件格式、73 源码严格类型检查与离线锁一致性再次通过。前端没有后续改动，沿用同一整合树的 257 项通过结果，不重复执行无变化的测试。
