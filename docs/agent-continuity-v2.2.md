# 2.2：任务说明与增量等待

本轮在持续主会话、持久团队和后台压缩之上补足两个边界：重要任务资料不依赖有损摘要，观察者等待新结果时不重复接收已看过的完成内容。实现复用现有 SQLite、commitment 修订、团队生命周期及事件通知，不增加模型、依赖或空闲轮询。

## 任务说明

一份 commitment 可附带完整目标、限制正文和证据引用，一棵团队树绑定一个 commitment。子孙继承绑定；根沐璃统一整理正文，队友继续更新工作进度。工具执行身份由宿主提供，模型参数、role 字符串、source_id 和队友自述均不能赋予根写权限。

每次构建绑定队友的新模型上下文时，读取一份当前修订的完整说明，作为明确标记的协调资料参与预算。正文不经过头尾摘录；与最新输入、原生协议回放一起放不下时明确失败。压缩快照仍保留自己的 seq/digest/generation 校验，原始归档不改。已经构建后等待模型名额的请求仍使用原快照，不承诺发送前即时更新。

根沐璃可通过只读工具按需分页读取说明，并固定修订避免跨页混合新旧版本。分页按外层 JSON 的最终长度计算，正文中的引号、反斜杠和控制字符都计入预算；游标和元数据不会被通用结果截断。列表、普通保存工具的返回值和更新事件只提供有界元数据，不广播所有任务正文。证据引用验证现存记录；消息补上宿主查得的会话及序号，便于读取原文。

管理界面只在相关队友旁提供“任务说明”入口，按需打开只读对话框展示目标、要求与修订；首页仍是对话，不增加常驻面板。详情读取沿用网页认证。

这份说明仍可能遗漏主模型尚未登记的要求，也不是新的授权。修改说明影响后续上下文构建，不撤回已开始的工具、不让已生成的批次自动失效。确定的任务暂停、主人限制变更与重新规划属于后续 2.3 控制协议，不能将本轮能力描述成即时撤销保障。

## 团队等待

不带 cursor 的 Python wait 保留原先“任一目标已终止就返回”的快照合同及完整旧结果。响应附带新的观察基线；带 cursor 后才进入增量模式。模型工具遇到超预算的完整快照时显式返回节选和历史引用，保留完整 cursor，避免通用截断令模型无法进入增量模式。

每次终态提交同步保存 agent、已有父报告意图和紧凑的 team.finished 事件，使用独立于 execution generation 的单调 completion_revision。排队取消、正常完成后立即进入下一代，以及重启恢复的 interrupted 均纳入统一边界。事件只记录有界结果预览与历史引用，不复制图片和原生协议块。

每个观察者持有自己的有界游标，不在队友身上设置全局已读。增量响应按持久事件回放已订阅基线之后的终态；只有实际返回的记录推进游标。超时返回紧凑状态，原游标不前进；两个观察者互不消费结果。版本、实例、调用方、目标和修订均校验，缺失中间记录或来自未来的游标明确失败。目标范围变化时，新加入目标建立当前基线，不假称已经回放其早期历史。

增量模式优先响应调用方真实主人输入，其次新完成记录，再处理其他邮箱活动；只报告可交付状态，不消费输入。通知与持久状态检查按既有 Condition 顺序连接，消除检查到挂起之间的丢唤醒窗口。同一调用方的多个等待独立登记，取消一个不会清掉其他等待或停止目标。

## 参考与验证边界

只读参考 `/data1/codex/codex-rs/core/src/tools/handlers/multi_agents_v2/wait.rs` 的邮箱/steer 唤醒，以及 `session/input_queue.rs` 的先订阅后检查。Codex v1 已终态快照也会立即返回，v2 没有这里设计的持久游标；不把 MuLi 的扩展说成照搬的现成功能。

`agent/control/root_handoff.rs` 与 `user_authorization.rs` 参考价值在于保留真实根输入及来源。它们属于 Guardian 授权上下文，不证明普通 worker 会自动获得根会话的全部更正。

回归使用假模型、临时 SQLite、Event 门控和真正的 close/reopen：覆盖多层压缩后的完整限制、跨任务投影、工具调用身份并发/取消、分页重组、逐代终态、排队取消、两个观察者、重启游标、新输入优先、等待环与结果预算。不调用真实模型或执行外部副作用。整合后首轮 745 项 Python、75 项前端测试通过；最终审查与发行验收另记于版本审查记录。

详细合同见[任务说明](task-briefs.md)和[团队等待](team-wait.md)。
