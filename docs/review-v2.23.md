# 2.23 候选更新审查记录

当前是开发验收记录，尚未发布 2.23.0。已发布版本仍为 2.22.0；此文件不把
局部测试、预览成功或进程收尾成功称为新版本已经可用。

## 功能范围

在同一管理计划中增加离线候选准备：从已核验的真实当前安装读取原始依赖意图，
使用主人配置的本地 wheelhouse、保留目录与 uv；依次核验 uv 版本、安装、依赖、
候选配置和空 Runtime 构造。完成后走已有 V2 托管切换及独立固定恢复控制器。
准备进程受独立 Linux 用户服务/cgroup 预算约束，四步共享截止时间，不重试安装。

候选策略保存在原 Store 的独立有界对象中，完整替换、不改变主配置格式。
`self_update_preview` 返回实际观察的匹配条件；`self_update` 仍须真实用户批准，
审批不替代格式、路径、回执或资源证明。配置变动会使旧候选观察失效。

进程身份在启动前、许可前与核空后持久写入同一计划。中断后 `self_recover`
只收尾已拥有的原进程，不重新安装；不明确的启动或清理保持 singleflight 阻断。
新内核启动可结合保留证据与同名无冲突消除旧启动的不确定性；同 boot 的一次
not-found 不足以解锁。详情见[管理接入](candidate-host-design.md)。

## 独立审查与已修缺陷

- 两位独立审查者核对源安装、当前 plan、receipt、证据文件与三个保护目录，
  以及关闭、审批漂移、prepared 后 generation 和原会话路由。
- 进程恢复独立审查发现：pending 已提交但回调丢返回时，旧 finally 会误删
  控制文件。先以新用例稳定复现，再收紧删除条件；修后验证保留身份且可恢复。
  宿主也保留实际已提交附件，防止旧本地计划副本将其抹掉。
- 恢复 HTTP 沿用配置锁内的关闭准入检查。把检查移到锁外改变了已排队请求的
  关闭时序，既有回归发现后恢复原合同；等待候选清理本身仍释放配置锁。
- 计划持久化拒绝外层 SQLite 事务与不受支持的自动提交模式，避免隐式提交
  调用方写入。附件和全计划分别受预算约束，并保留终态字段空间。

## 已有本地证据

所有检查通过同一 `muli-checks.slice` 串行执行，2 GiB 合计、单次 1 GiB、swap 0、
一个逻辑 CPU；本轮短组硬限 30 秒。没有增加资源限额、安装大库或下载模型。

- 准备核心 48 项、当前证据链 33 项、策略 Store/类型相关 47 项，分别在其
  对应检查点通过；详见各设计及测试文件。
- 管理接入新增 14 项、真实 Store/lease/投影的采集 16 项通过。
- 恢复底层新增 30 项与旧后端 48 项合 78 项通过，普通 stdlib worker/helper/
  probe 另 110 项通过；进程后台测试硬拒真实子进程，普通 worker 仅在守卫内。
- 计划附件新增 53 项通过，覆盖状态转换、绑定漂移、预算、原子回滚与事务模式。
- 宿主清理新增 17 项通过，涵盖真实 Store 提交后丢返回、协议缺席分界、
  双重取消、关闭强持任务、数据库已关后观察者只返回内存响应，以及真实 journal
  的 prepared 事务优先；所有子进程入口硬拒，manager/proc 观察使用 fake。
- 宿主修改后的管理相关 31 项及既有恢复入口/HTTP/托管管理/宿主 51 项通过；
  这两个组与上面的新测试有重叠，不能直接相加宣称唯一测试总数。
- 全仓 Ruff、格式检查及 128 个源码文件的 mypy 通过，静态检查峰值
  288.5 MiB、swap 0。完整测试集、候选 CI 与发行验收仍待执行。

## 尚未验证

真实 systemd 的整次离线安装、连续两次跨版本更新、断电或真实跨 boot 恢复
尚未验收；现有 fake manager/kernel 与小型 uv receipt 实验不能替代它们。
候选 Runtime 使用新建临时资料库，仅验证导入、构造及格式合同，不读取个人
数据，也不证明真实模型、MCP、渠道或插件健康。默认阈值式磁盘监测允许采样
间隙超量；没有真实配额后端的 strict 模式明确拒绝，不宣称恶意代码沙箱。

这轮只准备 Linux 托管安装的更新，其他平台不会退回不受保护的执行方式。
无兼容格式声明、未知 receipt/uv 版本或无法核定来源时拒绝准备。
