# 约定时间继续原任务

v2.65 开发候选，本地旅程及独立后审已通过，发行检查尚未闭合。它让“这个任务先暂停，明天九点到十点间交给原队友继续”成为一次持久约定。它保留原任务和队友，不另建一份研究工作流。

主人须明确开始时间、失效时间及要继续的原队友。主助手读取当前时间与完整任务说明后登记；约定只支持已有完整说明、已暂停、原直系队友真实停靠且无活动工作流的任务。`task_schedule_replan(task_id, target_id, due_at, expires_at, key)` 的目标参数只是选择符，真实身份、代次、任务版本、来源与权限由宿主核验并冻结。

等待期间没有模型轮询。原提醒时钟到期接纳一次主人重规划意图，将约定消费记录、控制回执、任务版本与主会话输入一并提交；它不会直接批准或唤醒原队友。主助手仍须真正读取说明，下一轮使用完整快照确认方案；只有准确的原目标及其代次可收到通知并进入新一代。未知操作结果先核查，不自动重做。

到期前另一私聊的普通对话不改变约定来源。接纳后尚未批准时，新的真实主人输入会在原入站事务中永久撤销未兑现资格；重复信封与隔离资料不会撤销。权限模式实际变更后改回也不能复活旧授权。任务版本、目标、原来源授权或渠道变化，以及取消或过期，均不得从最新记录补猜身份或改投默认渠道。

`task_schedule_replan_list` 有限分页展示实际状态；`task_schedule_replan_cancel` 撤销尚未批准的约定。已经批准的历史事实保持，通过原任务暂停或停止处理后续执行；不承诺追回已进入处理器的副作用。不支持周期续办、自动换人、孙代传播或操作系统定时唤醒。

独立作者使用真实 ASGI/OneBot、Runtime/Team 和临时资料库，完成手机7交代任务、队友真实读取本地资料、主人真实暂停、旧写入被拒、准确代次停靠、主助手读取完整说明及当前时间、确认原私聊工具执行上下文，再核新工具缺口。前三次分别在错误的选中快照前置、测试辅助函数参数冲突、provider 窗口误读工具 ContextVar 处失败，均不算功能目标红。

修正夹具生命周期后，正式首节点在所有上述前置成立时准确失败于工具目录没有 `task_schedule_replan`，实际持久工具回执为“工具未启用”：1 项失败，0.57 秒；守卫 1.298 秒，峰值 91 MiB，swap 0。

实现后，完整旅程已走通：私聊7登记原任务，私聊8普通交谈不撤等待约定；正常关闭重开后由原提醒时钟到期，主助手实际读完整说明、下一轮批准，原队友同身份进入下一代，读取旧工具证据并写临时草稿。重规划与最终报告仅回原私聊7，Web保留；重复时钟和再次重开不增加代次、接纳或出站。该旅程旧写入的结果明确为 `not_executed`，不证明真实 unknown 副作用可恢复。

第一组新测试为14通过、2失败；两处真实产品问题是撤销或过期后的主运行失败收尾连带取消已停靠队友。修为受控停靠后通过；后续一次夹具误用配置读取方法、一次误以为工具消息含 `run_id` 均已准确修正，不计作产品缺口。缺失回执标记不得降级普通授权、一次续办完成后正常主人可再给同队友新输入、普通主人控制推进 epoch 后清除旧定时域均已验证。

沿用原上下文、输出与待办预算及测试时间门。没有新依赖、本地模型或数据库物理迁移；七个全局格式版本保持1。离线固定模型策略与渠道替身验证的是宿主证据、权限、生命周期和投递合同，不代表自然模型回答质量、真实账号或真实设备效果；正常关闭重开不等于强杀恢复。

## 回退边界

定时约定首次接纳时，在原任务 `control` 内保存严格的 `scheduled_replan` 领域标记，并与真实控制回执交叉核对。批准后保留标记；普通主人暂停或请求重规划推进 epoch 时清除，旧快照继续因 epoch 变化失效。不能把这个领域形状变化描述为旧版完全兼容。

以签名标签 v2.64.0 的真实 TaskControl 源码在隔离临时数据上探测：定时接纳后的旧版重规划读取、持久旧执行快照核验，以及批准完成后的旧版执行读取均以 `control_invalid` 拒绝；新普通主人控制清除领域标记后，旧版可读取普通暂停与重规划。守卫861ms、峰值84.5 MiB、swap 0。该探测使用旧控制源码与当前支持类，不是整旧包或真实系统A/B回退验收。回退时受影响任务保守拒绝，不承诺无缝继续，也不能追回已进入处理器的效果。
