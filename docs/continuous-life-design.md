# 持续在线 MuLi：迭代目标与工程约束

用户要求版本发布只是检查点。继续按调研、设计、独立复核、实现、后审查、故障回归和发版循环推进；新功能研究与已有实现审查并行。所有阶段保持低资源验证，不自动下载模型或大型库，不以模拟结果替代真实平台实测。

## 一个身份，多条通信线路

主 MuLi 有稳定的本地身份、持久主会话、独立收件日志和后台团队。Web、OneBot/NapCat、微信 iLink、QQ 官方机器人、Telegram 是可选渠道；默认仅 Web。只有显式绑定为本人的发送者可以进入主人上下文。陌生人、群消息及附件内容是带来源的外部资料，不能自行获得主人的工具权限。

入站先持久化、去重，再在模型轮次安全边界注入。原生 assistant/tool 批次必须成组闭合；流式输出不被中途篡改。关闭窗口不会结束后台团队；主 MuLi 主要统筹、轻量读取与回复，动态 agent 支持创建、发消息、等待、停止、恢复。历史 agent 数量不设固定硬上限，驻留任务、实际执行并发和资源预算仍可配置。

## 记忆与上下文

身份与明确偏好、工作记忆、任务情节、长期语义事实、关系图和原始资料分层。持久化优先于异步提炼，写入/embedding/关系构建不阻塞回复。混合检索组合文字、可选远端 embedding、关系扩展和可选 reranker，保留来源、时间、置信度、矛盾与遗忘路径。提示词注入有分层预算，完整记忆经工具按需读取；不依赖每次把所有记忆塞进 prompt。

主、子 agent 和团队共用多层上下文策略：近期原文、可验证摘要、关键任务状态与可检索原始归档。压缩失败保留旧记录并回退，不压坏工具调用配对或协议原生思考回放。

## 本地一等公民

配置与数据默认集中于 `~/MuLi`，环境变量和显式 CLI 路径仍可覆盖。交互 init 配置主模型、昵称、视觉能力及服务 host/password/port，并请求安装、启用和启动当前用户后台服务；其它设置由启动后的配置对话协助完成。MuLi 可以读取完整自身配置、预览并校验修改、管理服务、经用户同意更新、管理插件与提示词；源码参考副本只读，产品定制保存在仓库外插件目录。新版本检查只请求小型元数据；更新需明确同意。配置应用失败会尝试恢复之前的配置；安装包更新失败不保证自动回退，状态会区分安装、重启和失败。

插件提供有版本的工具、上下文、模型、事件、路由和生命周期扩展点，支持附加与覆盖。插件是用户级可执行代码，不能把“插件”包装成沙箱；启用、失败隔离和来源记录可管理。

## 媒体和跨平台

上传只登记并存文件，按需读取；主模型可视时直接使用主模型，否则显式外挂 vision。截图、录屏与生成语音保存为可管理附件，可经渠道发回。ASR/TTS/embedding/reranker 使用可配置 HTTP 接口。中文“沐璃”唤醒默认关闭，声纹注册由用户主动录音；CPU/ROCm/CUDA 做能力探测，缺少可用运行时或模型时准确报告，不隐式大下载。

Arch/Linux 优先，随后其它 Linux、macOS、Windows。后台服务按 systemd/launchd/Windows 原生任务能力实现，不弹终端。桌面操控优先无障碍树，补充平台可用的截图与录屏方式，保留显式 capability 状态。

## 交付阶段与不停止条件

1. 发布链、初始化与认证；持久主会话、附件及无侧栏工作台。
2. 动态团队、非阻塞多层记忆、完整压缩与自我管理插件。
3. 多渠道收发及文件发送、chiliarch 0.5.0 自我介绍联动。
4. 跨平台服务/媒体/语音，集成故障测试与体验完善。
5. 持续独立评审，从实际使用缺口提出并完成进一步改进。

某一阶段发版不代表本次目标完成。每项分别记录已实现、模拟测试、本机实测、远端 CI 和仍需外部凭据的联调边界。
