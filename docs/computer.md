# 使用电脑

沐璃优先通过无障碍树理解应用和操作控件，电脑能力默认关闭。你可以先让她查看窗口，再明确交办操作；截图与录屏另见[平台支持](platforms.md)。

## 开启前的准备

在设置中启用电脑操作，并确认后台服务运行在能访问桌面的用户会话中。MuLi 不会静默安装系统组件或更改系统隐私授权；缺少依赖时，能力状态会给出原因，可在当前权限模式下按[平台支持](platforms.md#安装缺失的系统工具)的说明安装，或由主助手在你的请求下先尝试安装。

| 平台 | 当前范围 | 准备事项 |
| --- | --- | --- |
| Linux / Arch | AT-SPI 应用、窗口和选定子树，控件动作与完整文本设置 | 系统 Python 可使用 GI 和 Atspi（Arch：`python-gobject`、`at-spi2-core`；Debian/Ubuntu：`python3-gi`、`gir1.2-atspi-2.0`），应用启用了无障碍支持 |
| macOS | 当前前台应用及其窗口，支持的控件动作与文本设置 | 为实际运行 MuLi 的程序授予辅助功能权限；此后端仍为实验性支持 |
| Windows | 顶层窗口和选定窗口树，普通按钮的一次 Invoke | 当前用户桌面可用；暂不支持文本输入 |

系统状态显示组件可用，不代表所有应用都能读取或操作。窗口可能不提供完整无障碍信息，也可能要求额外的系统授权。

## 交办操作

可以直接说：

> 看一下当前有哪些窗口，先不要操作。
>
> 找到这个应用的保存按钮，确认后再点击。

沐璃先发现应用或窗口，再读取对应快照，最后使用快照里真正提供的动作。工具分别为 `computer_targets`、`computer_snapshot`、`computer_action` 和 `computer_type`；文本设置会替换控件的完整内容。

目标与控件标识是临时的。新观察、超时、重启或一次操作尝试后，旧标识可能失效；不会按同名按钮猜一个替代目标。让同一个队友完成观察和操作，避免多个队友争用桌面；必要时可以先释放当前观察。

Linux 由同一轮任务持有观察，其他队友需等待释放，再重新查看桌面。任务结束、停止或关闭后，旧标识自动失效。持有期由 `snapshot_ttl_seconds` 控制，重复读取不延长；查看状态不会占用桌面。

macOS 只查看当前前台应用。Windows 必须从刚发现的窗口选择目标，只有符合条件的普通按钮提供 Invoke；不支持的控件不会悄悄改用坐标点击。

## 权限与结果确认

电脑工具遵循当前权限模式：ask 每次询问，auto 将电脑动作交给你批准，yolo 自动执行已启用的操作。

“已接受”表示接口返回，不保证页面已完成预期业务。重要操作后应重新观察结果；已经开始的点击或输入无法靠停止任务保证撤销。结果不明时先核查，避免重复点击或重复提交。

读取结果可能不完整。控件没有出现在截取的树中，不代表它不存在；可以改选更小的窗口或区域继续查看。密码控件及保护状态不明确的文本控件受到限制，不应通过重复尝试绕开。

## 常用设置

例如，在默认关闭的基础上调整无障碍设置：

```json
{
  "computer": {
    "enabled": false,
    "backend": "auto",
    "python_path": "/usr/bin/python3",
    "max_nodes": 300,
    "operation_timeout_seconds": 12,
    "snapshot_ttl_seconds": 60
  }
}
```

确认准备完成后再启用 `enabled`。`backend="auto"` 按系统选择 Linux AT-SPI、macOS AX 或 Windows UIA，不会失败后自动改用其他操作方式。

`python_path` 只用于 Linux 的 AT-SPI 和 Portal，填写实际具备系统组件的 Python。一次操作默认最多12秒，临时快照默认60秒过期；复杂应用优先缩小观察范围，不必先增大节点预算。

截图、录屏与无障碍读取分别启用、分别授权。前者可用不代表后者可用，也不会因此绕过控件校验。服务与采集设置见[平台支持](platforms.md)。
