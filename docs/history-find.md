# 找回历史原文

可以直接告诉沐璃：“找一下上次出现‘备份完成’的工具结果，核对原文，不要重新执行。”

主助手、队友和工作流节点都可以在一个已知会话里查找保存过的文字，再读取准确出处。压缩和正常重开不会删除这些原始记录。查找使用本地记录，不调用模型，也不重新执行历史工具或发送旧消息。

## 查找与核对

`conversation_find` 接受来源会话和原文片段：

```json
{"session_id":"来源会话 ID","query":"备份完成"}
```

按字面、区分大小写匹配；空格也是原文的一部分。它可以定位消息正文及已保存的工具结果文字，不做语义联想、不跨消息拼接，也不查图片、附件内容或未保存的输出。附件内容使用[正文定位](attachment-find.md)，长期资料使用[个人记忆](memory.md)。

命中返回消息位置、来源及 `read_arguments`。将这些参数原样交给 `conversation_read` 读取正文；偏移单位是 UTF-8 字节，不能换成可见字符数。来源可能未知，旧记录和旧授权都只是待核对资料。

若还需核查原工具参数，可用该消息的 ID 或 seq，另从字节零开始指定 `field="tool_calls"` 分页读取；正文查找不搜索参数，也不能沿用正文命中的字节位置。详见[原工具调用参数](history-evidence.md#原工具调用参数)。读取不会重做历史操作或提供新授权。

想把已完成的沐璃答复长期保留，可以在核对后明确要求[收藏这条答复](memory.md#收藏沐璃的一条答复)。查找和读取本身不会收藏，也不会把原答复当成已经执行的任务。

`has_more=true` 时，保持原会话和查询，将 `next_cursor` 作为 `cursor` 继续。结果从较新的记录向前查找，同一条消息内按正文顺序定位，并保留重叠命中。新到消息在重新从首页查找时纳入。

## 如何理解没有结果

每次查找受现有时间、候选条数、正文与输出预算限制。`stopped` 表示本次停下的原因；有游标可继续。`omitted_total` 非零表示存在损坏、缺失或超过单次核查预算的记录，不能据此声称所有历史都没有这段文字。

续查中的消息发生变化或删除，会要求从首页重新核查；不能把新旧位置拼接。多次调用是有界的实时遍历，不是冻结全部历史的快照。旧记录的 `revision_is_legacy=true` 表示原版本机制较弱；直接绕过程序修改数据库，不在旧正文读取的版本保证内。

查找只覆盖实际保存的正文。入库前已被节选的尾部、已经删除的消息或未保存的外部响应，无法通过查找恢复。需要核对结果时，应先读原文并检查来源与节选标记。

## 忘记来源会话时

主人可以直接告诉主沐璃：“找回上次那句‘备份完成’，我不记得是哪个队友处理的。”主助手使用 `history_find` 定位自己的旧消息和现存直属队友保存过的原文，包括已经完成的队友任务，再用 `conversation_read` 核对正文。无需先提供会话 ID。

这个入口只在主助手处理真实主人当前请求时使用。它不查独立聊天、孙代或工作流节点，也不会恢复旧任务、重跑工具或把旧成果自动发往任何渠道。找回的旧指令和授权仍只是资料；来源没有保存时保持未知。

查找受同一份候选、字节、时间和输出预算限制。无关会话也会消耗扫描额度，所以空结果页仍可能有 `next_cursor`；应按游标继续，不能把一页没有命中说成全部历史都没有。多页仍是实时有界查询，记录或直属关系变化可能要求重新查找。

新入口的游标只在同一次主运行内续用。开始新一轮处理或重新启动后，需要从首页重新查询。当前运行的提问、工具调用和回包不作为旧来源；返回的原件位置仍可交给既有读取工具使用。已知会话时继续使用上面的 `conversation_find`。
