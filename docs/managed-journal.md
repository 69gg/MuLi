# V2 与原事务账本共用持久化

本文件记录 V2 的内部持久化合同与模块验证；启动和服务控制已由宿主接线，完整入口的整合状态见[本地托管切换](managed-operations.md)。

`managed_journal.py` 的函数接收现有 `TransactionJournal` / `JournalControl`。仍然只有原目录里的 `state.json`、固定控制锁和按数据库路径确定的 writer lease，不另设模式账本或第二个“已确认版本”指针。

`read_current()` 严格分派协议。V1 原 `read()`、prepare、advance 和健康证明保持原语义，遇到 V2 拒绝解析，不能误按单安装恢复。未决 V1 不能被 V2 替代；已决 V1 必须先有精确 generation、revision、store instance 投影回执。回执的实际数据库来源仍由宿主核验，纯持久化函数不把传入 DTO 当作来源认证。

V2 每个 role 保存配置、可选 selector 和 unit 的精确快照。配置及 selector 使用原 JSON 原始摘要与规范化语义摘要；unit 按原始字节校验，文件使用 `.bin` 后缀。迁入前 legacy role 没有 selector，这个缺席状态属于角色定义，不能用空 JSON 代替。

selector 必须已经是规范 JSON 字节（排序键、无额外空白）。prepare 在写任何文件前拒绝原始摘要与语义摘要不同的 selector，避免恢复时将“规范化后相同”误当成恢复了原字节。配置仍允许非规范 JSON；其精确快照照常保留。

prepare 先校验全部快照、记录大小、旧事务和实际 writer lease，再写快照，最后原子替换唯一的状态文件。每次替换仍用现有 file fsync、rename、parent fsync。写入失败可留下未引用快照，但不能发布缺失快照的新记录，也不会删除上一代的快照。下一次 prepare 只能回收已知名称且未被当前代引用的孤立文件；未知文件保留并计入目录预算。预算包括临时替换文件，不能靠先写一半再报告空间不足。

同一 request 的重试返回原 generation、challenge 和期限，并重新核验已存快照。缺失或被改动时失败，不能用请求重试悄悄“修好”恢复证据。持锁读取会确认目录耐久屏障；屏障或替换失败后该控制句柄拒绝继续执行。

验证在临时目录运行，覆盖 V1 未决与终态投影、同一文件严格分派、每个快照和状态文件的写入前后中断、原代保留、损坏重试、过期 revision、错误数据库 lease、目录预算和 fsync 失败。真实系统服务、候选启动、组件激活及跨版本回退需由后续整合测试证明，本模块不执行这些动作。

初次整合与 V1/V2 纯协议回归共 127 项通过（0.30 秒，峰值 61.8 MiB），两源码严格 mypy 通过，整轮最高 120.2 MiB、swap 0；所有检查串行经过统一 guard，每次期限 30 秒。独立只读复审未发现阻断，确认十四个写入前后中断窗口、旧代保留、投影边界及失败句柄行为。后续 legacy 回桥的验证另行记录，不把尚未实现的流程算入这些结果。
