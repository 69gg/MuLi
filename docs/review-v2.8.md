# 2.8 多来源别名与召回路径审查

状态：已完成签名发布与 PyPI/GitHub 发行文件核对。沿用现有 SQLite、查询缓存、证据分页与界面核查，不增加运行依赖、模型请求或全库提炼。

旧唯一别名索引只保存首份来源。真实 SQLite 反证发现：两条独立原文都支持 `Lumi → MuLi`，忘记首份来源后剩余事实和规范名查询仍在，但别名的两跳召回丢失。新贡献表保留各事实登记，删除时只撤销相关贡献，再从仍有效依据修复路由；同源多事实不计为独立来源。迁移只保存旧库真实可知的一份，无法恢复旧版未记录的支持者。

后审查进一步复现旧 source-only 索引加入新贡献后，遗忘新来源会误删旧索引生命周期的问题；修复为保留尚无对应已登记贡献的旧路由引用，只有原引用实际消失后才由剩余贡献接管。补充 source-only、无引用和不一致旧行的保守迁移、两种删除顺序及最终清理回归。事实更正、底层整份替换、规范自名和 legacy 兼容分别验证，不把修复前的测试数量当作最终结论。

路径使用实际 BFS 的父边和方向，每个图命中携带入口登记、事实/来源引用及同一 revision。独立检索命中不补造链。模型工具和融合 HTTP 查询按完整 JSON 保留整条候选与路径，预算不足明确省略；管理列表仅给新增路径设置共享限额，保留原管理行为。缓存与投影分离，网络等待期间遗忘后重新取本地当前快照，不重新请求模型。

原文预览此前先读取整篇再截取；现在在 SQL 侧取有界 BLOB 窗口，复用 UTF-8 边界处理。NUL、中文、emoji、实际来源身份和精确截断标记均有定向覆盖，完整原文接口仍保留原语义。

首轮候选 `f8a3357` 的 [Ubuntu / Python 3.12 作业](https://github.com/69gg/MuLi/actions/runs/39325532373/job/118310269561)发现超大正整数预览长度返回空内容。绑定长度虽已限制到 Python 整数范围，旧 SQLite 的 `substr` 仍会把长度转为 32 位；[SQLite 3.45.3 官方实现](https://github.com/sqlite/sqlite/blob/version-3.45.3/src/func.c#L374-L378)可核对此行为。修复在 SQL 中将请求窗口进一步限制到实际 BLOB 字节数，保持任意大正整数、Unicode、NUL 和有界读取语义，不削弱原测试。

新增五个用例观察实际传入 `substr` 的长度，修复前三个大整数用例失败，修复后全部通过；原文预览 34 项、全部记忆相关 175 项通过，Ruff 和该模块严格类型检查通过。从产品源码提取的精确 SQL 另在本机已有 SQLite 3.46.0、3.47.1、3.50.4 各验证四个窗口：前两者旧查询返回 0 字节，修复查询均完整返回同一份 17 字节原文。这里只验证这些已有运行时的 SQL，没有安装旧库，也不宣称在不受支持的 Python 版本运行完整应用；修复后的精确提交仍需远端 CI 复核。

同轮 [Windows / Python 3.12 作业](https://github.com/69gg/MuLi/actions/runs/39325532373/job/118310269548)单独失败于并行 DAG 测试的启动等待：`wait_for` 抛出超时，失败栈中的启动事件已为 `set`。日志无法独自确定精确调度顺序；本地用受控单调时钟模拟首次同步持久化耗时，在真实引擎和原完整测试上确定性重现相同失败，不实际睡眠或阻塞。启动事件与超时回调可在同一轮就绪，而事件等待者下一轮恢复时已被取消。

测试现同时观察真实启动事件与 `WorkflowEngine.wait` 的明确终态，唤醒后复核事件状态；保留原一秒卡死检查，提前失败会报告运行和节点状态。所有观察者均在 `finally` 中取消并等待收尾，工作流本身由已有 `wait` 的 shield 语义保护。新增同轮调度、提前终止及取消观察者回归；并发数、三个独立会话、权限模式、评审依赖和结果事件断言完整保留。工作流专项 33 项通过，没有调整产品调度、生产超时或跳过平台覆盖。

SQLite 修复提交 `3f794d5` 的[第二轮矩阵](https://github.com/69gg/MuLi/actions/runs/39326774334)中 Ubuntu / Python 3.12 已通过，八项中七项成功。Windows / Python 3.12 的唯一失败转为既有网页转写超时测试：20ms 总期限也包含附件读取，读取尚未完成就可能超时，不能据 HTTP handler 的取消标志为空推断远端操作泄漏。本地门控反证明确复现读取已取消、并发槽已释放而 HTTP 从未派发，纠正的是测试前提，没有改变转写产品代码。
