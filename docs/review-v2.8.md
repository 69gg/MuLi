# 2.8 多来源别名与召回路径审查

状态：实现和后审查进行中，尚未冻结或发布。沿用现有 SQLite、查询缓存、证据分页与界面核查，不增加运行依赖、模型请求或全库提炼。

旧唯一别名索引只保存首份来源。真实 SQLite 反证发现：两条独立原文都支持 `Lumi → MuLi`，忘记首份来源后剩余事实和规范名查询仍在，但别名的两跳召回丢失。新贡献表保留各事实登记，删除时只撤销相关贡献，再从仍有效依据修复路由；同源多事实不计为独立来源。迁移只保存旧库真实可知的一份，无法恢复旧版未记录的支持者。

后审查进一步复现旧 source-only 索引加入新贡献后，遗忘新来源会误删旧索引生命周期的问题；独立修复与回归正在收口。事实更正、底层整份替换、规范自名和 legacy 兼容分别验证，不把修复前的测试数量当作最终结论。

路径使用实际 BFS 的父边和方向，每个图命中携带入口登记、事实/来源引用及同一 revision。独立检索命中不补造链。模型工具和融合 HTTP 查询按完整 JSON 保留整条候选与路径，预算不足明确省略；管理列表仅给新增路径设置共享限额，保留原管理行为。缓存与投影分离，网络等待期间遗忘后重新取本地当前快照，不重新请求模型。

原文预览此前先读取整篇再截取；现在在 SQL 侧取有界 BLOB 窗口，复用 UTF-8 边界处理。NUL、中文、emoji、实际来源身份和精确截断标记均有定向覆盖，完整原文接口仍保留原语义。
