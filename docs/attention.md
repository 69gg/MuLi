# 提醒与主动事项

沐璃可以按约定时间提醒你、复盘已有任务，也可以在你明确授权后定时交给队友执行。先区分你需要哪一种：

| 你想做的事 | 可以这样说 |
| --- | --- |
| 到时提醒自己 | “明晚九点提醒我整理笔记。” |
| 看看某个任务的进展 | “每周五复盘这个任务，告诉我已有成果、未验事项和下一步。” |
| 到时完成一份独立委托 | “明早搜索这个主题，让队友整理并评审，把文字成果发回这里。” |
| 到时继续原暂停任务 | “这个任务明早九点到十点间交给原队友继续，过时就不要开始。” |

普通提醒和任务复盘不会自动获得执行任务的权限。定时委托、继续原任务需要你明确交代，并继续遵守当前审批和任务控制。

## 设置、查看与取消提醒

在网页打开 **通知 → 提醒 → 新建提醒**，填写标题、时间，以及可选正文和重复间隔。已有提醒可以改期、暂停、启用或删除。删除提醒不会删除已收到的通知。

也可以直接对沐璃说：

- “明天下午三点提醒我带材料。”
- “列出我的提醒，把整理笔记改到今晚十点。”
- “取消明天下午那条带材料的提醒。”

沐璃会读取当前时间、查到准确提醒后再操作。一次提醒触发后会结束；重复提醒使用固定秒数间隔，至少一分钟，不是日历式 cron。跨时区或夏令时有要求时，应明确说明时间和时区。

从手机私聊创建的提醒保留原来源；网页创建的提醒留在网页。说明默认在 WebUI 显示，向手机发送由助手显式调用渠道工具。后来在另一私聊改期，不会把旧提醒的通知目的地改成新私聊。没有可靠来源的旧事项不会猜测最近联系人。

### 原地改期已有提醒

“把这条提醒改到今晚十点”只改变下一次时间并重新启用，保留原标题、正文、重复间隔、任务关联和历史次数。已停用或已触发的一次性提醒也可以重新启用。重复提醒改期后，不保证继续保持原来的日历相位。

改期不会撤回已收到的普通通知。已关联任务的旧复盘若尚未开始处理，可以因编辑或改期失效；已经开始处理或发送的结果不保证撤回。

## 约定复盘指定任务

### 只读目标复盘

先让沐璃确认是哪个任务，再说明复盘时间。例如：

> 每周五晚上复盘刚才的研究任务，读最新要求和交付记录，告诉我哪些已经有依据、哪些还没验。

沐璃将提醒关联到真实任务。到期时读取最新任务要求及交付依据，区分登记时核验的文件事实、模型判断、未验事项和下一步。旧成果会标为历史，不会自动算作满足新要求。

复盘不恢复任务、不批准方案、不派工、不重发成果，也不自动发送文件。暂停或结果未知不会因此变成新的执行授权；任务已经完成或取消时，不再接纳尚未开始的复盘。

要改期、取消或换关联任务，直接说明准确约定。任务核查的读法见[任务核查](task-inspection.md)。

### 定时重新规划原暂停任务

如果希望到时继续做事，需要明确 **原任务、原队友、开始时间和失效时间**。例如：

> 这个任务先暂停，明早九点到十点间交给原队友继续。先核对完整要求，过了十点就不要自动开始。

该约定适用于已暂停、原直系队友已经停靠、没有活动工作流的任务。到期只接纳一次重新规划请求；沐璃仍须读取完整说明，再确认方案，才让原队友继续。登记成功不代表已经开始或完成。

可以请沐璃“列出继续原任务的约定”或“取消这条续办约定”。取消针对尚未批准的约定；已经批准的任务请使用[暂停或停止](task-control.md)。

任务要求、队友身份或权限模式变化可能使约定失效；模式改回也不会恢复旧资格。尚未到期时，在另一私聊普通交谈不会改变原来源；到期已接纳但尚未批准时，新的主人输入会撤销这次未兑现资格。未知操作结果须先核查，不会自动重做。

## 定时执行一份明确委托

可以说：

> 明早九点搜索这个主题，让执行队友整理、另一位队友评审，把文字成果发回这里。以后每周同一间隔执行一次。

沐璃保存委托内容、首次时间、可选重复间隔及原回复来源，到期使用执行队友与评审队友完成这份独立工作。主助手忙碌时等待空闲和容量，不打断当前工作；漏过多个周期时合并处理，不补跑一串任务。

在 **工作流** 页面展开定时委托，可以查看计划、最近运行和取消入口；也可以让沐璃查询或取消准确计划。取消会撤销后续执行资格，并尝试收口关联的在途工作流，不能追回已发出的操作。

这份委托独立于当前选中的任务，不会因那个任务暂停而自动停止。创建委托也不等于批准未来所有工具：`ask` 仍需批准，`auto` 仍按原审查规则处理，当前权限只能收紧。成果保留原来源，默认在 WebUI 展示；外发文字或文件仍须显式使用渠道工具。更多分工说明见[多 agent 协作](workflows.md)。

## 主动事项如何工作

提醒、更新和管理结果可以先出现在通知中，再由沐璃空闲时解释。主任务、队友或工作流仍在执行时，模型说明会延后；不会在当前工具批次或流式回复中插入新任务。

主动关注默认开启，主要配置如下。将片段合入已有配置，不必覆盖其它设置：

```json
{
  "attention": {
    "enabled": true,
    "events": ["reminder", "management", "update"]
  }
}
```

`events` 只选择提醒、管理和更新这三类。系统日志、chiliarch 消息与资料收件目录有各自的开启策略；只清空 `events` 不会关闭这些来源。要停止全部主动关注，设置 `attention.enabled=false`。它不取消已经明确登记的独立定时委托。

主动事项是资料，不是新的主人命令。沐璃可只读核查并解释，不能借通知修改配置或派工。普通文字默认留在 WebUI；需要外发通知时，须显式调用发送工具，并受权限检查和该事项保存的目的地限制。已有来源的事项保留原来源；没有发令会话的独立事项，按[默认通知设置](channels.md#无发令会话时的默认通知)选择，不广播到所有渠道。

## 使用限制

- 后台服务必须运行。关闭网页不影响服务；关闭服务或电脑后，不会自动唤醒电脑。
- 提醒通知不依赖主模型；让沐璃解释、复盘或执行委托需要配置模型，可能产生费用。空闲时不反复询问模型。
- 首次开启或重新开启主动关注，不补发此前历史；旧事项仍可在原通知中查阅。
- 正常重开后，未开始的有效定时委托可以继续等待；已经开始而中断的工作流不会自动重做可能已有副作用的节点。
- 外发显示“结果未知”不等于对方没收到，不会自动重发。遇到故障先查通知、运行和发送记录，再决定下一步。

Linux 桌面弹窗是独立功能，见[桌面通知](notifications.md)；故障提醒见[系统日志](system-events.md)；本地资料来源见[资料收件目录](file-inbox.md)。
