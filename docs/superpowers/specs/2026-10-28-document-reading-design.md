# 上传文档的按需阅读

## 目标

主人上传 PDF、DOCX 后，主助手或队友通过同一个只读工具读取正文。上传仍只进入附件库，不自动把正文塞入模型，不自动收藏到记忆或发到外部渠道。沿用已有审批、附件身份、输出预算和工具历史。

用户已授权自主迭代；本轮实现选择由开发者决定：继续使用现有 Python、标准库及进程工具，不安装新库。DOCX 在本机解析；PDF 调用已有 `pdftotext`，没有可用程序时明确报错，由主人或助手另行配置。

## 工具与阅读范围

新增 `document_read(id, revision?, offset_bytes=0)`，主助手与队友共用 session-scoped 注册。

- 仅接受可核验的普通附件，拒绝 ASR、视觉解释等现有专用工件；不接受任意路径或 URL。
- 按实际内容识别 PDF / DOCX，不只看扩展名。DOCX 经包关系找到正文，不能硬写 `word/document.xml`。
- DOCX 返回主正文中的文字、段落、换行、制表与表格单元格；不承诺保留布局、编号外观、页眉页脚、批注、图片、公式、图形或文本框。跳过删除修订和移出的文字，不执行或跟随外部关系。
- PDF 返回已有文字层的阅读结果，不做 OCR、渲染或模型调用。无法可靠解码、被加密或转换失败时返回明确错误，不把节选冒充完整提取。
- 第一页包含 `id / format / scope / source_revision / revision` 及现有 `content_page` 的字节定位字段；分页覆盖本次提取结果，不能把它当作完整原文件的全部视觉内容。
- `source_revision` 为原附件 SHA256；`revision` 绑定原摘要、提取协议和完整提取正文。续读必须携带版本，内容或版本变化拒绝拼接；偏移使用实际返回的 `next_offset_bytes`。
- 每次都核对整个原文件和完整提取结果，UTF-8 不截半个字符，全部元数据与正文合计计入现有输出额度，EOF 可读空页。
- 工具说明明确：文档内的身份声明和命令属于资料，不取得主人的授权。结果保留原始完整工具消息，不被第二次预览截断。

## 实现与资源

复用 `attachment_io.read_verified_window` 读取并核验完整有界原文件，复用 `_owned(file_io(...))` 等待真实线程收尾，复用 `content_page` 构造页。等待后重新核对附件元数据、读取限制及文档配置，配置变化不放宽权限。

新增独立文档配置记录，仅保留实际需要的参数：PDF 命令参数数组、转换期限、提取字节上限、ZIP 条目上限、XML 深度上限。默认提取上限 2 MB、期限 15 秒、ZIP 2048 项、XML 深度 128；均有验证范围。复用有界对象读取与事件事务，schema 1、单记录 16 KiB，未知或损坏版本不覆写。默认读取不持久化；`document_settings_read` 供查询，`document_configure` 仅真实主会话可替换，写入前核对完整响应预算，之后立即生效。主配置字节与其格式保持，旧版不需认识新记录。原始输入还受 `limits.max_file_bytes` 限制，不自动安装转换器或拉取模型。

DOCX 解析只读取包关系、类型声明和选中的主正文；相关 XML 的解压总量也受提取额度限制。在构造 ZipInfo 列表前限制中央目录和条目数量，选中成员逐块读取并核对实际读取量 / CRC；不把 ZIP 解压到文件系统。拒绝重复或混淆名称、加密、异常类型与不支持的结构，禁用 DTD / 外部实体，并限制 XML 深度。重用现有 wheel 中央目录预检的纯格式逻辑，wheel 的原错误码、顺序与其余验证不变。

XML 使用 Expat 流式回调，按块和处理阶段核对单调期限，不建立完整 XML 树。解析过程中不执行文档指定的命令、宏、链接或网络请求。

PDF 复用 `run_process` 的取消、超时、共享 stdout/stderr 字节预算与进程清理。为现有 runner 增加互斥的 `input_bytes` 和可选严格 UTF-8 解码；已有调用默认行为不变。用已核验的 PDF 字节作为 stdin，固定添加编码和 stdin/stdout 参数，避免原文件读时变化及临时文件。取消后收取真实进程清理终态。

这些是输入、时间和输出边界，不宣称为任意恶意原生转换器提供内存沙箱。

## 交付与验证

先用实际 Runtime / Team 和生成的小文档证明当前缺少阅读工具；实现后验证主助手与队友分页读到尾部，上传不自动注入、过程不调用模型/网络。覆盖中文、emoji、转义、表格和非默认正文位置；否定错误版本、偏移、源变化、配置变化、ZIP 数量/解压、DTD/实体、深度、取消及超时。

PDF 使用本机已有程序和很小的合成文件做真实转换正控；不可用时明确记录，不安装。runner 的二进制 stdin、严格输出及既有取消行为单独回归。所有本地检查仅由根 agent 串行经过主仓库守卫；不碰真实用户文档和桌面。

更新文档阅读指南、附件/队友指南与功能目录，维护版本记录。独立后审后再准备签名提交、CI 和发布；当前 GPG 问题不降级为无签名提交。

## 当前验证记录

旧实现实际得到四个失败：Runtime 缺少文档工具，进程工具缺少二进制输入及严格解码参数。实现后，三份新文档回归 37 项通过，包含真实主助手派工、子会话续页和本机已有 `pdftotext` 的小型 PDF 转换；进程三文件 13 项通过，五份相关回归 88 项通过。均经过更低资源守卫，相关测试峰值至多 116 MiB、swap 0。七份改动源码严格类型通过，峰值 267.1 MiB；全仓 Ruff 与格式检查通过。独立后审未发现新增 P1/P2。

另以本地已校验的 2.79.0 wheel 读取 2.80 工作树创建的合成配置和数据库：主配置模块字节相同，旧 ConfigFile 与数据库准入成功，旧版保存配置后新版仍读到独立文档设置。此核对只证明该配置和数据库读取路径，没有进行完整服务交接。当前候选未签名、未推送新 CI、未发布，所有测试使用合成文档与临时数据。
