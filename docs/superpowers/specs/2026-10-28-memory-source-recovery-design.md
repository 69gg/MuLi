# 来源管理与准确重试

来源目录需要形成完整的管理流程：发现保存了哪些原文，定位哪份整理失败，按同一版本核对正文，再由主人明确决定重试。主助手和队友共享只读发现能力，写操作仍由真实主人驱动的主助手或已认证管理入口发起。

沿用原 SQLite 来源、作业、checkpoint、向量与唯一 worker，不更改数据格式，不增加后台轮询、依赖或模型。旧 `retry(source_id)` 会额外登记其它 deferred 来源，故不直接用于单来源操作；新增同步接纳方法，保留旧接口供既有调用方使用。

## 接纳边界

必填准确 `source_id` 与 `revision`。先验证启用、关闭、维护和未收口事务，再核非墓碑原文 digest、当前状态、队列容量及完整 JSON 回执预算；此前不写入。只有 failed 可以重置尝试计数并排队，deferred 只为该来源建作业。failed 更新带原状态条件并保留 checkpoint；反复请求 queued、processing、retry 或 done 都返回未重试的真实状态。未确认保存的外部请求仍可能重复收费。

主工具复用原 `_attachment_guard`，在无 await 的最后提交前核对主会话、当前运行、实际主人输入、后续输入、权限与生命周期。队友不获得重试工具。HTTP 共用相同同步服务并持有配置锁，接纳后才通知原 worker；正常队列的后续推进与此次请求范围分开描述。

## 网页与预览

在既有记忆页加入来源页签，保留外层布局；列表使用同一有界目录，不为每个来源追加请求，不因空筛选窗口自动扫全库。原文复用已有按版本和字节翻页的 reader，来源 ID 通过查询参数传入，目录不读取正文。身份细节默认折叠，来源、状态及操作保持可见。

重试一次准确来源须显式确认，回执区分接纳、正在处理、已完成和容量不足，不用完成动画代替真实状态。关闭、离页、认证失效和旧按钮脱离当前目录后，取消等待并拒绝晚到数据；HTTP 中断不宣称服务端效果撤销。独立预览只操作本页合成资料，模拟同样的目录、原文与接纳状态，不启动真实后端或桌面。

## 验证范围

覆盖原作业进度保留、其它 failed/deferred 不变、幂等状态、容量、原文变化、遗忘、输出预算、维护、关闭和未收口事务。通过真实主人和队友运行验证工具资格，通过 ASGI 验证管理入口，通过实际前端函数与 DOM 验证分页、状态、关闭及旧按钮。所有检查由主代理串行经过收紧的资源守卫，外部模型与资料均为离线替身。

签名及发布取决于现有 GPG 会话恢复；本地实现和候选包不宣称已交付远端。

本地候选验证：8 份后端文件共 93 项通过，守卫内 15.755 秒、峰值 293.8 MiB；2 份前端文件共 80 项通过，3.669 秒、峰值 91.7 MiB；3 份源码严格类型检查通过，峰值 287.1 MiB。均为 swap 0。独立终审修正了脱离当前目录的旧按钮仍可触发操作的问题，随后回归通过；真实桌面、外部账号与模型未用于验收。
