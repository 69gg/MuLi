# 绑定任务的直属队友咨询

## 目标与复用

将现有 `team_consult` 开放给绑定任务说明的普通直属 worker，让完整执行任务也能在同轮向主助手核查资料后继续，不要求主人手工传话。复用 TeamConsult 队列、真实 run/generation/task/父身份、等待环、原渠道证明、有界等待和原路结果交付；不增加持久字段或模型进程。

## 原执行范围

咨询继续持有发问队友原 PreparedRequest，其中的冻结 TaskSnapshot 是本次咨询的唯一依据，不重新取新计划替换。guard_child 在入列、主控制轮及答案交付时核查原 TaskControl 执行资格。一般只读工具可在暂停时核查状态，咨询则属于原计划的延续：使用现有 write 执行资格门仅作撤销核验，工具与主控制轮仍只有 read 能力。TaskPaused 转为咨询拒绝，避免把主助手自身误标为暂停。

另外读取当前执行快照只作比对，忽略普通进度更新引起的 revision 增长；brief、plan、epoch、approved_epoch、范围或重新规划凭据变化均拒绝。服务不可用、缺少原快照、任务换绑和暂停同样拒绝，不给旧咨询续命。原一般读取、任务暂停与主助手重新规划语义不改。

## 主控制轮

在咨询 system 消息中加入原冻结完整任务说明、方案与代次，计入现有上下文预算，容量不足明确失败，不裁剪说明。子快照不赋给主会话 execution_scope，主助手没有取得执行绑定。只读 commitment_read 在咨询期间不选择重新规划；已有正常主轮读取和选择流程保持。

主人插话、队友新输入、停止、配置/渠道资格改变和模型迟到答案继续沿现有撤销流程。答案只交原队友，不外发、不批准新计划、不自动派工或重复未知副作用。reviewer、孙代与工作流节点仍不在本片范围；后续开放时必须保留其真实范围和等待关系，不能借取消现有门来实现。

## 验证

真实离线 Runtime 与 LocalServices/TaskControl 验证完整绑定派工、任务说明可见、只读核查、同 run/generation 接续；只更新进度仍可交付。模型等待阶段暂停、重规划并重新批准或修改原始说明时，旧答案必须失效；正常主助手规划选择不得被咨询读取清除或替换。另跑原普通/渠道咨询与任务控制、团队等待、插话和压缩交界回归。所有运行都经资源守卫串行完成，使用临时数据和 FakeClient。

快照对比沿用仓库已有 `dataclasses.replace` 模式，只构造比较值，不改原冻结快照；已按 [Python 官方文档](https://docs.python.org/3.13/library/dataclasses.html#dataclasses.replace)核对。Context7 本轮仍返回月配额耗尽，未反复请求。

五个新旅程节点已通过。重批变体在真实控制事务后、让出执行前，用独立咨询值副本将输入边界移到当前序号，单独断言旧 epoch 资格门仍拒绝；原运行的咨询和输入边界不改，随后继续验证原旅程撤销。初始夹具中的调用 ID/工具参数重名与任务说明 JSON 形状错误按真实接口修正，没有修改产品输出或放宽期限；共享调用助手将调用标识和工具名改为位置专用参数，避免与工具自己的字段冲突。

关联整合发现任务说明的旧压缩夹具直接调用 `_prepare`，绕过了已有任务所有权门，不能生成候选。该夹具改经 `observe`/`finish` 的真实受管生命周期，并保留完整说明、原文持久化、7000 字符预算与重新打开后的所有断言；没有放宽生产生命周期校验。

37 个关联后端文件在同一资源守卫内分两批通过，共 484 项；受改的两份生产源码通过严格类型检查，独立后审未发现待修的 P1/P2。以上均为离线临时数据验证，未连接真实模型、外部账户或桌面。
