# 可选本地声学适配器

本轮补齐已安装 sherpa-onnx 与 MuLi 声学 JSON 桥接之间的实现，复用现有录音、登记、后台循环、权限和取消流程。默认不启用、不安装依赖、不下载模型、不访问麦克风。

## 接口与配置

以 `python -m muli.acoustic_bridge --config /路径/acoustic.json` 运行一次请求；`--check` 仅验证配置、本地文件及依赖可发现性，不导入引擎或加载模型。配置文件独立于主配置，模型相对路径按该文件所在目录解释。唤醒、声纹可独立配置；缺失、格式错误或设备不匹配明确失败。现有配置工具可将同一命令数组填入两种桥接设置，不新增配置数据库或启动后台进程。

引擎使用官方 Python API：KeywordSpotter 与 SpeakerEmbeddingExtractor。每个进程单推理线程，模型仅在收到经过校验的有限 WAV 后导入。WAV 必须是单声道 16-bit PCM、符合请求采样率、完整且在字节与时长上限内；声纹先验证两份音频再载入引擎。模型只核对普通本地文件，不读取整个模型做检查。

CPU 为默认；CUDA 需明确配置及支持该 provider 的安装。该引擎本轮不宣称支持 ROCm；明确请求 ROCm 或与配置不符的设备即拒绝，auto 使用显式配置的 provider。返回的是配置 provider，不能据此声称已核实 GPU 执行。

## 阈值与身份

请求增加当前检测阈值。KeywordSpotter 的关键词阈值使用它；仅准确命中 `wake_word` 标签才接受。引擎不暴露每次唤醒概率，因此返回带实际阈值的 `score_kind=decision` 布尔决定，不伪造置信度；CommandDetector 仅为唤醒接受且校验阈值完全一致。现有带有限 score 的桥接协议继续有效。

声纹使用两份音频的真实 embedding 余弦相似度，非有限、维度不匹配或零向量拒绝，负值按 0 返回。未通过声纹不能取得主人权限。声纹登记依然只录制参考音频，不训练；参考和指令不因本地比对上传。

## 边界与验证

保留既有 15 秒受管子进程期限与输出限制；本适配器不另造守护进程。按片启动的模型加载时间、真实模型准确度、CUDA 执行及三平台音频硬件均未实测，不承诺持续监听性能或抗重放能力。原始音频、配置和模型错误不输出为主人信息。

离线替身覆盖正确 API 接线、阈值、音频前置校验、依赖缺失、设备不支持、声纹异常、CLI stdout/stderr、现有语音生命周期回归。检查继续串行通过仓库资源守卫，不安装实际引擎和模型。
