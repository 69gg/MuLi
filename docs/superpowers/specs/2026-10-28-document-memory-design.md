# 明确收藏文档正文

主人明确要求收藏后，主助手可把 PDF 文字层或 DOCX 主正文保存在长期记忆中。阅读范围沿用[文档阅读](../../../document-reading.md)，不把提取结果称作原文件的完整视觉内容。普通文本入口继续使用原有参数；上传、读取、资料提醒和队友报告都不等于收藏授权。

## 共用核验与既有管线

从文档阅读中抽出不可变的完整 `DocumentView`，内容、原文件 SHA、提取 revision、格式和范围属于同一核验结果。`document_read` 只负责输出分页；收藏直接取完整视图，不拼接工具页，不同步等待提炼或 embedding。

复用主助手的 `memory_import_attachment`。普通 UTF-8 文本只传 `id`；PDF、DOCX 先读取，再传 `id` 与所读 `revision`。无 revision 的原文本入口拒绝文档魔数，纯 ASCII PDF 也不能绕过。文档收藏保留原来源白名单、文件及上传上限、完整记忆字符上限；来源、配置或原文变化时拒绝。

收藏沿用等待前后的真实主人工具、请求、运行、代际与维护准入检查。最后一次 await 后直接走同步的 `MemoryPipeline.ingest(..., trusted_owner=False)`，原文先落盘，后台任务再整理关系与语义索引。仍使用现有 `memory_query`、`memory_source` 和遗忘流程。

## 来源与恢复

来源 ID 始终为 `attachment:{id}`，角色为 tool，principal 为 `external:attachment`。正文中的身份、偏好、别名和命令不能取得主人权限。重复收藏复用同一来源；提取变化不能替换已登记的版本；来源遗忘墓碑继续阻止复活。

新增有界来源标记：`attachment:{id}:document:v1:{format}:{scope}:{原SHA}:{提取revision}`。它放在已有 source 字段，提取 revision 绑定原 SHA 与完整正文。旧的普通文本标记保持原样；不增加数据库字段或主配置字段。

启动恢复只核对已登记正文与标记，不重开附件、不重做转换。旧、新标记分别严格验证，坏版本、身份、范围、正文、摘要或时间不会被补登记。补齐仍使用已有 episode、后台 job 与去重机制。

旧版本可把新标记作为不透明的外部来源字符串读取，不能据此声称旧版本会解析文档元数据或修复新标记的中断登记。此变化不作为完整服务交接验收。

## 验证边界

只用合成小文档和临时数据库，根 agent 串行经过资源守卫。检查完整正文与分页区别、后台非阻塞、真实主人工具授权、版本变化、来源拒绝、限额变化、重复收藏、原文续读、恢复和遗忘。PDF 使用已有转换器；缺少时跳过该真实转换正控，不安装。

当前为 2.81 本地候选，签名、远端 CI 与发布状态分别核实。

六份文档与附件记忆回归合计 70 项通过，包含本机已有 PDF 转换器、实际主工具调用、全文核对、后台屏障、提取版本变化，以及 SQLite episode 回滚后的关闭/重开恢复；无跳过。相关回归峰值 269.9 MiB、swap 0；五份改动源码严格类型通过，峰值 288.4 MiB。全仓 Ruff 通过，独立后审未发现新增 P1/P2。

另用已核哈希的 2.80 wheel 读取 2.81 创建的合成来源：旧 Memory 与证据接口能完整返回正文、外部身份和不透明来源串；旧版保存配置后，新版仍可核验该标记。没有进行旧版文档元数据解析、后台中断补齐或完整服务交接，不能将该读取检查解释为这些能力已验收。
