# 普通执行队友向主助手咨询

## 目标

普通直属队友遇到资料核对或判断问题时，可在同一执行轮通过现有 `team_consult` 向主助手取得只读建议后继续，减少主人手工传话。现能力仅接管渠道的队友可用；此次复用相同队列、等待环检测与只读控制轮，不引入新模型、进程、协议或持久格式。

## 范围与身份

首片面向主助手直接派出的 worker，且没有任务账本或工作流绑定。reviewer、孙代、有任务说明绑定或工作流执行仍沿现有协作方式；不能借咨询绕过任务暂停和完整执行快照。

普通队友的咨询冻结真实 parent、run、generation、运行 task 与当前 PreparedRequest。入口只能由当前真实工具处理调用；排队、读取资料、交付答案时持续核验同一身份。渠道接管队友继续冻结并核验原批次真实接纳的 ownership proof；没有 proof 不能降级冒充普通队友。普通咨询期间新增渠道归属也撤销此次咨询。

## 执行与撤销

继续使用既有有界等待与 child→main 等待边，主助手正常工作与主人消息优先，空闲后进入只读咨询控制轮。仅允许主助手已有的只读工具；问题、答案都是资料，不是新授权或新的主人请求，答案只交原队友，不自动外发。不能替主人批准、派遣更多队友或自动重做外部操作。

新的主人输入、队友输入、停止、重配置、维护及渠道权限变化仍撤销未交付答案；迟到内容不重新交付。不跨进程恢复尚未完成的咨询，也不取消无关任务。主助手正等待该队友时拒绝等待环，队友仍可阶段汇报后结束本轮。

## 验证

真实离线 Runtime 覆盖主派工→普通队友提问→主只读查证→同一 run/generation 接续完成，并检查答案仅为资料、无新主人输入或外发。另核主人插话撤销、真实父等待环，以及角色、代次、任务与工作流的拒绝路径；继续执行已有渠道接管咨询的故障、撤销和排队回归。只使用临时目录与 FakeClient，不调用外部模型或真实平台。

普通队友完成报告仍按原流程投递主助手，不能照搬渠道接管队友的 `local` 报告预期。插话验收核对准确主人输入的 ingress 交付与非咨询 run，不能要求其他队友报告也已全部消费；任务说明对照须挂接真实 LocalServices/TaskControl。这三处夹具问题在原运行记录与有限失败输出中定位后修正，没有更改生产收口语义或扩大等待时间。
