# 较长首条输入的后台压缩

## 问题与最小修复

原选择循环一达到目标大小就停止，随后才检查是否包含助手消息。首条用户输入已超过目标时，虽然其后已有完成回复，循环仍只选输入并放弃候选；后续观察会遇到同一前缀，无法开始压缩。

复用现有 `closed_groups`、有限历史前窗和候选生命周期，只把停止条件改为“达到目标并已包含助手消息”。每次添加完整组，维护一个布尔值；遍历完没有助手消息仍不生成摘要。没有新增配置、模型请求并发、存储字段或后台循环。

## 保留边界

最新输入不进入所选前缀。完整原生工具调用及对应结果继续作为一个组；尚未被助手处理的完整结果和未完成调用仍不可跨越。已有取消、配置指纹、序号摘要和候选代次门不变，原始消息不改写。

本片解决的是原有限前窗内已有合格回复却提前停止的问题。超过前窗且无法取得合格完整组的历史仍不会自动扩大读取；不能据此宣称任意大小的单条消息都可压缩，或摘要能无损保留所有细节。

## 验证

新选择回归在修改生产代码前准确得到两项失败、三项负控通过：长输入后普通回复与已消费原生工具批次均未启动摘要，尚未回应输入、待读完整工具批次和未完成调用均正确保留。测试使用临时 SQLite 和假模型，真实执行受管压缩流程，不直接登记内部任务或调用 `_prepare`。

关联验证覆盖旧压缩、关闭与取消、待读工具结果、任务说明和主/队友 Runtime；正常关闭重开只证明持久记录可回放，不代表真实系统服务恢复或自然模型摘要质量已验收。所有执行均经既有资源守卫串行完成。

主会话与真实派工队友的两个旅程已通过：三轮实际模型请求、队友原身份的三代续办、下一轮摘要注入、当前输入完整、原文不改与正常关闭重开。初跑夹具把摘要误认作独立的 provider 消息；按现有 Runtime 将资料摘要并入 system 的实现核对完整正文后通过，未改变产品投影。直接选择与既有压缩/生命周期/待读边界的五文件 38 项同样通过；生产源码严格类型检查通过。

最终 39 个相关后端文件在同一守卫内分两批通过，共 491 项，内存峰值 434.9 MiB、swap 0。独立后审未发现待修的 P1/P2；未接触真实模型、账户或桌面。
