# 命令结束通知

主人明确要求时，主助手通过 `shell_run(command=..., notify_on_finish=true)` 为当前命令登记 Web 通知。主回复可以先结束；命令完成、超时、停止或无法确认结果后，通知显示原会话、命令编号及准确状态。通知不代表任务成果已经验收。

## 使用边界

- 默认省略或 `false` 保持原行为，一次性 `argv` 不接受通知选项；队友可以继续执行普通命令，但不能登记这项通知。
- 通知不包含命令正文、目录或输出，不自动读取尾部、不启动模型回合、不向外部渠道发送。输出仍通过原 `command_id` 显式读取。
- 每个通知绑定原会话、命令及操作系统代次。新输入、无关配置修改和后来的命令不会移用该选择；重复收口不会重复通知或重置已读状态。
- 已删除身份不生成迟到通知。正常关闭先收取命令及通知回调，再关闭数据库；重开不会重做旧命令。崩溃、强杀或通知写入故障可能没有通知，应查询保留回执与实际状态。

## 实现与验证

沿用持续 shell 的 monitor、cleanup、权限和期限，以及既有通知对象、原子事件与 EventBus。通知选项在派发前计入回执预算；不增加调度器、持久订阅、存储格式或依赖。已有 Linux 桌面副本继续遵循原开关。

真实流程回归覆盖主回复先结束、原命令认证完成、唯一 Web 通知及之后显式读取双流；另覆盖正常关闭、全进程组丢失、超时、身份删除、写入故障、队友权限、容量及回调收取。相关真实进程用例限定 POSIX；Windows 原生命令和真实桌面发送仍须各自验收。执行结果保留在开发检查日志中，不作为本文的版本发布声明。
