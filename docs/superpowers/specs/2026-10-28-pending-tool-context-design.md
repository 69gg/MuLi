# 实时补充与待读完整回执

目标是在现有工具边界插入新消息时，保留尚未交给模型处理的宿主完整结果。无需数据库字段、额外常驻任务或额外模型请求；只修正现有打包与摘要选择。

## 可复现的缺口

`Runtime._execute` 在工具批次结清后接纳排队输入，再重建下一请求。`context._preserved_results` 原本只跳过尾部 system/developer；尾部 user 使宿主 `preserve_content` 标记提前失效，过长 JSON 会被节选，整轮也可能被移除。新增七个纯打包节点在旧行为下四个失败，修后全部通过。

后台 `Compactor.observe` 原来只排除最后一个闭合组，工具批次后的 user 组使尚未消费的完整回执进入摘要候选。前台超限后的 finish/project 回退也必须遵守同一边界。

## 实施

从请求尾部跳过 user/system/developer，保留最近连续工具批次中的宿主完整标记；遇到 assistant 就停止，不寻找更旧批次。补充输入不表示模型读完回执，新的助手响应或下一批调用才释放旧保护。最终打包不节选这些结果，也不移除包含它们的整轮；仍放不下则明确 ContextLimitError，归档保留原文。

后台压缩识别同样的待读工具组，仅选择此前的闭合组。由于摘要读取有限前窗，额外只查询持久历史中最近 assistant 的序号，避免把窗口外已有回应的旧工具误认为待读，长期阻塞压缩。该查询不把窗口外正文加载到 Python。

结果正文不能自行声明完整保护；标记仍只能来自宿主 Tool 配置。保留现有原生协议、工具配对、摘要 digest/generation/fingerprint 与历史来源边界。普通旧工具、已经回应的结果仍可节选与压缩。

## 验证

纯打包覆盖单条/多条补充、宿主固定指导、超限显式失败、淘汰已结束旧轮及保护释放；摘要覆盖完整与普通结果、消费后可再整理，以及消费回应落在有限前窗外。真实 Runtime 在 Event 阻住只读工具期间提交补充输入，再验证下一请求同时收到补充与完整 JSON，分别检查关闭和开启后台压缩。验证全部离线、临时目录，并由资源守卫串行运行。
