# 长资料的完整检索覆盖

收藏完整原文后，主助手与队友都应能从正文后半段找到相关资料。当前来源关键词索引保存了全文，但公开的 `memory_query` 只召回记忆条目；关闭模型提炼时，长来源通常只有前 12000 字的 episode 和向量。正文保留不等于检索覆盖。

本轮沿用 SQLite、既有分层记忆和唯一后台 worker，不增加数据库、常驻进程或模型下载。设计由开发者在用户的持续自主迭代授权内确定，复用既有审批、原文核查、检索与遗忘边界。

## 后台分块

原文仍先登记并返回，模型与向量请求不进入主对话的等待路径。超过单条记忆容量的来源在原后台 job 中生成连续、固定重叠的原文块，保存为已有 observation / episodic 条目；逐字 quote、source_id、来源标签与原信任属性保持。短来源保持原行为。

独立热策略记录配置块字符数、重叠字符数、最大块数和单批大小，不更改主配置格式。默认 2000 字符、重叠 128、最多 64 块、每批 4 项。创建计划前计算完整覆盖，超过块额度明确失败，不以部分正文声称完成。冻结版本、来源 digest、原文字符数、分块参数与单批大小，已开始的工作按原计划续接，新策略供后续作业使用。

新 checkpoint 单独记录块计划和已创建前缀，保留原 memory_ids 的事实与初始 episode 含义。块的去重键绑定来源版本及准确位置；每批后保存进度并让出事件循环，正常关闭后接续，不因重开重复生成条目。

## 索引与原文

分块使用已有关键词索引、embedding、reranker、提示词选材与 `memory_source`，不另造查询工具或全文副本。关闭自动提炼仍可建立原文块与向量；没有配置 embedding 时保留本地关键词检索。原文仍按既有来源版本和字节位置续读。

原始 archive episode 仍保留并参与关键词查询。长来源已完整分块时，只在既有 `automatic_episode_id` 证明其仍为未经修改的原始归档副本时，省去该重复头部的 embedding；避免额外发送 12000 字的头部绕过单块大小。更正后的条目不借此证明被排除。

向量工作按批处理。取得媒体锁后、发送请求前与返回提交前都核查来源 digest、遗忘状态、条目版本和当前模型标识；过期正文不能借等待锁发送，过期向量不能回写。每个成功写入保留进度，失败不重做已确认前缀。保持现有来源、向量扫描与输出额度，不保证全库必然召回，也不把原文中的声明变成主人事实。

显式重建纳入普通作业保存的已建块；旧完成来源可在明确选择重建时补齐原文块，不在启动或查询时自动重跑全部旧资料。完成作业原提炼历史保留；新的重建计划持有自己的进度和版本证明。旧完成作业不回填分块 checkpoint，后续不同请求键的计划会按当时策略重新规划；相同策略可复用稳定去重条目，策略变化可能增加条目与向量请求。遗忘仍按来源级联清除正文、块、向量及派生事实，墓碑阻止重建或重开恢复。

旧版本可以读取这些普通 episodic 条目和完整原文；不能宣称旧版本认识新块 checkpoint 或会恢复新进度。保持数据库及主配置格式不等于完整服务交接已验收。

## 验证

用无提炼的长合成附件证明旧查询无法召回尾部，再通过真实主工具收藏与后台 HTTP 替身验证尾部的关键词、无词面语义召回和原文核对。覆盖中途关闭重开、分批失败、同源去重、遗忘、等待锁时更正/遗忘、模型更换、明确重建以及策略热更新。开发检查串行经过收紧的本地守卫；不触碰真实文档、桌面或外部模型账号。

2.82 候选的 13 份相关回归共 160 项通过，覆盖分块、旧记忆管线、重建、附件收藏与上下文预算；守卫内 27.722 秒、峰值 362.6 MiB、swap 0。最终四份源码严格类型检查通过，峰值 263.8 MiB。独立后审修正了旧完成来源在新计划中重新规划的文档表述。

用哈希核验的 2.81 候选安装包真实创建旧完成来源，新版显式重建后可查询并索引尾部；反向验证旧版可读取新版的普通分块条目、关键词查询及原文，旧版保存主配置不会丢失独立分块设置和作业记录。兼容检查 3.428 秒、峰值 60.7 MiB、swap 0。未验证旧版恢复新版分块 checkpoint、完整服务交接或真实外部模型。
