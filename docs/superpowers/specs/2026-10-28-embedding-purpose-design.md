# 向量检索的文档与查询参数

## 目标

让需要区分建索引和查询输入的 embedding 服务正确工作。现有 `query_instruction` 已保存在配置并进入向量指纹，但 embedding HTTP 请求从未使用它；文档与查询也一直共用全部附加参数。复用现有 OpenAI 兼容 `/embeddings`、媒体预算、后台索引和显式记忆查询，不新增服务、依赖、模型并发或自动重建。

## 配置与请求

`media.embedding.query_instruction` 仅为查询正文加前缀；新增 `document_instruction` 仅为建索引正文加前缀。原样连接，所需空格、换行由配置提供，源记录和关键词/关系查询不改写。空前缀保持原输入。

新增 `media.embedding.query_extra_body`，查询时在已有 `extra_body` 上按顶层键覆盖；建索引只使用原 `extra_body`。例如通用字段保存文档侧 task，查询专用对象覆盖为服务支持的查询 task；不按模型名称猜测任务类型，也不写死供应商。核心字段仍由宿主生成并禁止覆盖，合并后的完整正文参与原输入预算。两项新配置同时接入原配置校验、自然语言自身配置和网页媒体设置。

`MediaService.embed` 新增可选关键字 `purpose`，值为 `document` 或 `query`，默认文档，既有普通调用不改语义。记忆的两个建索引路径保持文档用途；显式语义查询使用查询用途。reranker、ASR、TTS 不使用这些新增参数。

## 索引、缓存与边界

不修改已有向量或数据库格式。空文档前缀保持原向量模型指纹；非空文档前缀加入指纹，避免混用不同文档表示。查询专用参数不影响文档向量；配置应用复用现有 MemoryApplication 重建 pipeline，清空内存查询缓存。既有查询指令仍保留在原指纹合同里，不悄悄改掉历史索引身份。用户需要时沿现有显式重建入口处理，不自动发起全库工作。

前缀只在实际媒体服务边界应用一次；关键词、图遍历、查询缓存和 reranker 使用原问题，reranker 自己原有的前缀规则不变。坏参数、超限、网络失败继续降级到本地查询；原文和已有索引不被失败覆盖。

## 验证

用临时配置、SQLite、真实 MediaService 与 `httpx.MockTransport` 核对实际 HTTP：查询/文档不同前缀和 task、顶层合并、核心字段保护、前缀及参数计入预算、空配置兼容。真实后台 ingest、显式查询、重建索引和配置重开核对用途、原文、原问题与指纹；既有异步取消、遗忘和缓存边界保持。

只用离线替身，不请求真实模型或下载模型。Context7 查询本轮仍因月配额耗尽不可用，未重复请求；配置字段的独立默认值按 [Pydantic 官方文档](https://pydantic.dev/docs/validation/latest/concepts/fields/#default-values)核对。供应商具体 task 值须按其文档配置，不由本设计宣称任意 endpoint 已兼容。

独立后审发现网页表单统一 trim 会删掉前缀分隔符，两个前缀字段现使用原文格式，表单收集保留空格/换行；普通模型地址等文本的原有 trim 行为保持。前端回归同时核对字段格式与实际导航收集、保存请求、返回后的值。

41 个相关后端文件在同一守卫内分两批通过，共 531 项；内存峰值 464.7 MiB、swap 0。三份受改生产源码严格类型检查通过。新媒体请求与配置回归、真实后台索引/查询/显式重建/正常重开均已通过，未接触真实账户或下载模型。

前缀保存修复后，四个相关前端文件共 43 项通过；独立复核确认该 P2 已闭合，未留下待修 P1/P2。网页仅用离线渲染/表单替身验证，没有启动真实桌面浏览器。
