# 后台压缩的撤销与收口

目标是让主助手、队友和工作流继续共用现有分层压缩，关闭或清理派生摘要时不接纳迟到结果，也不遗失正在收口的任务。原始消息、任务说明、完成日志与长期记忆不随关闭删除，摘要仍然是资料而不是授权。

## 已确认的代码边界

现 Compactor.close 取消任务并直接 gather。若摘要调用捕获取消后返回，_prepare 仍可发布候选，_done 又会为 idle/paused 会话自动采用；关闭只清理内存，已经落盘的迟到摘要不会因此撤回。已有正常取消用例没有覆盖忽略取消的服务适配器。

forget 直接等待旧任务。旧 done callback 移除该任务后、forget 恢复前，另一次 observe 可以建立新任务；forget 无身份判断地 pop 会将新任务脱管。原文仍存在时，迟到结果可通过原 digest/generation 校验重新落盘。这是派生摘要清理 API 的反例，不能扩大为“已删除会话必定复活”：删除端点随后移除原文，digest 门仍会拒绝不匹配结果。

## 实施选择

继续使用现有 prefix digest、generation、配置 fingerprint、单摘要请求和有限作业预算。增加关闭与按会话清理的所有权，不增加常驻 worker、模型调用或数据库格式。

关闭立即撤销新 observe、候选发布与 adopt；清理某会话期间同样暂时撤销该会话。_prepare 在真实模型 await 后再次检查当前任务身份、取消状态与生命周期，_done 只有仍拥有该任务槽时才修改候选或自动采用。旧回调不能操作后来同会话的新任务。

close 与每个会话的 forget 各有一个强拥有的清理任务。重复调用共同等待，外层等待取消不得再次取消正在清理的摘要协程；等待者的取消最终在清理结束后传播。close 同时收取已开始的 forget，确保返回后没有脱管数据库写入。forget 只在旧任务结清后删除本会话的派生层，不修改原文；完成后仍可基于保留原文显式重新压缩，不能将它描述为长期遗忘。

## 验证范围

离线临时 Store、现有小历史 fixture 和 Event 门控证明：吞取消的迟到摘要不能在关闭或清理期间落盘；forget 期间新 observe 被挡；重复或取消的 close/forget 等待不会二次取消子清理；关闭结清并发清理；原文及已存在的摘要在普通关闭后仍保留。再验证正常分层压缩、队友完成游标、跨入口历史读取与正常关闭重开。所有执行由主代理经资源守卫串行进行，不运行真实模型或桌面。

取消与强引用语义已按 [Python asyncio 文档](https://docs.python.org/3.13/library/asyncio-task.html#shielding-from-cancellation)核对；Context7 本轮返回月配额耗尽，改查官方文档。接口核对不作为行为验证。
