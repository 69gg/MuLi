# Windows probe 的清理期诊断

v2.104 候选两次在同一个原生依赖探测用例中超时；Python 3.12 与 3.13 各出现一次。请求已写入并完成 drain，清理后原 reader 的 stderr 前缀为空，但这不能说明清理阶段没有收到输出：共享进程清理会取消原 reader，再丢弃剩余管道内容。

本次仅在测试观察层补齐这个证据缺口。在同一个 stderr reader 上旁观原有 read，保留有限前缀；原 reader 和清理过程仍使用原来的对象、调用、输出预算和清理顺序。只报告允许的阶段、是否附着观察与实际 EOF，不记录原始 stderr。

保持原请求期限、用例顺序和生产实现，不预热、不重试、不跳过。便携回归验证清理期输出、输出上限、取消与错误透传；之后只启动一次托管 Windows 原生检查。这个观察改进本身不构成根因修复，成功运行也不能证明此前的超时已消失。
