# 在指定来源内查询长期资料

## 目的

主人已收藏资料并从来源目录选中某份附件或经历后，应能要求“只查这份资料的备份步骤”，无需把整份原文装入上下文，也不被全库同主题资料占满候选。现有 memory_sources、memory_source、memory_query、关系路径及向量服务继续复用，不新增数据库或模型依赖。

## 范围与接口

memory_query 增加可选 source_ids。不传时维持原有全库行为；传入时必须是非空来源 ID 列表，按精确 ID 去重排序，不把 ID 当正文查询词，不把空列表或无效参数降级成全库。条目数受现有 max_candidates 限制，总 ID 字符数沿用现有查询长度上限；不默默裁剪。未知或已遗忘的来源可返回空结果，不扩展范围，不由此恢复资料。

查询范围同时进入关键词、近期条目、别名种子证明、图边和向量 SQL，均在候选/扫描 LIMIT 之前生效。来源范围是检索选择，不是新身份或授权。返回条目仍保留原来源与信任标记；冲突引用不表示其它来源已被检索或核实。未指定来源的调用、自动注入、主人侧写及记忆管理不改变。

Memory.source_scope(source_ids) 返回规范 tuple 或 None；search、traverse、vector_search、vector_count、communities_for 增加同名可选参数。内部 source_ids 参数同样核验，所有值均使用 SQLite 参数绑定。范围内别名只采纳该范围的有效贡献，不借另一来源的别名制造命中；完整 graph_via 中的别名来源及每一步来源均在范围内。

已有社区摘要可能混有别的来源，不能原样附上。范围查询通过现有受限图遍历和成员读取，临时生成范围内的社区投影，复用普通社区内容格式和预算，不写入或覆盖全库社区。标题、摘要、证据与来源只来自范围内成员；不把受限遍历说成全库完整性。社区 ID 与全库 ID 区分，保留 truncated。

## 查询与自动上下文

Pipeline/Application 传递同一范围，融合、重排及发生 revision 变化后的本地刷新都保持范围。只有范围内候选正文可发送至 reranker；向量扫描不先取全库前 N 条再过滤。已有锁、超时、降级和取消合同保持，不自动触发重建或提炼。

范围集合进入显式查询缓存键。自动提示只允许复用无范围缓存，不因一份资料的查询改变全局提示选材。查询输出附完整 source_ids 元数据，沿 query_result 的全输出预算核验，范围元数据放不下则拒绝，不截断成另一范围。

模型工具与已认证 GET /api/memory/query 使用相同参数；HTTP 通过重复 source_id 参数传入。网页来源详情提供一个简洁“在此来源内查找”入口，沿现有记忆查询展示结果，可回到全库。主助手与队友均可只读使用；不会因此获得重试、重建、遗忘等写权限。

## 验证与交付

使用临时 SQLite、离线 HTTP 服务替身与真实 Runtime/工具路径验证：同词多来源不挤占；关键词、向量、别名、跨源桥接关系及混合社区不串范围；多来源组合与输入顺序等价；未知、遗忘和无效范围不退回全库；重排请求只含范围内正文；等待模型期间修改或遗忘仍按原范围刷新；范围缓存不进入自动提示。保持原无范围回归、完整输出预算与错误行为。

网页测试确认来源入口和全库切换、保留统一时间轴/页面结构。离线 wheel/sdist 核验包含实际改动及安装后的 CLI/资源；不访问真实模型、账户、资料库或桌面。完成独立后审后保存本地 v2.97 候选，签名条件未恢复前不冒称已提交或发布。
