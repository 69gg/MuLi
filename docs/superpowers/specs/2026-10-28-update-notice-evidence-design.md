# 更新提醒的检查依据

目标是避免临时网络失败吞掉尚未交给主助手的真实更新提醒，同时保持最近检查结果准确。更新检查、提醒和安装授权继续分别处理；不增加网络轮询或自动安装。

现状中 `update/latest` 同时表示最近检查及所有通知的依据。一次失败覆盖它之后，Attention 会把先前的新版本通知判为无效并推进游标；同一版本恢复又因通知 ID 已存在而不重发。

新的通知与原事件在同一事务保存有限 `update_evidence`：格式版本、当时运行版本、已验证的新版本及检查时间。不复制元数据正文、URL、密钥或异常消息，不另建无界版本记录。通知校验同时核对事件和已保存通知的依据；再检查正式版本号、时间、通知 ID 和目前运行版本。已有依据独立于可变化的最近检查结果，已安装该版本后则不再作为待更新提醒。

`update/latest` 继续如实表示最近一次检查，网络失败仍显示 unavailable。旧通知没有新依据时保留原来的 latest 校验路径，不从正文推断或补造历史事实；格式错误、缺失或不一致的新依据直接拒绝，不能降级成旧逻辑。通知的来源、首次冻结路由、只读 Attention 权限、每版本一次及安装前重新核验保持原有行为。

离线回归覆盖成功后消费前失败、忙碌时延后处理、同版本恢复不重复、原冻结渠道不随默认变更、事件/通知依据不一致、异常格式和已安装版本。仅使用 HTTP 替身，不访问更新站点或安装真实软件。面向用户的日志说明与开发细节分开，保持已有技术内容可查。
