# 提醒时钟的失败隔离与恢复

v2.66 已发行，本地整合、独立后审、精确远端检查和两包元数据核验已闭合。一次提醒或定时委托写入失败后，健康提醒继续工作，并可通过真实事件恢复；不增加模型轮询、监督服务或新的持久队列。

## 现状与首片边界

现有 `Reminders` 只有一个后台 Task，普通提醒、原任务定时续办和独立定时工作流共用它。任一入口的未处理异常会结束整个时钟；之后 `changed.set()` 不能唤醒已结束的 Task。关闭仅收取取消异常，旧时钟错误还会阻断 Runtime 后续资源关闭。

首片保留原单 Task。在该 Task 内隔离具体普通提醒或两个固定委托入口的失败，排除其失败到期值，健康入口继续。只有原 `changed` 的真实唤醒允许一次恢复机会；正常期限超时不能清除失败门。失败诊断不得间接唤醒主会话再触发自身恢复：沿原日志设施使用固定安全信息、显式 `muli_notify=False`，诊断自身失败不应再次结束时钟。

真实配置、主人输入、创建或改期提醒，以及工作流空闲仍沿原事件唤醒。恢复重新读取当前持久事实和授权，不复用失败前的对象。无事件时不承诺静默修好外部故障，也不以过期 due 值形成短周期重试。

## 不确定结果与关闭

异常类型或 `db.in_transaction == False` 不能单独证明没有提交。已接纳的控制回执不再请求一次重规划，已登记的工作流不再派工。持久 queued run 也不证明 driver 已创建；提交后返回丢失或创建 driver 前失败的情况保持阻断，正常重开沿原恢复规则标记 interrupted，不借恢复再次执行。首片只验明确回滚的恢复，不承诺通用 COMMIT unknown 自动修复。

`CancelledError` 保持原关闭语义。时钟关闭实际等待唯一 Task，收取已经发生的旧故障；Runtime 仍先收口实际 driver，再关闭 Store 和释放 writer。不能为声称关闭成功提前释放仍有人使用的数据连接。

## 验证计划

先用真实 Runtime、原时钟和临时 SQLite 触发器，使定时委托的接纳事务准确回滚，再验证时钟仍活着。后续成功路径核对健康普通提醒实际产生一次通知，删除触发器后由真实 `changed` 恢复一次；不替换 tick 抛假异常，不用睡眠估计轮次。

正式首红使用真实主人 Web 入站、主助手工具执行和持久来源创建定时委托；SQLite 触发器在原接纳事务最后一个 workflow_run 插入时中止。准确核对 schedule 未变、无 occurrence/run/driver/node，之后失败于原时钟 Task 已结束：1失败0.22秒，守卫808ms、峰值69.1 MiB、swap 0。这不是伪造 tick 异常或测试生命周期错误。

首版实现后，正式回滚旅程与三项独立边界共4节点通过，0.34秒；守卫947ms、峰值73.5 MiB、swap 0。独立边界使用真实单提醒通知事务回滚、完整委派通知后抛错，以及实际 SystemEvents 工作者和 Attention 消费游标，证明健康提醒按原期限推进、已提交通知和次数不重复、诊断不产生主输入或自激。通知故障发生在实际 notify 已委派之后，不是通用 COMMIT unknown 验收；正式旅程的节点执行为固定合成内容，不代表真实模型工具质量。

后审另取得两条准确目标红，合2失败0.35秒，守卫1.086秒、70.3 MiB：超时取消窗口执行合法持久编辑，随后实际等待证明恢复信号被吞；以及受控入口真实 BEGIN、写 sentinel 后抛错，下一健康事务错误提交该前缀。后者是未收口事务边界注入，不是物理磁盘 rollback 失败验收。修后6节点通过，守卫975ms、72.7 MiB；单调停靠门不被真实 changed 或配置重建解除，未知事务不由时钟擅自回滚。

随后28文件整合297通过、5失败，暴露通用通知 finally 提前唤醒并消费了原待重开输入；没有修改旧预期。通用通知恢复原顺序和取消语义，只为本次新建且准确持久的 scheduled pending 输入补原唤醒。独立正式旅程临时恢复原窄函数后准确失败于没有新主运行，1失败0.51秒，守卫1.252秒、96.3 MiB；生产修复恢复后，真实时钟完成接纳、主助手读取、下一轮批准与原队友G2，重访到期入口不增加发生、控制回执、投递或实际临时写入。

独立后审又发现：前一回滚失败排入的真实日志，能在后一入口留下未收口事务后替它提交。真实消费者与独立SQLite连接取得准确首红，sentinel可见1而非0；1失败0.28秒，守卫881ms、71.7 MiB。SystemEvents 的持久化和保留清理均在任何DB读取、回调或事务上下文前拒绝已有事务，沿原有限失败/停止接收路径退出，不提交或回滚未知前缀。新测试与取消回归12项通过；两位非作者分别核准该链路与准确补唤醒边界。

最终新增两文件共8节点通过，0.69秒；守卫1.587秒、92.6 MiB。28文件整合304项通过，12.67秒；守卫14.871秒、486.5 MiB。发布、配置、正常重开与日志关闭另9文件254项通过，4.27秒；守卫5.558秒、203.4 MiB；共558个不同本地节点，其中8个新增，不重复累计中间小组。全部154源码在干净缓存下严格类型通过，守卫9.340秒、449.1 MiB。所有上述检查swap均为0，后续静态、打包和精确远端结果另记。

Ruff、432文件格式及离线锁核验通过，无依赖更新。离线构建守卫1.693秒、104.2 MiB；隔离wheel安装后的导入、兼容声明、资源、默认桌面禁用、任务控制与生命周期检查1.471秒、101.8 MiB。包审首次以临时脚本直接启动时因找不到仓库 `scripts` 模块退出，未运行校验；改为从仓库模块路径启动后264ms、19.5 MiB通过：validate函数核对版本/声明/发布说明，三个生产模块及角色资源与两包字节一致，生成原稿未入包，未调用会覆盖原有 `release-notes.md` 的发布main。

所有本机检查由根 agent 串行经资源守卫运行，保持原测试时间门；没有本地模型、大下载或真实账号/桌面操作。关闭证据区分恢复后的正常关闭、仍隔离时实际调用关闭，与尚未专门观察的全部外部组件收口顺序。未修复 `Reminders.close()` 原有的直接调用者取消传播问题；Runtime 的公开关闭沿原 settle 保护。不得由本片通过推断整个应用在数据库损坏或所有未知事务下均可自动恢复。
