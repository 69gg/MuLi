# 个人记忆与关系证据

MuLi 面向单个本机用户，将对话记录与长期记忆分开保存。长期记忆包括 observation、fact、preference、procedure、summary 五类，每条包含内容、来源、置信度、创建/更新时间、实体和有来源的关系。不自动把全部历史当成可信事实，也不要求多用户分区。

## 写入、修订和忘记

模型通过 `memory_remember` 提议保存；该工具经过与文件等操作相同的权限门。工作台支持手动新建和修改。写入验证内容、来源、实体和关系数量，一次事务保存事实、索引与关系。模型收到的提示明确要求保留出处、不存密钥、不要把推测写成确定事实。

修改时先保存完整旧快照，再更新内容与索引，工作台展示最近 50 次修订；完整修订仍保存在数据库并可导出。关系使用 `subject / predicate / object`，每条边通过 `memory_id` 指向提供证据的记忆。删除记忆时，索引、关系和修订级联删除，不留下仍可召回的旧版本。

该设计不自动解决相互矛盾的事实。检索向模型展示时间、置信度和来源，并要求将记忆视为待核实资料；用户可以更正或忘记错误事实。SQLite 删除不是介质安全擦除，已有备份仍需由用户管理。

## 召回过程

1. 英文词和中文双字词构成倒排索引，覆盖全部已保存历史；无需常驻 embedding 模型。旧数据以每批 100 条建立索引。
2. 查询最多使用 64 个词，SQL 按命中数选取最多 256 条候选，避免扫描后将全部内容加载到内存。
3. 对明确命中的实体扩展两跳关系，每跳最多读取 256 条边。候选保留原始证据的 `memory_id`。
4. 按词命中、图关系、置信度、时间衰减综合评分。偏好和步骤不按年龄衰减；其他类型以 180 天尺度衰减，但不会自动删除。多样性选择降低近似重复内容的占比。
5. 结果标明 `matched_by` 和 `score`。正常聊天只注入少量召回资料，并受上下文预算约束。

这是一种轻量的文字和图关系联合检索，适合本地个人事实与操作步骤。它没有向量语义检索、GraphRAG 社区摘要或自动关系抽取；同义改写且没有共享实体时可能漏召回。后续可在保持来源、修订和忘记协议的前提下增加可选召回器。

## 管理与验证

记忆页提供搜索、类型、来源、关系图、修订和删除入口；图展示最多 1000 条关系，列表每次最多 100 条，完整记录保留在数据库并可导出。测试覆盖中文检索、两跳关系、早期历史召回、修订快照以及忘记后的级联清理。
