# 使用长期记忆

长期记忆帮助沐璃在会话压缩、正常重开或更换聊天渠道后，继续查找曾经保存的资料。它与当前聊天上下文、附件库是不同的记录：聊天里看过一份文件，不代表已经把文件全文收藏到记忆中。

本文说明当前实现的用法；具体入口是否可用，以所安装版本和已启用的配置为准。

## 什么会被记住

启用记忆后，主人的真实对话输入会进入记忆处理。主助手直接委派的队友完成报告也可作为资料归档；报告仍是队友提供的信息，不会因此变成主人亲自确认的事实、偏好或执行授权。

记忆可以包含几类内容：

- 对话和工作经历，帮助找回当时发生的事情。
- 有来源的事实、实体与关系，帮助查询相关资料。
- 主人表达的身份和偏好，帮助保持称呼与交流习惯。
- 操作经验和步骤，供以后参考。

模型整理出的内容可能有误。队友报告、附件正文、网页资料中的“我喜欢……”或命令文字，不会仅因为被保存就取得主人的身份或权限。记住一项任务也不会解除暂停、替代审批或自动重做操作。

## 先保存，再后台整理

原始资料先保存，随后在后台提炼事实、建立关系，并按配置生成向量。聊天不需要等待整批整理完成。

长来源会在后台[按原文分块](memory-chunks.md)，让后半段也参与检索；关闭自动事实提炼时仍可保留这些原文块。分块设置可通过对话调整，不需要另建数据库。

你可以继续向沐璃提问；后台尚未整理好的资料可能暂时无法通过语义查询找到。明确收藏资料的整理最终失败时，可由沐璃空闲时说明并给出准确来源，见[来源与失败提醒](memory-sources.md#状态与翻页)。任务较多、服务不可用或处理失败时，仍应查看具体来源，不要把“已登记”当成“已完成整理”。

记忆保存在本机。若启用了提炼模型、embedding 或 reranker，相应正文或查询会发往你配置的服务；“本地保存”不代表这些网络处理也在本机完成。

## 自动带入与主动查询

**自动带入**用于日常对话。沐璃会从已有记忆中选择与当前输入相关的内容，并在上下文容量允许时带入。它不会在每轮对话里重新调用 embedding 或 reranker，也不会把全部历史塞进模型。

完整的当前输入、工具回执、任务与技能说明优先占用上下文，自动记忆随剩余容量收缩。能容纳时保留完整的来源与身份信息，必要时节选正文或暂时省略整条资料；后续容量允许时自动恢复。本轮没有带入不代表资料没有保存，可以继续请沐璃主动查询。

已有任务绑定的队友可在当前查询没有召回资料时，利用冻结的任务说明补找背景；当前问题优先。补充记忆只是参考资料，不增加队友权限。

**主动查询**用于明确查找。你可以说：

- “找一下之前记录的这个项目为什么延期。”
- “这条结论来自哪里？把原文找出来。”
- “比较这两条记忆，看看有没有矛盾。”

沐璃可以通过 `memory_query` 查询，再用 `memory_source` 读取实际返回的来源。长原文需要继续翻页；结果中的引文只证明来源里出现过这段话，不保证模型据此作出的判断正确。

只想查某份资料时，可以说“只在这份资料里找备份步骤”。沐璃可按准确的来源 ID 限定查询；网页的“记忆 → 来源”也有“在此来源内查找”，可随时切回全库。文字、关系和已配置的语义检索都遵守这个范围；没有匹配不会转去其它来源找答案。限定查询不改变日常自动带入的记忆选择。

不知道关键词或来源 ID 时，可以说“列出最近保存的资料”或“找出整理失败的来源”。主助手和队友都可查看[来源目录](memory-sources.md)，再按需读取原文；列目录本身不读取正文或调用模型。主人可以在网页确认重试某份失败资料，或明确请主助手按原文版本重试；不会重新执行已完成或正在处理的作业。

## 收藏附件正文

上传、预览或读取附件不会自动收藏全文。网页可从“附件”选择准确文件，核对范围与预览后确认“收藏到长期记忆”；也可以明确说：“把这份附件收藏到长期记忆。”主助手使用 `memory_import_attachment(id)` 登记准确的附件。两种入口都保存完整的受支持正文，再交后台整理，不把排队当成完成；流程与范围见[收藏附件](attachment-memory.md)。

此入口接受完整的 UTF-8 普通文本，以及经核验版本的 PDF、DOCX 提取正文；阅读范围见[文档阅读](document-reading.md)。文件过大、编码不符或版本变化时会拒绝，不把节选冒充全文。录音转写与视觉解释不通过这里混作原文件正文。

已有完整 ASR 转写可以由主人明确要求收藏，主助手用 `memory_import_transcript` 传转写工件 ID 和准确摘要。它复用原有分块、关系、来源查询和遗忘，不重复转写。所有引用、核查和资料回访都保留“ASR 转写文本”的身份；只证明宿主保存的文字，不证明原音频、说话者身份或转写准确性。未保存的网页语音草稿、视觉解释不会因此开放收藏，见[收藏已有完整转写](attachment-memory.md#收藏已有完整转写)。

已通过 `web_capture` 留存的完整网页，可明确指定快照 ID 和摘要，用 `memory_import_webpage` 收藏。它只核验本地快照，不再联网；网址、宿主采集时间和静态文本范围随完整原文保留。捕获、阅读、书签和摘录都不自动收藏，网页也不会取得主人身份或指令权限，见[收藏已捕获网页](attachment-memory.md#收藏已捕获网页)。

同一附件重复收藏不会另建一份来源。保存后可以按正文主题查询，再核对原文；文件名不需要包含查询词。附件中的内容作为外部资料处理，不会自动修改主人的人格、偏好或授权。

删除附件文件与忘记已经收藏的来源是两件事。想清除记忆中的副本，需要另行执行遗忘。

## 留意之后收藏的资料

你可以说：“帮我持续留意传送带什么时候用功能关系，以后收藏的笔记里有线索就告诉我。”沐璃会登记问题和需要同时出现的短语；也可以随时请她列出或取消关注。

在网页打开 **记忆 → 长期留意**，可以直接查看已登记的问题、约定短语和当前状态。查看和停止均不调用模型或向渠道发送消息。列表中的“默认 Web”“登记时 Web”或“登记时渠道”只说明保存的来源偏好，不代表消息已经送达。想结束某条约定时，在该条记录上点击“停止留意”，核对问题后确认；停止后保留记录，其它登记不受影响。

问题内容较长时，清单会自动分成多页，可点击“继续翻页”查看；它反映每次读取时的状态。单条记录过长或读取失败时会明确提示，不能据此判断没有登记。停止请求的返回不确定时，页面先读取清单核对，不会自动再发一次；核对后仍需停止的条目，要重新明确确认。关闭记忆或资料检查后仍可查看和停止已有登记；维护期间清单只读，禁用相应关注工具的策略也适用于网页管理。

登记后，明确收藏的资料每次完成后台整理，都会在本机检查原文。只有同一段引文包含全部约定短语时，才在 Web 主会话空闲时带着问题、出处和引文回访。每份资料对同一关注只提示一次，正常重开后继续留意；此前已经整理完成的旧资料不会自动补扫。登记前已收藏但尚未整理完的资料也可能提供新线索。

这是一种有明确条件的资料提醒，可能漏掉只有语义相似的内容。它不会额外调用远端 embedding、reranker 或全库扫描；原资料的整理仍遵守已配置的提炼和向量设置。引文出现不代表结论已经正确，沐璃可以继续读取原文、查询关系，再与你核对。

回访仍在 Web 主会话进行。你可以在登记时说“后续参考本次私聊告诉我”，让助手保存这次真实来源偏好；正常重开或后来换渠道输入都不改写它。省略时及旧关注仍默认 Web。

主 AI 会收到原偏好与出处，Web 文字不会自动外发。发送仍需 AI 显式调用渠道工具、核对当前渠道配置并经过原审批，原渠道不可用时不会换地址。取消关注、忘记来源或关闭记忆会使尚未处理的旧线索失效；已显示的历史保留，已明确下发并入队的消息不能因此撤回。完整身份预算与撤销边界见[技术合同](fresh-format-admission.md#长期问题关注的格式边界)。

需要启用记忆和“记忆”类注意事项。`memory_watches` 下的 `max_active`、`batch_size`、`max_quote_chars` 可通过配置调整关注数量、单批处理量和引文范围；不需要安装额外模型或服务。

来源偏好使用 `memory=4`，项目资料复核另需新的输入格式。已有资料库请按[停机升级说明](channel-ownership-format-upgrade.md)确认是否需要转换，不能只凭记忆版本判断。Linux 独立安装及符合指南精确来源与路径条件的 macOS 独立安装支持转换；Windows、其它 macOS 旧格式和托管旧库请继续使用原版本，新装不受影响。

## 核查、改错与忘记

在工作台的“记忆”页面检索条目，打开“核查”，可以查看当前内容、原始引文、来源身份和修改历史。有完整来源时，可按需继续读取原文；没有来源的条目会明确显示，不会凭一个可编辑标签补出证据。

重新连接后，可重新核查或打开条目继续阅读。重连或更换搜索词后，旧搜索和召回路径的响应不会退出当前登录或关闭正在核查的条目；当前登录失效时仍需重新登录。

想就收藏的资料继续问，可以在“记忆 → 来源”核原文后点击“带资料提问”。准确来源与版本会加入主对话的可编辑草稿，原问题和已选附件保留；检查、补充问题后再发送。加入引用不代表助手已经读过或核实原文，资料不可用时仍需重新核查。

发现错误时可以更正内容、类型、实体、关系、来源标签或置信度。来源标签只是便于辨认的说明，编辑标签不会改变原始来源身份。更正会保留历史；修改后的结论仍应重新核查，旧引文不一定能证明新正文。

也可以在 Web 或已绑定的主人私聊中说：“这条结论记反了，先找出原记录和出处，只更正这一条。”主助手会按查询得到的准确条目 ID 和版本，用 `memory_correct` 一起替换事实、偏好或步骤的结论、实体和关系，保留来源原文与原文副本。当前记录有变化时需要重新核对，不自动覆盖新版本。

默认更正操作指导只提供给已启用记忆与更正工具的主助手，队友仍按原权限查询资料。自定义完整提示词会继续替换默认提示词，追加内容与称呼设置保留。

聊天更正沿当前工具权限与审批，不增加原资料的身份或授权。正常重开和更换渠道后仍可查询更正结果；旧修订和来源级遗忘关系保留。更正不自动调用提炼或向量服务，旧向量会失效，之后可按需显式重建索引。结果不明时先核对当前记录，不直接重复更正。

<a id="自动提示中的冲突组合"></a>

互相矛盾的记忆可以分别查看证据，再明确选择如何处理，不需要让系统悄悄覆盖其中一条。自动带入的冲突资料可能经过节选，不能把它当成全部证据；需要时继续查询原文。

你也可以要求沐璃安排队友忘记资料，或在管理页面删除：

- 独立手动记忆按条目删除。
- 有共同来源的派生记忆按来源遗忘，会同时移除该来源的原文、相关事实与检索资料。确认框会说明范围。

遗忘后的同一来源不会因为消息重放或正常重开而自动恢复。之后的新对话或另一份独立资料仍可能再次提到同一件事。

遗忘生效后，后台提炼不再为这份旧资料开始新的模型请求，退避中的自动重试也会停止。已经开始的请求无法撤回，返回的旧结果不会重新写入记忆。

遗忘不删除原聊天记录、附件文件、已有导出或备份，也不代表已经清除模型服务商保存的数据。

## 可选模型与配置

只配置主模型即可使用：未完整配置的记忆提炼模型会继承主模型。设置中的几个常用选项是：

| 配置 | 用途 |
| --- | --- |
| `memory.enabled` | 开关记忆处理与自动记忆上下文，默认开启 |
| `memory.auto_extract` | 是否在后台用模型提炼资料，默认开启 |
| `models.memory_extractor` | 单独指定提炼模型；留空则继承主模型 |
| `media.embedding` | 可选的向量服务，用于语义召回 |
| `media.reranker` | 可选的重排服务，用于调整查询结果顺序 |
| `memory.context_limit` / `context_max_chars` | 控制自动带入的条目数与文字量 |

embedding 和 reranker 不继承主模型，也不是启用记忆的必填项。没有这些服务时，仍可保存来源并使用文字与关系查询；服务暂时不可用时，查询可能退回较简单的方式，不会假称已完成语义检索。

语义服务暂时失败时仍返回本地结果；服务恢复后，再次主动查询可以重新检索。自动带入不会因此自动请求或重试服务。

需要区分资料与问题的向量模型，可分别配置文档前缀、查询前缀和查询专用参数。它们只在请求向量服务时应用，不修改原文或关键词查询，设置方法见[模型与媒体服务](providers.md#向量服务的文档与查询设置)。

关闭自动提炼不等于关闭所有媒体请求：已配置的 embedding 仍可参与相关后台处理。希望停止记忆处理，应关闭记忆，并根据需要清除独立媒体服务配置。

更换 embedding 后，可以明确选择已有资料[重建语义索引](memory-reindex.md)，保留原文、事实和关系，不重新提炼；旧长资料也可在此时补齐分块。它不是改设置后自动执行的全库任务；使用前请确认所安装版本提供该入口。

模型地址、密钥、协议与媒体服务配置见[模型与媒体服务](providers.md)。
