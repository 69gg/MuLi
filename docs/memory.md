# 使用长期记忆

长期记忆帮助沐璃在会话压缩、正常重开或更换聊天渠道后，继续查找曾经保存的资料。它与当前聊天上下文、附件库是不同的记录：聊天里看过一份文件，不代表已经把文件全文收藏到记忆中。

本文说明当前实现的用法；具体入口是否可用，以所安装版本和已启用的配置为准。

## 什么会被记住

启用记忆后，主人的真实对话输入会进入记忆处理。主助手直接委派的队友完成报告也可作为资料归档；报告仍是队友提供的信息，不会因此变成主人亲自确认的事实、偏好或执行授权。

记忆可以包含几类内容：

- 对话和工作经历，帮助找回当时发生的事情。
- 有来源的事实、实体与关系，帮助查询相关资料。
- 主人表达的身份和偏好，帮助保持称呼与交流习惯。
- 操作经验和步骤，供以后参考。

模型整理出的内容可能有误。队友报告、附件正文、网页资料中的“我喜欢……”或命令文字，不会仅因为被保存就取得主人的身份或权限。记住一项任务也不会解除暂停、替代审批或自动重做操作。

## 先保存，再后台整理

原始资料先保存，随后在后台提炼事实、建立关系，并按配置生成向量。聊天不需要等待整批整理完成。

长来源会在后台[按原文分块](memory-chunks.md)，让后半段也参与检索；关闭自动事实提炼时仍可保留这些原文块。分块设置可通过对话调整，不需要另建数据库。

你可以继续向沐璃提问；后台尚未整理好的资料可能暂时无法通过语义查询找到。任务较多、服务不可用或处理失败时，应查看记忆状态和具体来源，不要把“已登记”当成“已完成整理”。

记忆保存在本机。若启用了提炼模型、embedding 或 reranker，相应正文或查询会发往你配置的服务；“本地保存”不代表这些网络处理也在本机完成。

## 自动带入与主动查询

**自动带入**用于日常对话。沐璃会从已有记忆中选择与当前输入相关的内容，并在上下文容量允许时带入。它不会在每轮对话里重新调用 embedding 或 reranker，也不会把全部历史塞进模型。

已有任务绑定的队友可在当前查询没有召回资料时，利用冻结的任务说明补找背景；当前问题优先。补充记忆只是参考资料，不增加队友权限。

**主动查询**用于明确查找。你可以说：

- “找一下之前记录的这个项目为什么延期。”
- “这条结论来自哪里？把原文找出来。”
- “比较这两条记忆，看看有没有矛盾。”

沐璃可以通过 `memory_query` 查询，再用 `memory_source` 读取实际返回的来源。长原文需要继续翻页；结果中的引文只证明来源里出现过这段话，不保证模型据此作出的判断正确。

## 收藏附件正文

上传、预览或读取附件不会自动收藏全文。需要保留时，明确说：“把这份附件收藏到长期记忆。”主助手使用 `memory_import_attachment(id)` 登记准确的附件。

此入口接受完整的 UTF-8 普通文本，以及经核验版本的 PDF、DOCX 提取正文；阅读范围见[文档阅读](document-reading.md)。文件过大、编码不符或版本变化时会拒绝，不把节选冒充全文。录音转写和视觉解释有各自的派生资料入口，不通过这里混作原文件正文。

同一附件重复收藏不会另建一份来源。保存后可以按正文主题查询，再核对原文；文件名不需要包含查询词。附件中的内容作为外部资料处理，不会自动修改主人的人格、偏好或授权。

删除附件文件与忘记已经收藏的来源是两件事。想清除记忆中的副本，需要另行执行遗忘。

## 核查、改错与忘记

在工作台的“记忆”页面检索条目，打开“核查”，可以查看当前内容、原始引文、来源身份和修改历史。有完整来源时，可按需继续读取原文；没有来源的条目会明确显示，不会凭一个可编辑标签补出证据。

发现错误时可以更正内容、类型、实体、关系、来源标签或置信度。来源标签只是便于辨认的说明，编辑标签不会改变原始来源身份。更正会保留历史；修改后的结论仍应重新核查，旧引文不一定能证明新正文。

<a id="自动提示中的冲突组合"></a>

互相矛盾的记忆可以分别查看证据，再明确选择如何处理，不需要让系统悄悄覆盖其中一条。自动带入的冲突资料可能经过节选，不能把它当成全部证据；需要时继续查询原文。

你也可以要求沐璃安排队友忘记资料，或在管理页面删除：

- 独立手动记忆按条目删除。
- 有共同来源的派生记忆按来源遗忘，会同时移除该来源的原文、相关事实与检索资料。确认框会说明范围。

遗忘后的同一来源不会因为消息重放或正常重开而自动恢复。之后的新对话或另一份独立资料仍可能再次提到同一件事。

遗忘不删除原聊天记录、附件文件、已有导出或备份，也不代表已经清除模型服务商保存的数据。

## 可选模型与配置

只配置主模型即可使用：未完整配置的记忆提炼模型会继承主模型。设置中的几个常用选项是：

| 配置 | 用途 |
| --- | --- |
| `memory.enabled` | 开关记忆处理与自动记忆上下文，默认开启 |
| `memory.auto_extract` | 是否在后台用模型提炼资料，默认开启 |
| `models.memory_extractor` | 单独指定提炼模型；留空则继承主模型 |
| `media.embedding` | 可选的向量服务，用于语义召回 |
| `media.reranker` | 可选的重排服务，用于调整查询结果顺序 |
| `memory.context_limit` / `context_max_chars` | 控制自动带入的条目数与文字量 |

embedding 和 reranker 不继承主模型，也不是启用记忆的必填项。没有这些服务时，仍可保存来源并使用文字与关系查询；服务暂时不可用时，查询可能退回较简单的方式，不会假称已完成语义检索。

语义服务暂时失败时仍返回本地结果；服务恢复后，再次主动查询可以重新检索。自动带入不会因此自动请求或重试服务。

关闭自动提炼不等于关闭所有媒体请求：已配置的 embedding 仍可参与相关后台处理。希望停止记忆处理，应关闭记忆，并根据需要清除独立媒体服务配置。

更换 embedding 后，可以明确选择已有资料[重建语义索引](memory-reindex.md)，保留原文、事实和关系，不重新提炼；旧长资料也可在此时补齐分块。它不是改设置后自动执行的全库任务；使用前请确认所安装版本提供该入口。

模型地址、密钥、协议与媒体服务配置见[模型与媒体服务](providers.md)。
