# 活跃任务期间发布 Skills

本片只放宽自主目录发现的 Skills 更新，不替换正在执行的 MCP 工具、不取消任务，也不增加设置或持久账本。现有 Runtime 在准备请求时已物化消息；Skills 的上下文装饰和激活操作没有内部等待，可以在自然请求边界使用新的不可变目录。

本文的 Skills-only 合同继续有效；2.33 的完整扩展发布另按 [MCP 活跃换代](mcp-live-generation-design.md)实现，不再等待所有任务空闲。以下历史验证仍指 2.25，不作为 2.33 的新增检查计数。

## 发布合同

`Extensions` 只在完整扩展发布成功后保留一份内存基线：当时的 MCP 配置、Skills 设置、扩展预算、MCP 输出预算和实际 MCP 来源指纹。首次加载存在错误，或后续完整候选失败时，不具备 Skills-only 资格。MCP、Skills 设置、预算或混合目录变化，以及手动重载、catalog refresh，必须使用完整候选。2.33 允许纯扩展完整候选在任务活跃时发布；其它配置继续等待全局空闲。

watcher 在忙碌时，仅为当前自主目录请求调用 `_apply_skills_locked`。该方法在既有 `configuration_lock` 和候选期限内准备完整 Skills 快照；发布前重新核验实际配置、MCP 与 Skills 来源指纹、请求代次、目录请求归属、refresh 集合、维护门、关闭状态和 Store 格式。新的手动或 MCP 通知保留 dirty/queued，不消耗另一请求。合并队列另保留一个内存 `full_reload` 标志，只有同请求的完整发布成功才能清除；后续目录发现不能把未履行的手动请求降级为 Skills-only，即使没有连接、refresh 集合为空也一样。发布没有等待点，不持久修改配置、不准备或退休 MCP 连接、不更换工具注册表。

Skills-only 成功推进扩展代次和已接受指纹，保留 MCP 来源列表，`last_apply` 明示 `scope:skills`、`mcp:unchanged`。准备失败保留已接受 Skills 与 MCP；固定错误沿用自主 watch 的去重通知和正常扫描间隔，不因忙碌循环重试同一失败候选。

`Skills.publish` 以完整 `Skill` 值相等复用未变对象，包含包目录身份。无关 Skill 更新不使正在等待文件读取的其它 Skill 误报换代；正文或包目录身份改变时仍拒绝旧读取。资源继续按读取时内容提供独立 hash，不增加递归扫描或包级历史快照。

## 请求与活跃指导

已发送或正在准备完成的请求保留其已物化正文。发布后对旧修订的 `skill_read` 仍返回 `skill_changed`；下一次 Skills 上下文装饰按现有合同清除被观察到的变更/删除激活，并提示 `changed_requires_reread_or_forget`，不会自动激活新版。未变化项继续有效。没有被会话观察到的中间变化不额外扫描撤销旧激活。

## 验证边界

本节记录 2.25 的验证基线。后续 Windows 本地 NTFS 句柄实现与真实平台验收独立记录在 [Windows Skills](windows-skills-design.md)，不改变以下历史结果。

旧实现的两个反例已稳定失败：真实 Runtime 模型请求活跃时，新指导始终排队；无关 Skill 更新使资源读取误报换代。实现中还补出了手动请求先于目录发现时被错误消费的两个反例，分别覆盖有连接和无连接。

修复后新增 26 项与既有 Skills、扩展、watcher、系统错误来源回归，共 157 项通过（5.95 秒，峰值 150.3 MiB，swap 0）。所有执行均经过共享资源守卫、每次上限 30 秒，使用临时目录、离线 MCP client 和门控模型替身，没有连接真实模型或 MCP server，也没有启动子进程。用例覆盖真实已激活请求保持旧正文、旧修订读取拒绝、下一请求的新目录及失效提示，资源真实 await 的不变/变更/换目录身份，混合变化和两种通知到达顺序，最后等待点之后删除真实数据库 marker、维护/配置/关闭门，失败保旧、去重与取消。三文件 Ruff/格式和两源码严格 mypy 通过，源码检查峰值 145.7 MiB、swap 0；主 agent 与独立 reviewer 静态复核后收口。

最多持有当前 Skills 目录和一个候选；已准备请求仍持有自己必要的消息正文，不增加无期限的历史快照注册表。Windows 的安全文件读取能力没有因本片补齐；新回归在缺少既有 dir_fd/O_NOFOLLOW 能力时沿原合同跳过，真正三平台执行仍以远端矩阵为准。2.25 当时仍会因持续活动而延后 MCP、混合变更、设置变更及完整重载；2.33 对纯扩展改用独立 MCP 代次合同，没有强制打断任务或放宽维护门。
