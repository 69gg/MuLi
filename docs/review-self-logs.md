# 自身日志读取审查

状态：本地实现与独立后审查完成，尚未发行。复用 UserService 的固定日志定位、run_process 的输出/时间/取消回收，以及 file_io 的有限文件读取；只增加一个 read 风险工具，不执行配置、重启或模型请求。

独立审查发现并修复两项泄漏边界：内联旧 key 与环境新 key 同时存在时必须分别隐藏，不能按优先级只收集其中之一；文件启动器按 write 字节轮转，新文件偏移零也可能是凭据后半行，因此文件模式保守省略无法证明完整的首行。回归使用六个裸凭据和真实 BoundedLog 的有限轮转样例，不读取真实用户日志。

相关诊断、管理和服务共 40 项测试通过，Ruff、格式与源码严格类型检查通过；全部使用共享资源保护入口，最终测试峰值及耗时以本轮受限 service 记录为准。覆盖固定 unit/路径、已配置和常见认证表达脱敏、轮转/半行、读取过程中配置变更、取消传播、失败不回显异常/stderr、完整 JSON 输出预算、FIFO/符号链接拒绝及热重配后工具仍可用。

边界：Linux 通过命令替身验证，macOS/Windows 文件后端在本机临时文件上验证；未调用真实 journal、用户服务或外部模型。文件模式不能保证整个文件 I/O 的五秒墙钟期限，符号链接保护限平台提供的 O_NOFOLLOW。脱敏不识别任意编码/变换或未登记历史秘密；空结果不是健康证明。自动阈值告警、统一事件来源和主动路由见另行设计，未计为该工具已经实现的能力。
