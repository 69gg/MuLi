# 2.16 主动投递与可恢复管理迭代

状态：开发中。版本范围以完成的产品接线、独立复审和验证为准，设计文档及基础模块不计作已经可用的服务能力。本轮不修改用户服务、真实账号或模型配置。

## 管理事务基础

纯 journal 和可注入 backend 的单步控制器已签名接入，复用已审的[分片设计](restart-transaction-v2.15-design.md)。固定 inode 的 journal 锁与 writer lease、持久化屏障、精确配置快照、同代 CAS、截止期限、一次回退和健康／放行证明均由临时文件与 fake backend 验证。

独立审查修正了目录同步失败后继续执行、旧实例归属、等待后的期限复核、回退实例放行以及错误标记与放行证明冲突时的优先级。首片作者与复审确认的 60 项定向覆盖，在合入 2.15 产品基线后再次通过，0.23 秒；2 份源码严格类型检查通过。该次共用 cgroup 守卫的 service 时间为 1.073 秒、峰值 121.5 MiB、swap 0。

当前没有真实服务 backend、恢复 CLI 或完整维护门接线。上述测试不证明真实服务能自动恢复、不证明停机时长，也不包含 A/B 安装、下载或数据库回滚。继续实施执行准入、排空、被动启动与同代健康确认，再连接现有管理入口。
