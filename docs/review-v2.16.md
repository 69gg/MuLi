宿主为新提醒、管理计划捕获原请求来源；只有启动时自主更新检查可以声明独立事项并选择默认渠道。选路与原记录、事件一起保存，默认改动不重定向旧事项。Attention 分批校验证据，在完整终答后由既有出站账本发送；逐段重验授权，撤销后 blocked，未知发送保留原确认门。设置页与 agent 使用相同的完整配置校验，地址更改与明确暂停可一起保存。

独立复审覆盖配置完整值替换、请求来源与只读系统身份隔离、跨来源批次、最终回复提交、QQ 已发送分段、撤销与失败恢复。补上实际设置表单在“更换地址但继续暂停”时遗漏 false 的问题，以真实收集/补丁链路两例回归。切片共 218 项 Python、19 项前端检查通过；14 个产品源码严格类型及相关 Ruff/格式通过，最高峰值 160.4 MiB、swap 0。

验证使用临时数据、假 HTTP/模型，不连接真实渠道账号、不启动用户服务。配置合法与入队成功不等于平台已经允许或送达；QQ/iLink 的实际主动发送能力仍受平台限制。系统日志、旧记录和未知来源保持本地，不以“没有来源”推断可外发。

## 2.15 失败复验的根因与修复

2.15 的最终 PR CI 八项成功，但签名标签的独立发布复验在 Ubuntu / Python 3.12 和 Windows / Python 3.12 失败，上传被阻止，见 [Release 39462552531](https://github.com/69gg/MuLi/actions/runs/39462552531)。没有移动标签或通过重复运行掩盖失败。

语音测试错误地假定不同投递记录按入队顺序发送；实际 outbox 使用 `(created_at, id)` 排序，时间戳相同时 ID 可以逆序。将时钟固定并给两个相反的 ID 排序，修复前在本机稳定复现与 Windows 相同的失败，峰值 65 MiB。修复后严格核对三项请求、同一语音投递内部文字先于语音、各自 multipart 内容，同时覆盖两个顺序，不改变产品调度或增加 FIFO 承诺。

Linux 子进程已消失时，打开 `/proc/<pid>/stat` 与读取之间可能抛出 `ProcessLookupError`（ESRCH）。仅将它与原 `FileNotFoundError` 一起视为已退出，其它系统错误仍失败；原真实子进程、有限等待及僵尸检查保留，没有放宽超时或增加 skip。相关语音、渠道及安全用例共 83 项通过，0.70 秒，service 1.355 秒、峰值 78.8 MiB、swap 0。独立只读复审无阻断。
