2.24.0 已完成精确候选、main 与发行验证，并发布至 PyPI 和 GitHub。

## 完整语音转写

原 `audio_transcribe` 一次调用后，把完整 UTF-8 结果保存到现有私有附件库，
保留原音频 ID 与短结果 `text`。长结果返回有界预览、工件 ID、内容版本和
字节游标，新增 `audio_transcript_read` 续读；不再依赖重新付费转写找回全文。
复用附件配额、文件保存和证据分页，不增加独立资料库或配置项。

独立审查发现保存等待期间热缩限额，可能返回当前无法继续读取的成功引用。
修复在保存引用登记后再次核验当前限额，明确 `asr_completed` 及失败原因，
保留已经保存的工件，不删除或自动重调 ASR。取消也强持拥有的文件操作，
等待收尾后传播，不宣称可以撤销上游已经处理的请求。

实现与边界详见[完整转写工件](voice-transcripts-design.md)。原附件列表保持
最近一批协议，旧转写的查找由新增的独立检索入口承担，见下文。

## 扩展监听器存活

独立 agent 先复现维护状态读取异常会结束监听任务，再修复整轮观察的异常边界。
失败保留旧代与原 dirty 状态，等待原扫描间隔；不会把已经消费的候选补成自动
重试。通知本身抛错时记录固定状态，不递归通知或重试未知投递。`running` 反映
实际任务存活，显式 `start()` 可收集已结束任务的异常并重建；`wake/reload`
保持原生命周期，关闭后不重启，取消继续传播。

作者新增 14 项、既有扩展/系统错误来源/MCP 93 项通过，最高峰值 143.2 MiB、
swap 0；两处 Python Ruff/格式与扩展源码严格 mypy 通过。两位独立审查者未发现
剩余 P1/P2，已整合为 `c8447a2`。所有新用例拒绝实际网络和子进程；不表示已
验证用户的真实 MCP 服务。

## 附件检索

`attachment_search` 按精确来源与文件名字面包含查询，使用既有主键按 ID
单调续页；每次处理至多 200 条，另读一条判断后续范围，不新增表、索引或配置。
完整元数据与最终 JSON 都有界，无法容纳的条目不越过；空页仍可有下一游标。
这是实时目录，不能把 `has_more` 当作还有匹配结果，也不宣称文件实际存在。
使用方法和限制见[附件检索](attachment-search.md)。

作者新增 37 项、既有四文件 98 项通过，峰值 159.8 MiB、swap 0；三源码严格
mypy 与四 Python Ruff/格式通过，两位独立审查者未发现剩余 P1/P2。以固定 ID
构造真实保存后回执丢失、200 多条元数据、重开续读，证明找回不依赖再次请求
ASR；测试只调用一次 MockTransport。已整合为 `d8ff3ec`。
