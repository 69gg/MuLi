# 2.24 语音资料与后台连续性审查

这是开发验收记录，尚未发布 2.24.0。2.23 的发行检查独立进行，不能用其
CI 或标签证明本分支通过。

## 完整语音转写

原 `audio_transcribe` 一次调用后，把完整 UTF-8 结果保存到现有私有附件库，
保留原音频 ID 与短结果 `text`。长结果返回有界预览、工件 ID、内容版本和
字节游标，新增 `audio_transcript_read` 续读；不再依赖重新付费转写找回全文。
复用附件配额、文件保存和证据分页，不增加独立资料库或配置项。

独立审查发现保存等待期间热缩限额，可能返回当前无法继续读取的成功引用。
修复在保存引用登记后再次核验当前限额，明确 `asr_completed` 及失败原因，
保留已经保存的工件，不删除或自动重调 ASR。取消也强持拥有的文件操作，
等待收尾后传播，不宣称可以撤销上游已经处理的请求。

实现与边界详见[完整转写工件](voice-transcripts-design.md)。原附件列表目前
只能返回最新一批；长期库中旧转写的可发现性仍在单独设计，不视为已解决。

## 已有证据

- 作者临时 Store 与 HTTP MockTransport 新增 24 项，以及既有媒体、网页语音、
  本地工具和上传 109 项通过；独立审查无剩余 P1/P2。
- 整合到 `86b093d` 后，同一 133 项通过，耗时 2.52 秒，守卫峰值
  219.1 MiB、swap 0。这与作者组为同一批测试，不能累加。
- 作者两处源码严格 mypy、三处 Python Ruff/格式通过；整合分支的完整静态、
  跨平台 CI 与发行验收仍待执行。

检查串行使用 `muli-checks.slice`，2 GiB 合计、单次 1 GiB、swap 0、一个 CPU，
单组期限 30 秒。没有真实 ASR、麦克风或大音频，没有下载模型或大型依赖。
本机假传输的成功不代表真实模型服务或全平台行为已经验收。
