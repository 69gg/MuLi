# MuLi 运行架构

MuLi 是服务于单个电脑用户的本地数字生命助手。界面保留十八岁少女的亲切气质，不模拟恋爱关系。所有执行能力通过同一个权限入口，模型只提出行动，运行时决定是否执行。

## 实现选择

- Python 3.12+、FastAPI、HTTPX、SQLite；不加载本地模型、向量数据库或 LangChain。
- 原生 HTML/CSS/JavaScript 工作台，无 Node 构建链。青瓷蓝、墨青文字、简洁会话布局；状态按需展开。
- `providers` 负责 Chat Completions / Responses / Anthropic 协议与原生工具回放。
- `runtime` 负责会话、流式输出、取消、预算、独立审查；`conversation` 维护持续主身份收件队列，`team` 管理持久队友与邮箱，`workflows` 执行显式 DAG。
- `task_control` 在已有工作账本上保存主人暂停、追加要求和主助手确认方案的事实；SQLite 短事务同时提交修订、回执与通知意图。模型请求携带完整说明的固定快照，运行器在进入工具处理函数前核对执行版本，团队生命周期负责暂停和有证据的续办。
- `compaction` 后台生成和验证分层摘要，`context` 以确定性节选和完整轮次淘汰整理最终请求；原生协议数据与持久历史不改写。后台摘要和记忆提炼不占前台模型执行额度，各自保持有界队列和单请求并发。
- `tools` 显式注册工具；文件系统、搜索、个人记忆、无障碍电脑操作共用权限门。
- `store` 使用 SQLite 保存消息、事件、审批、通知、运行和记忆；图关系与来源共同检索，不引入多用户隔离的复杂度。
- `memory_pipeline` 独立处理原文提炼、向量、社区与查询缓存；原文、证据、冲突和来源级遗忘由 `memory` 管理。`attachments` 保存上传与生成文件，内容仅按需读取；`local_services` 提供统一文件引用和未完成工作账本。
- `channels` 负责平台协议、身份绑定、附件和持久投递，`channel_application` 在配置锁内重新验证入站授权；主回复固定使用当前轮的明确路由。
- `personal_io` 组合可选截图、录屏、声学桥接及附件；`management` 在空闲边界应用校验过的自身配置或经批准的更新；`plugins` 从用户目录加载显式信任的扩展。
- `integrations.chiliarch` 使用真实 agent 配对、SSE、消息与 ACK 协议；收到事件先事务持久化再 ACK。空闲时不调用模型。
- `reminders` 等待最近到期时间或配置变更事件，通知和下一次触发在同一事务内保存；`tools.mcp` 仅在显式启用后连接扩展。
- `attention` 只消费有持久证据的提醒、维护终态与新版事件，等待活动主任务结束后把游标、去重凭据和主会话入站原子提交。系统资料使用独立只读回合，不继承 owner 权限或历史渠道；消费者等待事件变化，关闭不会取消正在观察的主任务，并先于 Runtime/Store 退出。
- 后台服务分别使用 systemd 用户服务、macOS LaunchAgent 或 Windows 无窗口计划任务。AT-SPI 通过 Linux 系统 Python 的 GI/Atspi 调用，避免在虚拟环境编译 GTK；其他桌面系统的无障碍操作后端尚未实现，按平台报告真实能力。

无障碍读取分为有界应用/窗口发现与定向快照。宿主持有带有效期的原生定位信息，仅向模型返回当前临时标识；helper 在每次读取或动作前复核身份。工作量、省略原因与最终 JSON 大小分别核算，新快照失败也不会复活旧操作凭据。Linux 保持单次 helper；macOS AX 需要保留原生对象，因此使用仅归属于一个 session/run 的短期 helper。一次动作、到期或准确执行的终态回收全部引用，配置重载先完成旧对象关闭。协议只允许一个在途命令，发送动作帧前重验捕获的任务控制与新输入；不创建桌面轮询服务。见[电脑操作合同](computer.md)。

## 执行边界

`ask` 每个工具调用请求用户批准；`auto` 使用独立、无工具的模型上下文审查，风险操作和审查失败交给用户；`yolo` 自动执行已启用工具。三种模式都遵守输出和运行预算；访问根目录约束文件工具，shell 与桌面操作拥有当前用户权限，不是文件系统沙箱。子 agent 继承模式，不得自行提权。审批绑定工具参数及运行，不可重放到别的请求。

工作流是有限 DAG：节点依赖、并行上限、角色模型、每步工具预算和总时限。失败只影响依赖链，取消向下传播；重启后中断的运行标记中断，不自动重复有副作用的动作。模型可创建工作流；运行中不允许无界递归开队伍。

模型发起的子工作流绑定父运行。父 agent 释放共享执行名额后等待子结果，避免单并行名额下互相等待；父取消向下传播。主会话和工作流入口分别限制未完成任务数量，共享实际模型执行的并行上限。配置更新与新运行登记由同一把锁串行化，防止新配置与旧工具混用。

主人可从任务详情暂停一个账本所绑定的全部团队成员。已进入处理函数的操作允许收尾；尚未进入的旧副作用调用被拒绝，原生工具调用与结果仍完整配对。纯暂停不请求模型，也不能由模型自行解除。主人明确交主助手重新规划后，主助手须读取完整说明，在后续请求的固定快照上确认方案，再向指定未完成队友投递持久通知。通知记录证明送达，不等同于任务执行成功。活动 DAG 暂不支持中途暂停，相关请求原子拒绝，需先停止或等待结束；详见[任务控制合同](task-control.md)和[管理接口](task-control-api.md)。
