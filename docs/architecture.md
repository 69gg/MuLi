# MuLi 运行架构

MuLi 是服务于单个电脑用户的本地数字生命助手。界面保留十八岁少女的亲切气质，不模拟恋爱关系。所有执行能力通过同一个权限入口，模型只提出行动，运行时决定是否执行。

## 实现选择

- Python 3.12+、FastAPI、HTTPX、SQLite；不加载本地模型、向量数据库或 LangChain。
- 原生 HTML/CSS/JavaScript 工作台，无 Node 构建链。青瓷蓝、墨青文字、简洁会话布局；状态按需展开。
- `providers` 负责 Chat Completions / Responses / Anthropic 协议与原生工具回放。
- `runtime` 负责会话、流式输出、取消、预算、独立审查和自动工作流。
- `tools` 显式注册工具；文件系统、搜索、个人记忆、无障碍电脑操作共用权限门。
- `store` 使用 SQLite 保存消息、事件、审批、通知、运行和记忆；图关系与来源共同检索，不引入多用户隔离的复杂度。
- `integrations.chiliarch` 使用真实 agent 配对、SSE、消息与 ACK 协议；收到事件先事务持久化再 ACK。空闲时不调用模型。
- Linux 使用 systemd 用户服务；AT-SPI 通过系统 Python 的 GI/Atspi 调用，避免在虚拟环境编译 GTK。其他系统准确报告可用能力。

## 执行边界

`ask` 每个工具调用请求用户批准；`auto` 使用独立、无工具的模型上下文审查，风险操作和审查失败交给用户；`yolo` 自动执行已启用工具。三种模式都遵守输出和运行预算；访问根目录约束文件工具，shell 与桌面操作拥有当前用户权限，不是文件系统沙箱。子 agent 继承模式，不得自行提权。审批绑定工具参数及运行，不可重放到别的请求。

工作流是有限 DAG：节点依赖、并行上限、角色模型、每步工具预算和总时限。失败只影响依赖链，取消向下传播；重启后中断的运行标记中断，不自动重复有副作用的动作。模型可创建工作流；运行中不允许无界递归开队伍。
