# 本地检查资源隔离验收

2026-10-20：前端连接生命周期改动尚未同步测试环境，旧测试进入失败断言。无资源隔离的前端全量测试期间，宿主机发生全局 OOM。此后本地验证统一移入独立 systemd 用户服务，共用受限 slice；不通过重新耗尽宿主机来验证。

启动前在服务内部读取真实 cgroup v2 文件，确认每次内存 1 GiB、共享合计 2 GiB、swap 0、共享单逻辑 CPU 等效时间及任务数上限。运行期限 180 秒，终止宽限 2 秒；Node 堆额外限制 256 MiB，前端文件单并发，禁止 core dump。

实际证据：

- 空命令通过内核限额核验，峰值约 9.8 MiB。1 秒期限的父子进程测试被终止，随后 `/proc` 和 service 列表确认自有子进程已消失。
- 同一可疑前端单用例在保护内约 0.64 秒达到 1 GiB，被局部 cgroup OOM 回收，swap 0，未升级为宿主机全局 OOM。修复测试连接初始化和循环 DOM 身份断言后，该用例通过，峰值约 43.4 MiB。
- 修复后的现有 221 项前端测试通过，峰值约 93.3 MiB、swap 0；该数字不包括后续新增的订阅专项回归。
- 独立审查发现 systemd 把部分终止信号视为正常退出，已保留轻量 supervisor 将负返回码映射为失败。目标自发 SIGTERM 的实测返回 143。
- 17 项无服务单元回归通过，覆盖内存/swap/CPU/任务数与整组 OOM 配置缺失、前端并发与期限、guard 拒绝后不执行目标、正常/非零/信号退出、取消只清理自身 service、回收未确认时失败、平台不支持时拒绝运行。Ruff 与入口严格 mypy 通过。

这些是开发执行边界，不是恶意代码沙箱，也不证明产品每个模块均已限制总内存。Linux 本地入口与远端托管跨平台 CI 分别记录；没有安装新库或模型、使用真实用户数据或进行负载测试。
