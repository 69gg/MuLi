2026-10-24。v2.44候选已完成生产实现、完整后端、静态检查、多轮独立后审修复及离线构件验证，元数据已统一为2.44.0；尚未远端CI或发行。不能据版本号认定已发布；先前发行与原生验证也不由本片离线绿色替代。

## 问题与最终行为

现有分层记忆已经支持可信来源、逐字引文、关系、别名、冲突检测、显式选择、修订和遗忘。本片只改善自动提示中的证据选材：以前即使知道某事实有冲突，也可能只给模型这一方正文和另一方 ID。

现在普通记忆页形状不变。未解决冲突使用 `type=conflict` 组合：可容纳双方完整定位及可读正文片段时为 `paired`，双方各占一个原名额；不能共同呈现时为 `pending`，占一个名额，仅保留当前有效 seed 定位和记忆 revision，不交付单侧正文。连提示都放不下时整体省略。

组合是不可拆的选材单元。召回与侧写同 seed 只点查一次，pair 与已选成员有交集时整体降级，不删去一方来伪造完整组合，也不重复正文耗尽名额。两名额且可行时保留 pending 与独立侧写；原同 ID 覆盖两流的规则保留，不保证额外保留无关侧写。

组合始终 `partial=true`，含义是仅核验本组、未证明列全；对方增量页只保留已验证的对方 ID，标 `conflicts_partial=true`。即使真实只有两项也不宣称完整，解决三方中的一组不保证其它冲突已消失。没有自动解决、重试、删除记忆或权限提升。

## 成本、来源与兼容

两流各取至多 `L=min(context_limit,max_candidates)` 个 seed，按 ID 共享复核，新增组合查询总量不超过 `2L`；失败占额度，不触发补扫。每次查询最多读取当前 seed 和第一项登记对方，关系按排序的 `(left_id,right_id)` UNIQUE 键核对；不做无索引 OR 枚举，不展开对方的全部关系或冲突，不取 source 全文。

元数据先经 SQL 字节门，正文只取 SQL BLOB 窗口，在 Python 严格解码。时间戳保持原 SQLite 数值精度。真实来源关联、同槽位、分层、信任、状态和版本重新核对；当前未解决关系与 active 状态矛盾时整体省略。旧缓存中的 seed 已遗忘时不能产生携带旧来源的 pending。`source_id=None` 的旧手工记忆继续按原信任可读，不因组合升级主人身份。

流水线和 Runtime fallback 共用渲染。原显式查询、来源分页、冲突管理、普通提供器接口、后台 worker 及 revision 语义保留；没有新增工具、网络、配置字段、SQLite 表或格式。旧 `Memory.get` 的完整关系/冲突列表读取及既有召回总成本未因本片获得相同有界证明，不声称任意历史或任意大 JSON 恒定 I/O。
