# 2.22 Linux 本地保留安装切换

状态：候选已完成下述本地验证，尚未发布；远端精确提交、CI 与发行证据待实际完成后补充。

本版把 protocol 2 类型、同一 journal 的严格分派、共享控制引擎、稳定 launcher、真实启动准入和 Linux 后端接到公开管理入口。`self_adopt` 迁入当前完整保留安装，`self_switch` 经真实用户批准后切换到另一个已存在的兼容安装。配置与重启沿用同一恢复机制，`self_recover` 和已认证 API 可接续当前代。候选下载、环境创建、跨格式迁移与 macOS/Windows 同等切换不属于本次交付；详细输入与边界见[操作合同](managed-operations.md)。

固定控制安装不依赖 selector 选中候选才能恢复。配置、selector、unit、实际运行安装和健康证明分别核验，不能用配置相同代替程序已经切换。目标拒绝后回到旧程序仍打开原数据库，保留 prepare 之后的最新消息和未知投递，不还原旧数据库副本。终态结果与原始回复来源原子记录，观察重试不再写一份完成事件。

独立审查重点覆盖写入状态后丢失返回、单次授权确认、生命周期所有权、监听漂移和发布声明。legacy 回桥的逻辑 permit 保留原 writer owner；新锁确认必须与同一次 PendingLegacy、实际 Store、原回执和持久代次完全一致。prepared 后 helper 错误或取消仍保留原计划和 generation。HTTP 恢复持配置锁，关闭等待已进入请求，关闭后排队请求拒绝，避免恢复读取已关闭 Store。

监听 host/port 不再尝试热迁移 socket。模型配置和网页保存完整补丁进入重启事务，当前或候选控制地址不受支持时提前拒绝。网页仅显示“已排队，空闲后重启”，保留未应用草稿及等待期间新输入；普通热保存不变，Chiliarch 配对不会夹带监听更改。真实回归验证旧、新端口快照和最后一次进程观察后的配置漂移。

本地整合回归串行经过同一资源守卫，每次 30 秒、单次 1 GiB、共享 2 GiB/1 CPU、swap 0。完整后端套件仍由远端矩阵执行，下表是本轮明确执行的相关组，互不累加早期重复复验：

合计 1,253 项相关后端回归；完整前端 277 项通过（service 2.504 秒、92.5 MiB）。最初两次后端大批次触及 30 秒限制被守卫终止，没有 OOM；按已有模块文档拆分后全部通过，没有提高限额或将终止算作通过。

全仓 Ruff、276 文件格式检查以及 118 源码文件的无缓存严格 mypy 均通过；mypy 峰值 389.6 MiB、service 7.595 秒，swap 0。83 包离线锁一致性、全新临时目录的 wheel/sdist 离线构建、源码树外临时安装 smoke 及发行校验通过。构建、安装 smoke 分别为 61.5/92.2 MiB；没有下载依赖或覆盖用户安装。

实际安装 smoke 验证包内兼容声明、运行版本、七领域格式、网页与 API 文档、提示词、默认关闭的桌面能力、任务控制及 lifespan。发行校验要求源码、wheel、sdist 的声明和版本文件完全一致，沿用 CI 的一次构建产物，不在发布时另造未经检查的包。本地产物只用于验证，正式发布将使用对应远端 CI 构件。

[真实进程验收](managed-process-recovery.md)使用临时保留安装、真实稳定入口同 PID exec、实际 CLI/bootstrap/Runtime、nonce HTTP、SQLite WAL/FULL 与 writer lease；systemd 命令、loaded unit/proc 归属和 cgroup 为合成边界。测试从原服务已停止的持久安装阶段开始，不代表真实用户服务、原实例 drain、完整依赖环境、断电或真实外部渠道已验证。原数据库最新输入、主身份、原 routing 和 unknown 状态均有保留断言。
