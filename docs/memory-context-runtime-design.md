# 模型请求中的自动记忆

自动记忆是当前任务的补充背景。它与显式查询、已保存原文和后台整理共用现有记忆服务，不另建存储或增加每轮远端请求。使用方法见[长期记忆](memory.md)。

## 选择时机与容量

Runtime 先准备会话历史，运行扩展上下文回调，再加入冻结任务说明和技能指导。这些步骤完成后，才选择本轮自动记忆。主助手、队友和工作流节点共用这一路径；只读咨询保留原本的独立提示范围。

宿主复用正常上下文打包的保护与节选规则，计算必要内容的最低占用。这个副本只用于计算余量，最终请求仍从原始历史打包，尽量保留能放下的旧内容。最新输入、当前待处理的完整工具结果、原生调用数据和必要说明不会为自动记忆让位。必要内容自身超限时仍报上下文不足。

资料同时受配置字符上限、原有比例上限和当轮剩余容量约束。剩余容量按 Message 文本投影的 JSON 字符数计算，包含资料消息外壳、标题、分隔符和字符串转义；它不是模型 token 数、UTF-8 字节数或供应商完整 HTTP 请求的大小。

渲染器复用完整条目、冲突成组和双流选材。先保留身份、来源和冲突信息，再节选正文；连完整元数据都放不下时省略整个单元，不截断最终 JSON。配置和存储不因此改变，下一轮会重新按容量选材。显式查询与原文分页保持原有权限、版本和输出预算。

## 插入与扩展

自动资料是宿主临时创建的独立 system 消息，放在开头连续的 system/developer 说明之后，不插在原生调用与结果之间，也不写回历史。扩展与技能回调看到的是尚未加入自动资料的必要内容，不能再依赖从第一条 system 消息中提取记忆。

具名 `MemoryContextProvider` 可显式注册支持请求预算的 `request_composer`。既有 renderer、composer 和一参数 callable 的签名保持可用；宿主只调用一次，不通过捕获 `TypeError` 猜签名。旧回调的结果整体超预算时省略，不任意切片。提供器自身的异常原样传播，不当成压缩信号重试。

已绑定任务的可选背景仍使用冻结目标，仅在当前查询没有召回资料时补位。既有 baseline 优先；任务增量只能使用最终真实余量，不重新打包挤走其他内容。扩展改写或复制原宿主说明时禁用任务补位，保留扩展内容与必要说明。

## 当前输入与来源

选材会排除仍可证明是本次最新主人输入自动归档原文副本的初始 episodic，避免重复占据相关名额。识别依赖真实消息 ID、确定性去重键和当前版本；不从相同文本猜身份。更正条目、冲突、同源提炼事实和其他来源的相同内容继续可用。

缓存与有界本地候选复用原规则，不扩大查询、关系边或条目上限。来源失效、更正、遗忘及当前开关仍在每次选材时生效。自动带入为空只说明本轮没有选入资料，不能解释为没有保存、查无结果或已经读完整个资料库。

## 验证边界

回归使用临时 SQLite、离线模型和真实 Runtime 请求边界，核对最终消息的容量、完整元数据、工具保护、恢复与异常传播。它不证明真实模型一定使用记忆、语义答案正确，或外部渠道和供应商已经联调。
