# 2.10 已保存正文归档审查

状态：实施和整合中，尚未完成验收或发布。本轮只实现已知会话的只读归档窗口及单条正文续读，全目录标题搜索与实时首屏资源改造另案处理。

并行研究与独立反证确认：持久主会话和旧记录保存超过 1000 条消息后，原详情仅返回最后 1000 条，早期原文仍能通过既有 HistoryEvidence 读取。因而本轮解决第一方界面的可达性，不把节选前已经丢失的内容描述成可恢复。另已复现目录越过最近 200 条后不可搜索，明确保留为下一片，不能用正文分页冒称解决全部目录。

设计独立审查纠正了实时回放假设：hydrate 自己拼接 delta/reasoning，依赖 completed 清除旧尾流；删除完成事件会使已完成回复重复出现。全局 SSE 首次连接仍可能从 after=0 回放。首片因此使用独立归档状态与弹窗，不修改实时链路；新增 32000 字符上限也不宣称整个启动、SSE 或内存已经有界。

数据层沿用现有消息证据投影与 UTF-8/JSON 装箱，API 复用认证和错误映射，界面独立请求归属与代次。独立 reviewer 还复现了 JavaScript 对 2^53+1 游标舍入造成漏项，HTTP 和界面将超出精确范围的序号明确拒绝，不增加另一套 BigInt 或游标框架。

核心与 HTTP 首轮整合已通过 88 项归档、正文证据和 API 回归，以及 71 个源码文件严格类型检查。覆盖主/旧会话各 1001 条实际保存记录、1000 字符预算连续读回全部记录、默认大预算的 32000 字符整页上限、NUL/emoji/HTML 原文续读、错会话和版本/删除错误、认证和 GET 前后数据库写入计数不变。这个数量仅是首轮专项，尚不代表前端与完整版本验收通过。

各项专项、实际浏览器、独立后审查及发行证据将在完成后记录；方案和局部通过不算完成。开发仅使用临时数据库和假回调，不调用真实模型、采集设备、修改用户服务或安装大型依赖。
