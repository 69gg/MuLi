# 按运行查询有限故障位置

状态：下一轮调研提案，尚未实现，不属于 2.25 的 Skills 发布能力。

## 要解决的问题

`Runtime._drive` 已记录真实运行失败、固定系统事件与有限的用户可见错误；
`self_events` 可定位运行，`self_logs` 可读取服务出口。当前私有 logger 没有
自动保存 traceback，因而有时只能知道“哪个运行失败”，不知道失败经过哪个
宿主函数。原生日志全文留存还涉及新的 writer、轮转和多进程归属，不宜作为
取得基本定位信息的前提。

建议先复用既有 `run` 终态记录保存一份小型诊断，增加按运行 ID 查询的只读
入口。它与运行同时保存、保留和删除，不另开数据库、文件、线程或日志队列。
这仍是诊断资料，不是执行回执，也不构成重做未知副作用的依据。

## 最小合同

- 只覆盖宿主已捕获的普通运行失败，不捕获正常取消或暂停，不承诺覆盖启动、
  原生进程、所有插件或所有第三方异常。系统采集关闭时不新增诊断；旧记录
  仍可查询，关闭采集不隐含删除历史。
- 在失败边界同步提取纯值，不能把异常、traceback、frame 或 logger 对象
  留到异步队列和持久对象里。提取失败不得覆盖原始运行失败或阻止收尾。
- 只保存有限异常类别和 MuLi 包内的模块、函数、行号。不得调用异常的
  `str`/`repr`、读取 locals、加载源代码、追踪 cause/context 或递归展开
  ExceptionGroup；不保存用户目录的绝对路径。外部或不满足结构约束的字段
  归为固定未知值，不把任意类名或编译文件名视为可信标签。
- 限制实际遍历帧数和完整序列化字节数，不能为了取“最后几帧”先遍历整条
  超长 traceback。明确 `truncated` 和覆盖范围，空位置不表示没有故障。
  预算的具体落点需在实现前审查，不能引入多套相互矛盾的输出限制。
- 查询显式接收规范 run ID，复用 read 权限及当前工具输出预算，保留完整
  结果交付。旧运行缺少诊断、尚未落盘、查无运行与证据损坏须区分；不能把
  缺少记录解释为运行正常，也不从最近一次失败猜测关联。
- 查询不得先把任意大的 `run.result` 或完整运行 JSON 载入 Python。需要
  在既有主键点查上给读取与解析建立实际边界；不能只在输出前截断。
- 系统事件、Attention 和渠道报告保持现有固定字段，不自动注入这份诊断，
  不增加通知、回执或自动重试。模型按需回查，再决定是否查看只读源码。

## 必须验证的边界

先使用真实临时 Runtime 的离线失败定位当前缺口，再验证保存、关闭重开与
按 ID 回查。覆盖异常自定义 `__str__`/`__repr__`、带敏感内容的局部变量与
异常消息、过长堆栈、外部帧、提取失败、关闭采集、缺失旧记录、损坏证据、
超大运行结果和完整工具输出预算。核对前后没有新增通知、Attention 游标
推进或模型请求。测试继续经过共享资源守卫，禁止真实服务和模型调用。

目前尚未确定与故障原子持久化的最小接线点：当前 `run` 最终写入位于
异步清理之后；硬退出或清理提前抛错可能使诊断未落盘。首片必须如实呈现
这个窗口，或以独立审查通过的最小事务修复它，不能承诺崩溃前必然留存。

## 已核实的接口

通过 Context7 核对 CPython：`traceback.walk_tb` 按 `tb_next` 惰性产出帧；
`StackSummary.extract(lookup_lines=False, capture_locals=False)` 不立即加载
源码或 locals，但后续格式化仍可能读取源码。因此实现应只采集需要的纯值，
不直接保存或格式化 `TracebackException`。
依据：[CPython traceback](https://docs.python.org/3/library/traceback.html)。
接口核实不代表上述诊断能力已经实现。
