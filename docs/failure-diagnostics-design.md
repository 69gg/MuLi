# 按运行查询有限故障位置

状态：实现随 2.26 整合，发行验收见[2.26 审查](review-v2.26.md)；不属于 2.25 的 Skills 发布能力。
用户入口与返回状态见[按运行查询故障位置](failure-diagnostics.md)。

## 要解决的问题

`Runtime._drive` 已记录真实运行失败、固定系统事件与有限的用户可见错误；
`self_events` 可定位运行，`self_logs` 可读取服务出口。当前私有 logger 没有
自动保存 traceback，因而有时只能知道“哪个运行失败”，不知道失败经过哪个
宿主函数。原生日志全文留存还涉及新的 writer、轮转和多进程归属，不宜作为
取得基本定位信息的前提。

实现复用既有 `run` 终态记录保存一份小型诊断，增加按运行 ID 查询的只读
入口。它与运行同时保存、保留和删除，不另开数据库、文件、线程或日志队列。
这仍是诊断资料，不是执行回执，也不构成重做未知副作用的依据。

## 最小合同

- 只覆盖宿主已捕获的普通运行失败，不捕获正常取消或暂停，不承诺覆盖启动、
  原生进程、所有插件或所有第三方异常。系统采集关闭时不新增诊断；旧记录
  仍可查询，关闭采集不隐含删除历史。
- 在失败边界同步提取纯值，不能把异常、traceback、frame 或 logger 对象
  留到异步队列和持久对象里。提取失败不得覆盖原始运行失败或阻止收尾。
- 只保存有限异常类别和 MuLi 包内的模块、函数、行号。不得调用异常的
  `str`/`repr`、读取 locals、加载源代码、追踪 cause/context 或递归展开
  ExceptionGroup；不保存用户目录的绝对路径。外部或不满足结构约束的字段
  归为固定未知值，不把任意类名或编译文件名视为可信标签。
- 限制实际遍历帧数和完整序列化字节数，不能为了取“最后几帧”先遍历整条
  超长 traceback。明确 `truncated` 和覆盖范围，空位置不表示没有故障。
  预算按下面已审的协议常量执行，不引入新的 Settings。
- 查询显式接收规范 run ID，复用 read 权限及当前工具输出预算，保留完整
  结果交付。旧运行缺少诊断、尚未落盘、查无运行与证据损坏须区分；不能把
  缺少记录解释为运行正常，也不从最近一次失败猜测关联。
- 查询不得先把任意大的 `run.result` 或完整运行 JSON 载入 Python。需要
  在既有主键点查上给读取与解析建立实际边界；不能只在输出前截断。
- 系统事件、Attention 和渠道报告保持现有固定字段，不自动注入这份诊断，
  不增加通知、回执或自动重试。模型按需回查，再决定是否查看只读源码。

## 必须验证的边界

先使用真实临时 Runtime 的离线失败定位当前缺口，再验证保存、关闭重开与
按 ID 回查。覆盖异常自定义 `__str__`/`__repr__`、带敏感内容的局部变量与
异常消息、过长堆栈、外部帧、提取失败、关闭采集、缺失旧记录、损坏证据、
超大运行结果和完整工具输出预算。核对前后没有新增通知、Attention 游标
推进或模型请求。测试继续经过共享资源守卫，禁止真实服务和模型调用。

采集位于 `Runtime._drive` 的普通失败分支，同步生成纯值后只挂入当前 `run`；
仍由原有 finally 在异步清理后保存终态，不改变原异常 reason、终态事件或
收尾时序。硬退出或清理提前抛错可能使诊断未落盘，不承诺崩溃前必然留存。
提取自身失败时丢弃可选诊断，继续原始故障和清理；取消与暂停不进入采集。

## 实现预算与数据边界

协议 v1 使用三个有类型常量：`MAX_FAILURE_FRAMES=16`、
`MAX_FAILURE_BYTES=4096`、`MAX_RUN_RECORD_BYTES=32768`。
前者限制实际访问的 traceback 帧；达到上限即保守标记 `truncated`，不为
判断是否还有一帧而继续遍历。诊断完整 UTF-8 JSON 超过 4KiB 时减少末尾
位置并标记截断。模块和限定函数名各限 128 个 ASCII 标识字符、最多四段；
不能映射的包内嵌套或动态函数与外部帧均只给固定 unknown/null。

包内位置不只信任编译文件名：按包内模块名点查 `sys.modules`，核对当前
模块字典、文件名及至多四个直接模块/类字典键，最终要求绑定函数的 code
对象相同。不会扫描模块、遍历类属性或执行自定义描述符。异常类别只识别
有限的精确内置类型，子类及第三方类型归 unknown；不展开 ExceptionGroup。
这提供受限定位提示，不是对同进程任意插件代码的安全隔离或真实性证明。

`read_failure(store, run_id, max_output_chars=...)` 复用 `_read_object` 的
`objects(kind,id)` 主键点查，SQL 返回总字节长及最多 32769 字节的哨兵窗口；
原 JSON 完整解析上限为 32KiB，超限明确返回 `run_record_over_budget`，
不会先调用 `Store.get` 或用 JSON 提取解析整份大 result。坏 JSON、未知
诊断版本及坏字段固定拒绝，不把原 `run.error`/`result` 带入响应。
合法失败的既有元数据可能超过诊断自身 4KiB，因此两个上限分别验证。

`self_failure` 是现有权限门下的 read 工具，`preserve_output=True`；完整响应
仍受当前 `limits.max_output_chars` 限制。必要时只减少诊断帧并明确截断，
不返回截坏 JSON，不修改持久原证据。过小到容不下固定封套时返回既有
`output_budget` 错误。关闭采集不禁止查询历史。

新增采集器不调用异常格式化；既有用户可见 `error` 路径仍可能对 ValueError
等调用 `str(exc)`，本片不改写该既有行为，不宣称整个错误处理路径均不格式化。

## 离线验证

新增真实临时 Runtime 最小用例在旧代码确认失败：终态可重开但无诊断，
1 failed / 0.18 秒，峰值 64.7MiB、swap 0。
实现后专用 37 项通过，0.51 秒、峰值 87.9MiB、swap 0；包括真实合法失败
元数据超过 4KiB 仍可查询，以及下一实际准备请求获得完整 JSON 的工具交付。
既有 Runtime、主请求错误来源、SystemEvents 集成、自身管理四文件共 63 项
通过，4.10 秒、峰值 107.6MiB、swap 0。三份改动源码 mypy 通过。
所有执行经每次 30 秒、1GiB / 共享 2GiB、无 swap、共享单 CPU 的守卫；
新增用例硬拦 HTTP 和子进程，仅使用临时资料库、离线模型替身。
独立静态复审通过；尚未进入正式版本或实际用户服务验收。

## 已核实的接口

通过 Context7 核对 CPython：`traceback.walk_tb` 按 `tb_next` 惰性产出帧；
`StackSummary.extract(lookup_lines=False, capture_locals=False)` 不立即加载
源码或 locals，但后续格式化仍可能读取源码。因此实现应只采集需要的纯值，
不直接保存或格式化 `TracebackException`。
依据：[CPython traceback](https://docs.python.org/3/library/traceback.html)。
接口文档与上述离线验证分别提供方法和实现证据，不替代实际服务验收。
