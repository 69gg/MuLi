# 更换语义服务后接续已有资料

v2.68 开发候选；方案与实现经过独立评审，新增16项离线回归通过，尚未正式发行。

更换 embedding 的地址、模型或维度后，旧原文、事实和关系仍在，旧向量却不会被新模型
使用。可以明确说：“为这几份已收藏资料重建当前语义索引，不要重新提炼。”计划只处理
准确选择的已有完整来源，保留事实、信任和完成历史，不在改配置或查询时自动全库重建。

## 使用合同

主助手通过 `memory_reindex(action="start", source_ids=[...], key=...)` 登记有限计划；
`action="status"` 与 `action="cancel"` 按实际计划ID查看或取消。宿主冻结当前语义模型
标识，模型不能提供地址、向量、正文或信任。开始须经过真实当前主人主工具上下文与原
write、维护及生命周期门。原来的 done 作业整行保持，不重跑提炼、改写引文或关系。

只准一个活动计划，不另排计划队列；它占原 pending 配额，来源集合及完整元数据受现有
上限约束。普通后台作业优先，重建复用唯一 worker、媒体锁、请求期限和逐项版本复核，
不新起服务或下载模型。准确重复请求返回原计划，换参数不会借同一请求键开新工作。

取消先持久撤销未完成资格；已经发出的HTTP可能收费，返回后不再写回。真实重配置观察
到不同模型后将计划持久阻断，换回原模型也不会复活。同一模型的正常关闭重开可接续原
计划，已完成前缀按实际向量核查。遗忘、更正或来源变化使旧在途结果失效；已提交向量
不回滚，不承诺HTTP收费或写入 exactly-once，也不把部分成功说成全源完成。

认证的管理API使用 `POST /api/memory/reindex`，请求与工具相同；`GET /api/memory/status`
的 `index_plan` 给出当前计划。工具的开始、查看和取消均沿实际主助手的当前主人请求、
权限与生命周期检查，不向队友或系统提醒开放写入口。管理API沿现有主人认证和配置锁。
状态返回准确计划ID、模型标识、来源完成数、实际写入数、已存在数、遗漏数与固定错误码，
不含正文、服务密钥或请求头。`done` 仍须核遗漏项并进行实际查询。

计划只接纳已有完整来源及其原 `done` 作业。来源集合不超过原 `max_pending_jobs`，完整
元数据受 `limits.max_output_chars × 4` 字节预算限制；接纳时为后续状态和计数增长预留
空间，不通过增大上限让计划进入。重建复用 `max_facts_per_source` 的单批大小，包含
事件记忆和完整尾批；每个成功向量独立提交，后续失败不会抹掉已经完成的前缀。

缩小输出预算时，若完整当前计划已不可读，默认原地配置入口在关闭旧 worker 前拒绝，
配置和在途请求保持原样。记录可读但不足以继续更新时，计划转为 `blocked/output_budget`，
保留来源、证明及真实计数，仅去掉终态不再使用的执行游标。模型更换复用同一紧凑终态，
写入前核目标预算，避免一次同时换模型和缩预算破坏工作进程。显式 `restart_transaction`
仍沿原A/B健康检查与回滚，不宣称新增相同的关闭前预验；外部手改配置使整条记录超出
新预算时仍按SQL字节门拒绝，不无界读取或声称通用数据库恢复。

## 已核缺口与首红

既有模型标识绑定 endpoint、model、维度及检索配置，向量查询只取同标识；原完成作业
仅用 `embedded=true` 标记，改配置不会重新进入处理，原 retry 也只重试失败作业。

真实前缀已完成：ASGI上传，手机7主助手明确收藏，实际 MediaService 的A服务HTTP
完成提炼及向量；用无词面重合的 `nightjar` 查询真实命中 semantic 事实。随后经认证
设置API换B，核原source、fact、Graph和done整作业不变，B确无旧事实向量。手机7真实
调用重建工具，正常主回合与原私聊sent回执完成后，准确失败于主工具目录缺失入口：
1失败0.55秒，守卫1.239秒、93.8 MiB、swap 0。不是导入错误、假来源或超时。

## 本地验证与后审

两条正式旅程使用实际ASGI、Store、Runtime、后台管线与MediaService：手机7收藏后从A
换B并明确重建；后台HTTP等待时手机8仍能完成对话，首来源提交后正常关闭，再以同库、
同主身份重开接续原计划。之后手机8通过B语义召回同一事实，分页核完整原文SHA，仅向
当前私聊8回复，Web同时可见。原来源、事实、图边、整行完成作业和提炼调用次数保持，
相同请求键重放不新增HTTP。

独立负控覆盖在途取消、遗忘和更正，模型B→C→B，真实SQLite后项写入失败保留前缀，
份额与同键参数，事件记忆加完整尾批。后审继续取得以下准确先红，再按原因窄修：

- 实际检索占用媒体锁时，等待中的重建仍会发送已遗忘或更正的正文；改为取得原锁后
  再复核来源与条目版本，失效项不发HTTP。
- 合法近限计划进入 `processing` 后元数据增长可杀死共享worker；接纳时预留有限状态、
  错误和计数空间，保持原预算。实际近限反例和前述两项先取得3失败。
- 同模型重开后缩小预算，错误状态增长会中断共享worker；受控阻断并继续普通作业。
- 配置拒绝虽回滚值却已关闭原worker；将完整记录字节预验前置，真PATCH先红后修。
- 一次同时换模型和缩预算，旧预算写出的失效记录超过新预算；模型失效与预算不足共用
  紧凑终态，并在写入前核目标预算。真PATCH先取得1失败，再通过原代完整或新代可用的断言。

首次整合还发现测试策略的无词面查询被两条重复含词主人输入挤出top3；实际库只读诊断
确认是词面回声。将最后输入改为自然的“沿用之前的不同措辞”，保留原查询、top3、同一
事实语义命中与全文SHA断言，没有增加预算或等待掩盖失败。

既有Runtime的4000字符上下文回归又捕获全局提示词增长：新增工具段即使在未注册该
工具的独立Runtime中也占据固定预算，导致文件结果的JSON路径挤掉开头正文证据。
撤回该全局段，将操作规则留在实际可用工具的描述；不改原整串头尾节选合同、不调整

合34项通过，守卫856毫秒、71.6 MiB、swap 0。
