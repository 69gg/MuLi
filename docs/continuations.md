# 查找上次工作记录

你可以在重新打开 MuLi 后询问：

> 上次队友还有哪些没完成？先查一下，不要继续执行。

沐璃会查找自己直接队友的当前记录，再按需阅读原对话、工具结果和任务说明。即使换了消息渠道，查询的解释也回复到你本次发问的地方。

## 直属队友记录

- 正在排队、运行或暂停的直接队友。
- 中断、取消或失败后仍保留的当前队友记录。
- 有记录可查时，对应的旧对话和工具结果。

记录会分页查阅。队友很多时，沐璃可能需要继续翻页；暂时没有返回条目，不一定表示已经查完。

## 主助手自己的中断运行

也可以直接问主沐璃：

> 上次你自己做到哪里？先查记录。

沐璃会查找服务恢复处理时保存的中断主运行记录，再核对最早已领取输入的位置。这只是历史起点，不表示已经读完全部要求、后续更正或工具结果。原文已变更、缺失或无法核对时，会明确说明，不能把当前消息冒充当时的原请求。

此入口只包括有恢复记录且仍为中断的主运行，不是全部旧运行或待办的完整清单。记录可能来自系统事项，不能当作主人委托；读到旧请求、状态或回执也不等于任务完成，不产生新的操作授权。

## 查看以后如何继续

查看本身不会恢复任务、批准工具、重新执行命令或发送旧成果。你可以在核查后明确要求继续某一项，沐璃再沿原任务的暂停和审批规则处理。

“中断”或“取消”不能证明某个操作没有发生。发送文件、修改内容等结果不明时，应先核对原回执和现状，避免重复操作。

工具 `conversation_read` 的 `section=continuations` 仍只查看直接队友的当前记录，不包括主助手自己的运行、工作流和更下层的队友；主助手恢复记录使用 `section=main_recovery`。核查已知任务的要求与成果，见[任务核查](task-inspection.md)；继续暂停任务，见[任务控制](task-control.md)。
