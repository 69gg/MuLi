# 2.26 故障诊断与输入预算审查

2.26.0 已正式发布。下文保留开发与修复过程，最后记录精确发行证据；
候选与发行流水线通过，main 的 macOS 3.13 另有一项测试夹具失败，不能称为
全部检查通过。2.25 的进程收尾问题已修复，不改写已发布提交或标签。

## 会话目录游标预算

静态审查发现 `SessionRecords._cursor` 在核心工具路径直接解码任意长度
游标；HTTP 自己的输入限制不能替代工具入口的边界。两条受限反例在旧实现
分别进入被禁止的 decoder，以及在当前预算已经缩小时仍接受旧的大游标。

最小修复把已验证的 `max_output_chars` 传入解析入口，在 Base64、JSON 和
目录 SQL 前检查输入长度，超限明确 `output_budget`。成功输出本来就计入
同一预算，不改游标格式、排序和过滤；恢复原预算后合法旧游标可继续使用。
独立静态复审无剩余问题，使用说明已同步。

会话目录、附件目录和团队增量等待三个文件共 137 项通过，耗时 0.99 秒，
峰值 100.2 MiB、swap 0；两文件 Ruff/格式和修改源码严格类型检查通过。
全部检查串行使用原资源守卫，单组 30 秒、单次 1 GiB、合计 2 GiB、swap 0、
一个 CPU；反例只有约 1 KiB 的输入，没有用大数据模拟内存耗尽。

## 按运行定位故障

已整合签名实现 `cd59c5a` 为 `29f7239`，接口与边界见
[诊断设计](failure-diagnostics-design.md)。实际最多访问 16 个 traceback 帧、
完整诊断不超过 4 KiB，运行原记录的主键读取最多 32 KiB；仅保留可核对的
包内位置纯值，提取失败不覆盖原异常。它复用运行记录，不新增文件 writer、
线程或采集队列。

作者先用临时真实 Runtime 复现当前失败记录没有诊断，再实施；该红例
峰值 64.7 MiB、swap 0。37 项新增回归和既有运行、系统事件来源、系统事件
运行时及管理测试已通过；独立静态审查没有剩余 P1/P2。root 整合后同五文件
共 100 项通过，耗时 4.23 秒，峰值 122.8 MiB、swap 0；包含作者用例，不重复
累计。作者三份源码类型检查与四份 Python Ruff/格式通过，全仓终检和远端
跨平台验证仍待完成。

正常取消和暂停不产生诊断，未知类型与位置保守标记，关闭采集不隐藏历史。
旧记录、超大原 JSON、损坏字段、输出缩减与真实下一模型请求均有离线回归。
保存仍在原异步清理之后；硬退出或清理失败可能缺少终态，不能据此声称具备
崩溃前落盘保证。没有真实模型、外部账号或用户服务验证。

## 恢复用例收尾期限

2.25 main 的 Ubuntu 3.13 已通过 controller 解决、两次真实 nonce 接口及
身份核验，但最终结束服务时只剩约 32ms 的操作预算。修复仅将功能证明后的
退出等待归入既有独立收尾预算；操作阶段仍使用原 20 秒，中途停止目标、
controller 等待和业务断言不放宽。两位独立审查确认范围；四项确定性回归
覆盖仅剩 32ms、操作期限已耗尽、异常退出及独立收尾超时，全部通过
（0.14 秒、59.1 MiB、swap 0）。真实 `target-rejected-rollback` 单项通过
（14.86 秒、182.4 MiB、swap 0），没有操作真实 systemd 服务。
修改测试的 Ruff/格式/严格类型通过，后续候选 CI 将核验远端各平台。

## Windows 收集兼容修复

首个固定候选 `28e6385` 的 [CI 39541798153](https://github.com/69gg/MuLi/actions/runs/39541798153)
在两个 Windows 作业收集阶段失败：新增参数装饰器读取不存在的
`signal.SIGKILL`，而模块 skip 只在后续执行阶段生效。没有用重跑隐藏此问题。
该轮八项均已终结：Ubuntu/macOS 四项、quality 与 MCP 共六项成功，两个
Windows 作业失败；已确认 2.25 的 Ubuntu 3.13 最终收尾问题在本候选通过。

最小修复将参数改为平台无关的两种退出类别，Linux 专有信号仅在测试函数体
读取，保留原 Linux 用例和失败断言。受限子进程删除该常量后导入旧代码稳定
失败（49.5 MiB），修后通过（49.1 MiB）；这只模拟缺属性边界，不声称运行了
Windows。四项 Linux 确定性回归通过（0.17 秒、63.1 MiB、swap 0），单文件
Ruff/格式及严格类型通过，独立只读复审通过。新签名提交将重新接受完整矩阵。
