# 2.26 故障诊断与输入预算审查

这是下一轮开发记录，尚未发布 2.26.0。2.25 的 Skills 候选八项 CI 已通过，
签名标签已推送并进入发行验证，本片改动不加入该固定候选。

## 会话目录游标预算

静态审查发现 `SessionRecords._cursor` 在核心工具路径直接解码任意长度
游标；HTTP 自己的输入限制不能替代工具入口的边界。两条受限反例在旧实现
分别进入被禁止的 decoder，以及在当前预算已经缩小时仍接受旧的大游标。

最小修复把已验证的 `max_output_chars` 传入解析入口，在 Base64、JSON 和
目录 SQL 前检查输入长度，超限明确 `output_budget`。成功输出本来就计入
同一预算，不改游标格式、排序和过滤；恢复原预算后合法旧游标可继续使用。
独立静态复审无剩余问题，使用说明已同步。

会话目录、附件目录和团队增量等待三个文件共 137 项通过，耗时 0.99 秒，
峰值 100.2 MiB、swap 0；两文件 Ruff/格式和修改源码严格类型检查通过。
全部检查串行使用原资源守卫，单组 30 秒、单次 1 GiB、合计 2 GiB、swap 0、
一个 CPU；反例只有约 1 KiB 的输入，没有用大数据模拟内存耗尽。

## 按运行定位故障

独立实现仍在进行，接口与边界见[诊断设计](failure-diagnostics-design.md)。
预算方案已审查：最多访问 16 个 traceback 帧、完整诊断不超过 4 KiB，
运行原记录的主键读取最多 32 KiB；仅保留可核对的包内位置纯值，提取失败
不得覆盖原异常。它复用运行记录，不新增文件 writer、线程或采集队列。

作者先用临时真实 Runtime 复现当前失败记录没有诊断，再实施；该红例
峰值 64.7 MiB、swap 0。产品测试、独立审查与最终整合尚未完成，不能将
提案或接口核对计作已交付功能。
