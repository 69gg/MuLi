# 2.37 MCP 文本模板与 Windows 按钮操作审查

状态：两片实现与独立后审完成，第二轮远端八项成功、两项失败，未发布。
Windows 修正已通过两个 Python 版本。新增计时写入了严格 checkpoint 输出流，
导致两个 Linux 第二片提前失败；这是诊断引入的夹具回归，原耗时问题仍保留跟踪。

## 实际行为

MCP 只增加两个固定 external/preserve_output 工具。显式列出模板与完整参数后，
通过当前目录已展示引用取回完整文本；服务端 user/assistant 角色仅是工具资料。
资源与模板复用有限目录、字节预算、宿主分页、调用准入与租约，分别保留缓存。
缺省参数和空对象原样传给 SDK，不补默认值；参数名不能安全展示、混合媒体、
超限正文或上下文无法容纳完整结果均明确失败。旧代已接纳 get 可按原连接与策略
收尾，迟到目录不能发布新引用，纯 Skills 更新继续保留当前 MCP 连接。

Windows 沿原 computer_action 操作当前快照保存的普通按钮对象。私有引用绑定
所选窗口、PID 与进程启动身份，原对象父链再次验证；IsPassword 在 Name/模式
之前检查。宿主在首个 await 前消费快照，并在实际写入前复核执行与 Runtime 门。
原生 Invoke 进入后异常或回执不明保留 unknown；accepted 只表示调用返回。
没有 Value、坐标、键盘或寻找替代控件的回退。

- Windows 3.12 job `119228670548`：1 失败、3444 通过、1393 跳过，334.12 秒。
  同一断言失败，两者 probe 本次均成功；

## 第二轮远端与诊断流回归

精确签名 `3efa34058c0ccad1b9cc87fe9ad1e4d0ad4d2adc` 的
[`39605245030`](https://github.com/69gg/MuLi/actions/runs/39605245030) attempt 1
已结束，八项成功、两项失败。两个 Windows、两个 macOS、两个 Linux 第一片、
quality 与 MCP 均成功。Ubuntu 3.12 job `119239640676` 与 3.13 job `119239640806`
各为 2 失败、2274 通过、18 跳过、2569 未选，分别 163.00 与 135.36 秒。

两种场景都在首条 `controller-step` 后立即失败，仍剩约 17 秒，尚未启动服务。
原共享 checkpoint 按完整单行精确匹配期望，根新增的 stdout 诊断没有接入该合同，
因此本轮不是原先 20 秒耗尽的重现。首条步骤约 2 秒、47 次 `_check` 的观察只覆盖
install_target，不能由此证明完整事务耗时或把校验略去。共享读取器继续保留严格合同；
该夹具的本地读取改为有限、逐行区分固定诊断与真正的 checkpoint，另补管道反例。
原总时间、总字节上限与真实 checkpoint 的成功要求不变。

修正前，真实小管道反例在旧读取器下 1 失败（0.20 秒，70.5 MiB），直接复现
诊断与 checkpoint 同批到达时的错误拒绝。修正后 28 项纯替身/小管道回归通过
（0.18 秒，71.1 MiB），覆盖拆分读取、非法帧、跨握手序号、32 步上限、EOF、
累计 4 KiB 与已读尾部；共享读取器仍严格拒绝这些诊断。未启动子进程或真实服务。
两处测试文件严格 mypy 通过（306.3 MiB），完整 Ruff 与 352 文件格式检查通过。
以上均经 30 秒资源守卫，swap 0；独立 Sol 只读后审无确定 P1/P2。
该修正只闭合诊断夹具回归，不宣称解决首轮原有的 20 秒耗时问题。后续远端结果另记。
