# 2.35 MCP 故障通知与分页兼容审查

状态：实现、独立审查与本地根整合检查完成，精确远端验收待完成；未发布。
MCP 普通资源工具仍是下一阶段设计，不作为本版本已交付能力。

## 用户结果与归属

当前已发布 HTTP/SSE 连接首次被接收保护标记不可用时，固定错误事实进入现有
SystemEvents、Attention 与渠道路由。SDK 后台吞掉异常不会抹掉这个宿主事实；
不通过额外轮询、自动重连或重放工具调用恢复连接。

前台工具结果继续属于原请求。独立连接故障在首次持久化时冻结默认或经核验的
记忆渠道，不能从正在执行的请求或 SDK 复制的异步上下文猜测发令人。保留首次
记录期间，重复事实只更新计数，不改变原路由和通知资格；不承诺永久去重。

候选、退休连接、stdio、正常取消及关闭期间不新增这类提醒。独立审查发现
Runtime 已开始关闭、尚未等待到 MCP 关闭的窗口；实际 Runtime 门控反例先失败，
薄回调检查现有 `_closing` 后通过，故障锁存和原连接清理仍继续执行。

新来源只复用有限固定码和宿主 occurrence，日志采集不访问数据库或格式化远端
异常。现有阈值、开关、队列、只读 Attention、模型预算及撤销守卫继续生效。
不增加主配置字段、数据库 DDL、持久队列或第二套通知引擎。

通知作者签名 `39a71fb7a5298f1eab7f57865212f1fa6b02ab1a` 整合为 `1c6fd40`。
根与独立 reviewer 逐项核对首次故障、关闭、路由、保留期与旧 slot 边界，
无剩余确定 P1/P2；整合保留 2.34 的可选 SDK 客户端显式类型注解。

分页片作者签名 `3d1781c56a248f90228f662dfd8ba8fd8e48e1af` 整合为 `acba453`。
锁定 SDK 与固定版协议均将 cursor 视为不透明字符串；仅删除错误的空值拒绝，
由 None 结束分页，重复空串和页数/目录预算仍拒绝。有效空串反例先失败，再验证
成功续页、原样 SDK 参数、失败保旧与候选关闭；四项新增及原相关共十一项通过。
两份 Python Ruff/格式和单源码 mypy 通过，pytest 峰值 66.6 MiB，类型 177.8 MiB。

## 作者验证

通知片十二文件 276 项唯一回归通过：新增 27 项，接收/代次四文件 67 项，
系统事件三文件 58 项，路由/Attention/MCP 四文件 124 项。真实 Runtime、临时
Store、SystemEvents、Attention 与 HTTPX MockTransport 贯通；不连接真实 MCP、
模型或渠道，一个既有实际 in-process server 用例未选取。

七份 Python 的 Ruff/格式、六份产品源码及新测试的限定严格 mypy 通过。
pytest 峰值 173.9 MiB，整轮 mypy 峰值 344.7 MiB，swap 0。每项沿根绝对路径
共享守卫串行运行，单次 30 秒、1 GiB、共享 2 GiB、单 CPU，没有安装依赖或
操作本机服务。根整合结果另记，不与作者测试重复累加。

既有 MCP extras CI 显式加入新通知测试文件；普通无 extras 矩阵仍执行纯
Runtime/Store/HTTPX 回归，不以整文件 skip 掩盖收集边界。

## 根整合验证

三组十三文件共 281 项通过，一个既有真实 in-process server 用例未选：

- 通知、系统事件、来源与 Attention 六文件 120 项，4.32 秒，128.5 MiB。
- 接收、HTTPX 集成与主动路由四文件 107 项，1.90 秒，190.1 MiB。
- 最终分页、MCP 代次与活跃调用三文件 54 项，1.26 秒，129.5 MiB。

版本准备阶段的兼容/发行两文件另 166 项通过，0.99 秒、68.7 MiB；只涉及元数据，
未因后续独立代码变更重复运行。139 个源码的完整严格类型检查通过，7.602 秒、
399.6 MiB；之后整合的分页一行改动再按最终文件复核。所有检查沿原守卫串行、
每条 30 秒，swap 0，不与作者结果重复累计，也不包含本机真实 CLI 或原生服务。

最终单源码严格 mypy 通过，5.416 秒、345.3 MiB；全仓 Ruff、337 文件格式通过。
83 包离线锁检查在版本准备时通过，依赖未变。没有前端变更；完整三平台两种
Python、普通无 extras 安装及构建检查由原远端八项 CI 验证，不另启动本地大组。

## 限制与后续

有界日志队列满、首次写失败、未提交时崩溃或关闭都可能丢通知；接收状态仍可
按需查询。旧 slot 不认识新 producer/code 时可能跳过并推进 Attention cursor，
不保证升级后的历史补发，也不声称旧程序执行新接收保护。

Linux 原生服务整链在独立 draft PR37 验收：第七轮 `7a0ece9` 的
CI `39585202872` 八项成功、一项 native 失败，仍为零事务、正常清理未获证明。
有限观察只证明当时专用 UID 的 manager 镜像存在，不证明具体等待根因。
本机不进行账户、挂载、用户服务或真实升级测试，也不放宽资源和期限。
