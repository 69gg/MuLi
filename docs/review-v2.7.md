# 2.7 记忆核查与注入审查

状态：本地验收和独立复审通过，待精确提交的远端矩阵与发布核验。本轮沿用现有 SQLite、权限门、模型工具批次与网页设置，不新增运行依赖。

先复现默认六条身份/偏好挤掉精确命中流程记忆的问题，再并行实现公平注入和网页核查。数据与 API 由主 agent 接线，独立 reviewer 同时检查旧编辑、来源遗忘和新预算边界。

注入在两流各至多 `context_limit` 候选中选择；最小完整页先预留，剩余正文共享预算。同一 ID 保留双流归属但只输出一次；极小预算、转义、中文、长元数据和单名额均有定向回归。独立 review 复跑 28 正式测试及两项预算枚举，未发现该分片阻塞；这与最终全套结果重叠，不相加计算。

旧网页 PATCH 会覆盖未提供的 kind、信任和事实槽位，并删除冲突、别名与去重键；无变化编辑也会改写语义。新 `Memory.edit` 合并显式可见字段，保留来源和宿主状态。原始引文仍只是原始资料，不能证明之后更正的正文。后审查进一步发现移除实体时孤儿清理会间接删掉仍有来源依据的别名；改为保留真实来源/记忆引用，纯 canonical 自映射不阻止回收，来源忘记后仍完全清理。

来源页沿用 2.6 的 UTF-8 和完整 JSON 算法，提取为共享帮助函数。SQL BLOB 窗口不将整篇原文载入 Python，身份元数据要么完整返回，要么明确失败。版本使用既有 source.digest；网页还核对 source_id，因为不同来源可有相同摘要。没有原始来源时不从会话备份静默恢复。模型工具实际执行回归检查前段、中段及过时版本错误进入下一请求时均保持完整结构，系统来源不会转为 owner。

网页复用记忆详情对话框按需读取原文，逐页验证来源 ID、摘要和 UTF-8 字节位置；一次只保留当前页，遗忘、版本变化、退出或切换条目清除旧页。编辑只提交六个可见字段，保存后重新读取详情和修订。后审查修复身份等四种类型缺少选项、首次详情仍未解析来源时迟到响应越过同源遗忘事件、保存后焦点丢失三处问题。未知类型也保留原值；原文的实际角色与主人信任不会被可编辑的来源标签覆盖。

最终本地验证：1346 项 Python 测试通过、1 项仅 macOS 的 CF/ABI 冒烟在 Linux 跳过；127 项前端测试通过。全仓 Ruff、143 个 Python 文件格式检查、71 个源码文件严格类型检查及离线锁文件检查通过。独立 reviewer 检查候选 `f0e12ab` 的有效 GPG 签名和变更，补跑 8 项新增门控及 2 项独立反证通过；这些测试与全套覆盖重叠，不另行累加。

真实浏览器使用临时目录、临时 SQLite 和回环地址，完成五页原文前后翻阅、末页边界、HTML/NUL 按文本显示、更正后历史、系统来源身份、同源遗忘事件立即清页以及关闭返回焦点。390×844 与 1280×800 的深浅主题均无横向溢出，控制台无错误；[桌面截图](screenshots/memory-verification-desktop.jpg)和[手机截图](screenshots/memory-verification-mobile.jpg)只包含演示数据。未知来源的首次 GET 竞态和退出场景由前端门控测试覆盖，不冒充浏览器全场景实测。临时服务和页面已关闭。

wheel/sdist 离线构建，并将 wheel 无依赖安装到 `/tmp` 后从仓库外导入。包内模块、CLI 所需资源、API 文档、提示词、默认关闭的电脑功能、任务控制与完整 lifespan 通过；额外验证包内新版网页、原文 NUL/实际身份、更正保留隐藏字段及修订记录。未下载运行依赖。
