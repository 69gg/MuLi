# 沐璃网页对话

界面使用原生 HTML、CSS 和 ES modules，无构建步骤、前端运行时依赖或 CDN。后端同源提供 `web/` 和 `/api/`；访问服务根路径即可使用。

## 界面与交互

2.57 定时委托入口采用现有青瓷蓝、轻分隔列表和工作流字号。内容为按需展开的计划名、下次时间、最近实际执行及取消；创建继续通过主对话。展开与分页沿原局部加载状态，取消显示提交中，页面刷新沿现有焦点恢复，不新增装饰动画或侧栏。

“定时委托”展开才读取 `/api/workflow-schedules`，一次只保留当前有界摘要页和访问过的游标，不预取或自动轮询。没有下次时间不补造日期，最近运行缺状态时显示未记录，授权或定义检查阻塞时显示暂缓执行；失败不冒充空目录。取消以服务端回执及重新读取为准，不先把行标成成功；已派发的操作不保证追回。目录与取消都绑定当前连接，收起、离页及认证失效清空目录并拒绝晚响应，旧取消的迟到401不会清掉新登录。首页保持持续对话，所有计划名及ID均按纯文本显示。

默认界面只有一段持续的 MuLi 主对话，打开或刷新时通过 `/api/conversation` 恢复。主页面没有侧栏、新建或删除主会话按钮；左下两个小按钮分别切换深浅主题和进入设置。主题首次跟随系统，用户切换后仅在本机浏览器保存偏好，不保存消息或密钥。

设置以自然语言要求为入口，完整管理页面仍可直接使用：

- 设置：主、审阅、执行、视觉、压缩、记忆提取模型，协议和原生推理参数，称呼与提示词，权限与工具，Chiliarch / MCP，消息渠道，语音与采集，媒体与检索，插件、更新、管理计划，通知、限制、访问和用户服务。
- 工作流：模板、步骤、模型角色、依赖、真实运行结果和取消。
- 团队：按最近创建分页查看成员，可筛选进行中任务，发送协作消息、停止任务和查看子任务记录；已绑定任务说明的成员可按需查看完整目标、要求与修订。支持任务控制的后端还可在说明弹窗内暂停任务范围、追加要求并交主沐璃重新规划。实时刷新保留焦点和已展开的消息。
- 记忆：检索、逐条核查原始引文与真实来源、按需分段读取原文、内容与实体关系更正、置信度及修改历史。
- 通知：收件箱、已读状态，以及一次或重复提醒的创建、改期、暂停和删除。
- 附件：本地文件库、图片和音视频预览、下载，以及将已有附件带入对话。
- 运行记录：按标题搜索完整记录目录、逐页查看主对话和子任务记录；子任务只读，主对话保持唯一。

头像与空态插画分别为 `muli-avatar.svg` 和 `muli-empty.svg`，是本次原创的青蓝古风 Q 版 SVG；并非生图模型输出。旧宣传图片不再用于新界面。浅色为青瓷蓝，深色为夜青；共享文字、表面与状态色 token，正文和可用按钮在两种主题中均以 4.5:1 为最低对比度。装饰线条和禁用控件另按用途处理。

输入支持中文组合输入，`Enter` 发送、`Shift + Enter` 换行、`Ctrl/⌘ + K` 回到主对话。运行中仍可发送补充消息，停止按钮独立显示；收到的是排队确认时显示实际待处理数量。切换管理页面保留对话、输入草稿和 SSE，刷新页面恢复已持久化的消息、未完成回复、审批和队列；未发送的文字草稿不会跨刷新保存。

当前执行与可操作审批由 `/conversation` 的 `live` 校正，历史开始/审批事件不会重新激活重启前的任务。已有页面接收到 `session.recovered` 时保留部分文本与 reasoning，结束旧流与审批；未闭合工具显示“结果未知”，明确的完成、失败和未执行继续保留。会话流从精确字符串 `after` 续接，不由最近历史事件猜测位置。该修复没有为完整首屏或长期 state/seen/DOM 建立总字节预算，见[会话恢复](session-recovery.md)。

## 已保存的正文

主对话顶部的“已保存记录”打开独立正文归档，从最新已保存的最多 50 条记录向前翻阅。旧任务详情保留原有图片、音视频与下载，并提供同一个“查看正文归档”入口；归档本身只读消息正文，不复制媒体或工具原生块，也不调用模型、执行工具或重新投递消息。

目录按返回的真实序号翻页，首次响应的 `through_seq` 固定本次追加上界；它不是数据库快照，期间删除可能缩短旧页。窗口仅保留当前目录页或当前正文段，以及访问过的数值页界，不预取、不累计全文。分页与分段导航位于内容顶部，打开或主动切换页段时回到该滚动区顶部，不必滚过长列表寻找按钮；较新一页和上一段重新读取。待处理收件的序号不作为消息归档游标，新 SSE 继续更新实时聊天，不改归档页、输入草稿或附件引用。

点击“查看正文”后，首段与续读都携带目录的 `revision`，按 UTF-8 字节边界读取。界面校验会话、消息、序号、版本、实际字节长度与推进位置；中文、emoji、NUL 和 HTML 按纯文本显示。角色使用“用户记录”“助手回复”“工具输出”等中性标签，系统资料独立标记；展示实际 `principal`、来源及元数据省略标记，缺失身份显示未记录。`runtime_excerpt` 明示保存时已节选，未标记的旧内容显示完整性未知；“所存正文末尾”不表示能恢复旧版本在入库前已丢弃的输出。

关闭、切换弹窗、离开页面及 401 会中断请求并清空保留的页，弹窗与请求身份使迟到响应不能回填；旧任务详情也采用相同归属门控。404 / 409 清空旧正文，返回记录后重新选择版本，不自动转到其他会话。读取失败明确显示错误并由用户重试，不能冒充空归档或 EOF。超过 JavaScript 安全整数范围的消息序号和游标明确拒绝，不发送舍入后的续页参数。翻页后恢复分页位置，正文返回后恢复同条消息按钮；等待中已移到其他控件的焦点不被抢回。

本入口未改变原有 `/conversation`、会话详情的初始消息窗口、hydrate 或 SSE 回放策略。

## 完整记录目录

设置内的“运行记录”通过 `/api/session-records` 单独读取目录，每页最多 50 条摘要，按创建时间由近到远；标题筛选在服务端先于分页执行，不再只搜索最近更新的 200 项。搜索框提交后读取，输入时不自动查询；`query` 原样传送，保留空白、NUL、`%` 和 `_` 的字面含义，最多 120 个 Unicode 字符。ASCII 不区分大小写，非 ASCII 精确匹配；这不是正文或语义搜索。分页位置显示已提交的查询，未提交的新文字不会改变当前结果。

“较新一页 / 更早一页”位于列表顶部，使用完整不透明 cursor；只保留当前摘要页与访问过的轻量游标。换页替换原行，不累计目录或预取正文。“刷新列表”使用当前已提交查询回第一页，保留正在输入的文字；删除导致后页变空时只回退一个已知页。创建排序不是数据库快照，标题更正或删除可改变后续页面。日期缺失、非法或不大于零时显示未记录；`idle` 只表示会话无当前执行，不代表成功完成或所有后代都空闲，也不增加基于它的结果筛选。

目录使用独立槽、稳定搜索表单及明确的加载/错误/重试状态，不写回 `state.sessions`。旧 `/sessions` 仍供主身份元数据与原实时链路使用；SSE 刷新至多提示“记录有更新”，不会重建目录、重置页、抢输入焦点、改变主草稿或增加目录查询。失败不会冒充空列表或 EOF，旧服务不支持新端点时明确提示，不降级最近 200 项并称作完整目录。

所有标题和 ID 按文本显示；标题缺失或为 `null` 时显示“标题未记录”，空字符串显示“空标题”，不会补成原始名称；状态缺失或为 `null` 时显示未记录，标题/状态的其它非文本类型作为响应错误。主记录展示实际标题与主身份标记，点击只回到持续主对话，其它记录沿用已有详情、媒体及正文归档。关闭详情或取消删除返回同一完整 ID 的按钮，条目已移除时回分页位置。页面读取不从已打开的弹窗或正在编辑的输入框抢焦点。切换视图、重新进入、401 和离页会取消读取、清空摘要并使晚响应失效；搜索请求乱序也不能覆盖新查询。目录 GET 不触发模型、工具、消息入站或执行恢复。

## 记忆核查

每条记忆都有“核查”入口，包括没有关系或没有关联原文的条目。打开时重新读取当前详情，展示正文、层次、状态、原始引文及来源实际的 `principal`、角色、渠道与可信标记。可编辑的“来源标签”与宿主记录的原始来源分开；身份缺失时显示未记录，不补成主人。冲突项可查看另一条记忆，更正操作不等同于选择冲突胜者。

“查看原文”和“修改历史”展开才读取。原文首段即携带详情中的 `origin.digest`，后续按同一版本的 UTF-8 字节位置读取；界面只保留当前一段正文和已访问段的起点，上一段重新请求，不预取或累计全文。中文、emoji、NUL 与 HTML 均按纯文本呈现，完整返回的条目、来源、版本与字节位置须一致。没有来源显示“无关联原文”，来源已忘记或变化时清空旧页，要求重新核查；不改读会话档案恢复已忘记的来源。

更正先重新读取详情，再复用原有表单；只提交内容、类型、实体、关系、来源标签和置信度。宿主的来源关联、可信标记、层次、槽位及状态不作为表单参数回传。保存后重新核查当前记忆，将键盘焦点移到详情标题；普通详情和原文异步读取不抢走当前阅读焦点。历史再次展开时读取最新修订；保留的摘录始终标为“原始引文”，不表示它已经证明更正后的正文。已有删除确认会说明同源遗忘范围，取消不发送写请求。

类型选项覆盖现有九种 `kind`（包含自动提炼的 `identity` 和兼容的 `episodic/semantic/procedural`），均有中文标签；未识别类型保留为“当前类型”选项。打开或提交更正不会因选项缺失而把原类型变为空值或默认观察。回归使用与浏览器一致的未匹配选项语义，并通过实际编辑器和表单提交核对类型保留。

关闭、切换弹窗、离开管理页面、离页与 401 会中断读取、清除原文和详情，并用弹窗身份阻止迟到响应回填。`memory.updated` / `memory.forgotten` 按条目或来源 ID 使当前核查失效；遗忘会立即丢弃旧页。从关系图打开列表外条目时，首次详情读取尚未确认来源，遇到来源级变更也会保守中断并要求重新核查；已知无关来源不打断，不累计事件缓存。正在更正时保留未保存草稿，提示重新核查，不让后台响应替换输入。没有广播的受信底层变更由下一次来源读取复核；网页不承诺撤回已经发出的响应。上述操作不调用模型或新建会话，首页保持不变。

### 召回路径

检索结果携带完整 `graph_via` 时显示“召回路径”，展开后重新请求原查询，核对当前条目与路径修订；同时只展开一条，不预取其他路径或原文。路径按实际有序步骤呈现，反向遍历仍保留原关系方向；名称使用显示字段，规范键不冒充显示名。登记入口区分原始登记、手工登记、规范名称和旧索引；“还有登记未展示”只表示尚有贡献记录，不表示更多独立来源。每个登记和关系步骤分别复用记忆核查弹窗；旧索引即使仍关联一条记忆，也只供查看，不表示该记忆已经证明此别名登记。

缺失、断开或不完整的路径不会由平铺关系补造；`path_omitted` 只显示“召回路径因预算省略”。关系或记忆变更会清空已展开路径并中断在途请求，等待用户重新检索；此失效范围不干扰无关原文或正在更正的草稿。关闭核查弹窗回到原步骤，即使多个步骤引用同一条记忆；步骤已移除时回到该路径按钮。切换查询、条目、页面或认证失效后，迟到响应不能恢复旧链。此入口解释本次召回依据，不表示全图、最短路径或独立来源数量。

## 附件边界

选择文件后先上传原始字节到本地附件库，发送消息只携带 `attachment_ids`。前端不会读取文本全文、将文件转成 Base64 注入模型、自动转录或自动播放媒体。移除输入框内的附件只移除引用，不删除文件。图片是否发送到视觉模型由服务端及模型配置决定。

图片使用安全的栅格 MIME 白名单；音频和视频使用原生 `controls`、`preload="metadata"`，不自动播放。SVG、HTML、PDF 等文档保留下载入口，不作为同源活动文档嵌入。所有内容与下载 URL 都由附件 ID 构造，同接口返回的外部地址不会直接作为预览源。

2.1 增加默认关闭的点击录音按钮；开启网页语音并配置 ASR 后，可生成可编辑文字草稿，仍须点击发送才进入对话。录音期间的用户编辑会被保留，迟到文字放到独立草稿区。取消、离页及退出登录会回收录音和转写请求；音频保留在附件库。详见 [网页录音](voice.md#网页点击录音)。

语音与桌面采集配置位于设置分组中。页面只读取组件和后端状态，不会在进入分组时录音、截屏、录屏或播放声音。设备可见、后端存在与真实权限验证分别展示；缺少声学唤醒组件、ASR 或声纹参考时显示服务端原因，不把文本匹配描述为声学识别。

## API 合同

所有接口同源、位于 `/api`。普通变更请求声明 `Content-Type: application/json`；文件上传使用原始 MIME。网页不持久化访问密码或 API Key。服务端负责 Cookie、同源请求、文件访问、模型权限和工具审批。

| 接口 | 用途 |
| --- | --- |
| `GET /auth/status`、`POST /auth/login`、`POST /auth/logout` | 访问状态，密码登录和退出 |
| `GET /conversation` | 幂等获取唯一主会话，返回 `{session,messages,events}` |
| `GET /status` | 模型、工具、集成、通知、版本和真实运行状态 |
| `GET /sessions`、`GET/PATCH/DELETE /sessions/:id` | 子任务记录、详情和已有会话管理 |
| `GET /session-records?query=&cursor=&limit=50` | 完整标题目录的有界摘要页，返回 `items/next_cursor/has_more`；cursor 绑定原样查询，EOF 为 null |
| `GET /sessions/:id/messages?before_seq=&through_seq=&limit=50` | 正文归档目录，返回 `session_id/messages/through_seq/next_before_seq/has_older`；向前游标排他，EOF 为 null |
| `GET /sessions/:id/messages/:mid/content?offset_bytes=0&revision=...` | 按版本读取单条已保存正文，返回完整身份、UTF-8 字节窗口与下一位置；不返回附件或原生模型块 |
| `POST /sessions/:id/messages` | `{content,mode,attachment_ids}`，返回 `{run_id,session_id,message,queued?}` |
| `POST /sessions/:id/stop` | 请求停止当前任务 |
| `GET /events`、`GET /sessions/:id/events?after=cursor` | 全局 / 主会话 SSE，按最后事件 ID 接续 |
| `POST /approvals/:id` | `{decision:"approve"|"reject"}` |
| `POST /uploads` | 原始文件字节；`X-File-Name=encodeURIComponent(name)`，原始 MIME 作为 Content-Type |
| `GET /uploads` | `{items}`；项目含 `id,name,mime_type,size,url,preview_url,kind` |
| `GET /uploads/:id/content`、`GET /uploads/:id/download` | 本地内容预览 / 文件下载 |
| `GET /team?limit=50&offset=0&active_only=false` | `{members,messages,offset,limit,total,active_only,has_more}`；成员含限长消息预览，完整历史通过会话详情读取 |
| `POST /team/:id/messages`、`POST /team/:id/stop` | `{content}` 协作消息 / 停止成员任务 |

密码门通过 HttpOnly / SameSite Cookie 访问服务。任何接口或 SSE 返回 401 时立即中止事件重连，显示密码输入；登录成功后重新恢复主对话。API 参考也仅加载同源文件，不依赖 Swagger CDN。

工作流管理先显示全局“进行中”，再显示最近定义及可展开的最近运行历史。活动入口独立于定义列表，每条运行均有完整、可换行的 ID 和独立停止按钮；同定义的较新完成记录、其他并发运行及不在最近定义列表中的旧定义都不会遮住它。`pending` 显示“等待中”，不推断为审批。停止仅在响应后显示“已提交停止请求”，实际状态由重新读取确认；定义删除的 409 保留真实错误。

活动接口只返回 `id/workflow_id/name/status/created_at/updated_at`，每页最多 50 项，包含 `pending/queued/running`。`has_more:true` 时 `next_after` 为本页最后的完整 ID，否则为 null；它是排序位置，不代表固定快照或全局已读。前后翻页仅保存页起点和当前页摘要，不预取后续页或累计节点、结果正文。后页因实时完成而变空时只回首一次，不循环跟随 `has_more`；不显示推算的总数。

活动运行和定义并行读取并独立报错，读取失败不能显示为空闲。`workflow.updated` 使在途旧页失效，合并回首刷新，即使对应定义未列出也会重新读取；迟到响应不能覆盖新页。重绘保留历史展开及同运行焦点，运行移除后回到活动标题，不抢走区域外焦点。离页、认证失效或关闭页面会取消读取并丢弃活动页。完整记录目录另有标题查询分页，不从记录页或会话的 idle 推断全部工作流是否活动。

任务说明正文按文本展示，证据引用默认折叠。打开时按需读取当前保存的修订，不截去中段要求；旧任务没有说明时明确显示尚未登记。没有 `control` / `scope` 的 2.2 详情保持只读，不提供不能兑现的暂停按钮。关闭或打开其他对话框后，迟到的详情响应不会替换新内容；认证失效会关闭对话框并清除详情，确保密码门可访问。

任务控制沿用此弹窗，不增加首页面板。暂停必须收到宿主回执，模型文字和本地点击不会直接变成“已暂停”；已经进入工具的操作允许收尾。暂停范围使用服务端 `scope.member_count`，包含同一任务说明的全部绑定成员及其子任务，不从当前团队分页推断。存在活动工作流时显示 `workflow_active` 原因，暂停原子 409，不自动停止工作流，也不显示部分成功。暂停后可追加完整要求或留空交主沐璃重新规划；没有直接恢复按钮，关闭和刷新都不会解除暂停。

控制显示以 `current.revision` 单调归并，覆盖同 epoch 从暂停到批准的变化。紧凑写响应不含计划正文时保留已有正文，再按需 GET；只有完整详情自己的修订可标在要求正文上。后台更新不重建正在输入的补充要求，409 保留草稿并提示核对后再次明确提交；“补充要求并交沐璃”只追加要求，不提供删改旧约束的入口。SSE 的 `commitment.updated` 只使当前弹窗失效，不携带或拼接正文，也不轮询模型。

请求结果未知时保留原操作体及 `request_id`，用户重试复用相同内容，不自动换 ID 发第二次。`503 / model_unconfigured` 与 `429 / queue_full` 属于明确的事务准入失败：显示服务原因、结束本次提交并保留既有暂停及补充草稿；断线和其他无法确认提交结果的 5xx 仍按未知结果处理。同标签页的 `sessionStorage` 仅在操作已经提交、回执尚未确认期间保存该操作体，支持关窗和刷新后确认；成功或明确失败后移除，401 和退出登录清空。未提交的补充草稿只留在打开的弹窗中，关闭后不保存。该机制不保存密码或 API Key。方案确认与队友通知投递分开显示，界面不把“计划已确认”描述成全体已执行。

`run.paused` 结束当前流式状态并清理旧审批，保留排队输入；刷新回放也保持暂停，不显示为持续忙碌。工具结果的 `not_executed` 与失败、成功分别展示，`task_paused` 标为“未执行 · 已暂停”。紧凑工具事件中的非截断 `status/code` 优先保留语义，结果正文可继续按后端预算截断。新暂停后，旧 epoch 的计划只显示为“此前计划”。

SSE 事件为 `{id,type,session_id,data,created_at}`。支持消息增量、思考、消息完成、工具开始 / 完成、审批请求 / 解决、运行开始 / 完成 / 失败 / 取消。持久收件使用 `message.queued {message}`，用户消息的 `delivery_status` 为 `pending` / `delivered`；快照中的 pending 行恢复待处理数量。前端同时兼容 `conversation.queued {message_id,run_id,source}` 和 `conversation.injected {message_ids,run_id}`。用户消息完成事件不会清除助手正在流出的片段；晚到的 pending 确认也不会把已送入的消息重新排队。全局事件更新通知、提醒、工作流、团队和附件列表。

记忆变更使用 `memory.updated {memory_ids,source_id}` 与 `memory.forgotten {memory_ids,source_id}`。来源页返回 `memory_id/source_id/field:"content"/revision/content/offset_bytes/length_bytes/next_offset_bytes/total_bytes/has_more` 及真实来源元数据；前端不依赖额外的兼容字段。404 `evidence_not_found` 和 409 `evidence_changed` 清除旧页，其他读取错误保留当前段并允许原位置重试，不能显示成假 EOF。

`attention.queued {message}` 将后台资料纳入待处理队列；`principal:"system:attention"` 的内容显示为可展开的“系统资料”，不会冒充用户请求。`ingress.cancelled` 清除取消的待处理行和计数，保留已送入的消息与流式回复。历史回放维持同样的来源标识。

会话详情的 `messages` 是已完成消息的权威来源；回放仅重建工具、审批、运行状态、最新思考、未完成回复和待处理队列。事件 ID 去重防止重连重复 Token。消息中的 `attachments` 使用完整元数据；只有 `attachment_ids` 时从本地库缓存查找。

设置仅提交实际改动；空 API Key、访问密码和渠道密钥保留旧值，`clear_api_key:true` / `clear_password:true` / `clear_token:true` / `clear_webhook_secret:true` / `clear_client_secret:true` 才明确清除。`api_key_set`、`password_set`、`token_set`、`webhook_secret_set`、`client_secret_set` 等只读状态不会回传；`reasoning`、`thinking`、`extra_body`、`extra_headers` 为完整对象替换，互不生成隐式参数。执行、压缩与记忆提取模型未配置时复用主模型；审阅模型未配置时交由用户批准；主模型不支持图片时可配置独立视觉模型。

设置概览提供自然语言入口与检查配置、消息渠道、语音组件和更新的短示例。没有未保存编辑时，再次进入设置会读取最新配置，供对话完成配置后核对；有编辑时保留草稿。状态刷新不会清除草稿。渠道、语音与采集、扩展与维护分组可直接编辑常用字段，其余完整参数以折叠 JSON 按字段覆盖；删除 JSON 中的键保留原值，明确的空数组、空对象或清除开关按接口合同处理。独立模块读取失败不会阻止其余分组使用，也不会把未知状态显示为关闭或更新成功。

渠道分组管理 OneBot、Telegram、QQ 官方机器人和微信的用户 / 群组白名单、接收附件及独立凭据，展示持久发送记录中的失败或结果未知。失败记录可重试，结果未知时须再次确认，取消不发起请求。扩展与维护分组展示插件清单、待重启标记、已有更新检查和管理计划；读取页面不会触发网络更新检查、安装插件或执行重启。记忆处理、上下文压缩和主动关注可在媒体与检索分组的折叠 JSON 中调整。并行 Agent 数只约束资源并发，界面不添加任意人数上限。手机横向设置导航在切换后保持当前分组可见。

MCP JSON 仅在实际修改后提交完整 `mcp` 对象。服务端原子替换服务器集合，并保留原位未改的 `••••` 凭据。旧服务只返回 `configured` 标记时隐藏编辑器；标记不回传。用户服务重启 / 停止使用短确认并处理断线，收到提交确认后再读取实际状态。提醒由后端调度，网页不调用模型轮询时间。
