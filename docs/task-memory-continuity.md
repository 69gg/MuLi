它补充现有的分层记忆、后台提炼、GraphRAG和冻结任务说明，不建立另一套记忆服务。

## 使用

主沐璃用 `commitment_save` 登记任务说明，再将真实任务ID传给 `spawn_agent`。
队友收到“继续整理”这类通用输入时，如果当前输入没有召回资料，宿主可用该次请求已冻结的
任务目标，从本地已有记忆中补入相关背景。资料仍带原来源和冲突状态，不是新的主人指令。

任务说明始终独立、完整注入；背景补位不决定任务归属，不解除暂停，也不授予执行权。
没有真实任务快照时不猜测最近任务。主会话明确选择的重规划快照仅可选材，不转成队友授权。

## 当前问题优先

原当前查询、Graph检索、侧写、缓存顺序和完整渲染先执行。排除本次user初始自动episode后，
只要仍有当前召回，就不搜索任务目标；不会把目标拼入当前查询，改变其词序或排名。
原资料块先完整生成，再用实际剩余槽位和字符尾部追加，保留原正文与冲突组合。

正式请求先让原基线经过扩展hook、完整冻结任务说明、Skills和原打包流程，之后才决定
是否加入任务背景。补入后的整请求JSON也必须放得下；否则舍弃全部可选任务增量，
不再次打包、截短旧工具结果、重复检索或重复运行hook。宿主系统消息被扩展改写、删除
或复制时保守不补；合法Skills内部打包的深拷贝不会单独触发退化。

任务背景首片只作词法补位，不增加Graph遍历、embedding或reranker请求；查询词、候选、
证据检查、名额和字符共用原有余量。当前已用满、目标无剩余词、资料放不下时保留原结果。
当前自动episode不得从目标检索回灌。无有效来源、已遗忘或过期修订不能成为补位事实。

显式 `memory_query` 的已有缓存命中时，如果没有本次候选消费的准确资料，就保留原缓存行为，
不重新搜索或清缓存来争取补位额度。普通自动上下文不会自行写这种显式查询缓存。
显式 `memory_query`、`memory_source` 仍可按需查询别名、多跳路径及原文；这些既有能力不能
当作本片新增自动多跳的验收。

适配器和没有MemoryApplication的Runtime使用同一本地组合入口。旧单参数回调接口保持；
受信扩展要接收任务补充查询时显式登记返回两份结果的typed composer；旧str renderer
保持原接口，不猜签名、双调用或以TypeError重试。
不增加依赖、持久格式、队列、定时器或前台网络等待。
