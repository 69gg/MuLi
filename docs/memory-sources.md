# 查找已保存的来源

可以直接说：“列出最近保存的资料”，或“找出哪些资料整理失败了”。主助手和队友使用只读的 `memory_sources`，无需先知道关键词或来源 ID。

目录包含准确的 `source_id`、入库来源、身份、原文版本、字节数和后台整理状态，不附正文或内部处理记录。需要核对内容时，再用 `memory_source` 按需读取。查看目录不会提炼、生成向量、重试失败任务或创建重建计划。

## 状态与翻页

`state` 可筛选 `queued`、`processing`、`retry`、`failed`、`done` 或 `deferred`；不传则查看全部。`deferred` 表示来源已保存，尚未登记整理作业；`done` 只说明原整理作业完成，不证明当前 embedding 模型已覆盖所有资料。

每页默认检查 20 个来源，`limit` 可设为 1 到 100。为保持读取有界，筛选不匹配或无法核查的记录也占检查数，并计入 `omitted`。即使 `items` 为空，只要 `has_more` 为真，仍可用相同筛选和 `next_cursor` 继续。输出预算较小时会返回能完整容纳的前缀；单条完整身份也放不下时会明确报错，不截短来源 ID。

目录按入库先后倒序实时读取，不是固定快照。新保存的来源从首页查看；后台状态和遗忘结果以当前读取为准。游标只用于同一资料库和同一筛选的续页，不代表操作授权。

失败条目保留错误类型，便于定位；进一步处理沿用已有的审批、重试和[重建索引](memory-reindex.md)入口。遗忘后的来源不会因为翻页而恢复。
