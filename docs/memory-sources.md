# 查找已保存的来源

可以直接说：“列出最近保存的资料”，或“找出哪些资料整理失败了”。主助手和队友使用只读的 `memory_sources`，无需先知道关键词或来源 ID。

网页也可从“记忆 → 来源”浏览、筛选和刷新。每条资料可展开来源详情，或点击“核原文”按版本分段读取；正文只在明确读取时展示。

目录包含准确的 `source_id`、入库来源、身份、原文版本、字节数和后台整理状态，不附正文或内部处理记录。需要核对内容时，再用 `memory_source` 按需读取。查看目录不会提炼、生成向量、重试失败任务或创建重建计划。

明确收藏了旧稿和新稿后，可以请沐璃[核对两份资料的变化](source-comparison.md)，逐条查看增删改动并核对双方原文。

明确收藏的沐璃答复以 `reply:<原消息ID>` 保存，保留原消息位置与原文版本，作者为助手。收藏时使用历史读取返回的消息版本；以后核原文、比较或查询时，使用来源目录返回的版本。这两种版本不能互换。历史消息仍在不代表已收藏，来源存在也不证明答复中的内容正确。

## 状态与翻页

`state` 可筛选 `queued`、`processing`、`retry`、`failed`、`done` 或 `deferred`；不传则查看全部。`deferred` 表示来源已保存，尚未登记整理作业；`done` 只说明原整理作业完成，不证明当前 embedding 模型已覆盖所有资料。

明确收藏的文本、PDF、DOCX、完整 ASR 转写或已捕获网页在后台整理最终失败时，可以交给沐璃空闲时说明：“原文已保存，整理失败。”提醒保留准确来源 ID 和原文版本，不附正文、凭据或异常正文，也不自动重试。ASR 来源会明确说明仅核验转写文本，没有验证原音频、说话者或准确性；网页来源保留静态文本范围，不证明网页真实或当前状态。重试中的暂时失败、日常聊天自动记忆、队友报告和单独索引重建不产生这类提醒。

ASR 收藏的来源 ID 是 `attachment:<转写工件ID>`，不是原音频 ID；来源标记含 `transcript:v1:asr_text`。目录、核原文和比较页面保留转写说明。目录的 `revision` 绑定完整来源身份，与转写附件本身的 SHA-256 不同：收藏用工件摘要，来源续读、重试和比较用来源目录返回的版本。

网页收藏的来源 ID 是 `attachment:<快照ID>`，标记含 `webpage:v1` 和 `http_utf8_text_v1` 或 `html_static_text_v1`。用 `memory_source` 从首页读取，可以核对保存的请求网址、最终网址、宿主采集时间和正文；不会查询网站现在的内容。收藏使用快照附件摘要，来源续读、重试和比较同样使用目录返回的来源版本。同一网址的新快照是另一份历史来源。

此项由[主动关注](attention.md#主动事项如何工作)的 `attention.enabled` 和 `attention.events` 中的 `memory` 控制。新配置默认包含 `memory`；已有配置明确列出其它类别时，需要主动加入。通知沿独立事项的默认目的地，普通说明仍在网页；手机外发须沿既有渠道权限显式发送。

同一份资料的同一失败期只提醒一次，正常重开或重新配置不重复。遗忘、原文变化、已接纳的明确重试或作业恢复会使尚未处理的旧提醒失效；已经开始显示的文字不能保证撤回。没有收到提醒不能证明整理成功，仍可刷新来源目录核查。

每页默认检查 20 个来源，`limit` 可设为 1 到 100。为保持读取有界，筛选不匹配或无法核查的记录也占检查数，并计入 `omitted`。即使 `items` 为空，只要 `has_more` 为真，仍可用相同筛选和 `next_cursor` 继续。输出预算较小时会返回能完整容纳的前缀；单条完整身份也放不下时会明确报错，不截短来源 ID。

目录按入库先后倒序实时读取，不是固定快照。新保存的来源从首页查看；后台状态和遗忘结果以当前读取为准。游标只用于同一资料库和同一筛选的续页，不代表操作授权。

## 只查选中的资料

点击来源条目的“在此来源内查找”，再输入想找的内容。页面会显示当前来源；“查全库”保留查询文字并恢复普通检索。也可以让主助手或队友调用 `memory_query(query, source_ids=[准确来源ID])`，同时选择几份资料进行比较。

限定范围同时适用于文字、关系、向量和重排。关系路径与社区摘要只使用所选来源的依据；没有匹配或来源已遗忘时返回空结果，不自动扩大范围。语义服务不可用或输出只能容纳部分结果时会明确提示，可继续核对原文。查看结果不会重新提炼或重建索引。

不传 `source_ids` 才是全库查询；空列表无效，重复 ID 会合并。返回结果保留完整的 `source_ids`，不会把放不下的 ID 截短。范围是本次检索的选择，不是身份或操作授权，也不表示范围外的冲突已核实。

## 只重试选中的资料

失败条目保留错误类型。确认原因后，可以明确说“重试这份失败资料”，主助手用准确的 `source_id` 和 `revision` 调用 `memory_retry_source`；队友没有此写入口。也可以在来源页面点击“重试此来源”，核对确认框后提交。

此操作只重新接纳这份失败或延后的来源，保留已有处理进度，不重置已完成或正在处理的作业，也不顺带登记其它延后来源。原队列中的正常工作仍会继续。记忆关闭、维护暂停、工具禁用、原文变化或来源已遗忘时不会接纳；容量不足会明确返回未接纳。

重试可能继续向已配置的提炼或向量服务发送正文。已确认保存且仍有效的向量会复用；上次请求已经发出但结果未确认保存时，仍可能再次收费。`accepted=true` 和 `queued` 仅表示接纳，应刷新目录核对后续状态。原作业已经完成、只是需要更换 embedding 时，应明确[重建索引](memory-reindex.md)。

关闭确认框会停止页面等待，但不能保证撤回已经被服务接纳的重试；结果不明时先刷新核查，不直接重复操作。遗忘后的来源不会因为翻页或重试而恢复。

## 管理 API

已认证管理入口与模型工具共用相同的来源核验和额度：

- `GET /api/memory/sources`：可传 `cursor`、`state` 和 `limit`。
- `GET /api/memory/source`：传 `id`，用 `revision` 与 `offset_bytes` 继续读取，可指定 `length_bytes`。
- `GET /api/memory/query`：传 `query`、可选 `limit`；用重复的 `source_id` 参数限定一份或多份资料，例如 `?query=备份&source_id=资料甲&source_id=资料乙`。不传来源参数查询全库，空值无效。
- `POST /api/memory/sources/retry`：只接受 `source_id` 和 `revision`；返回准确来源、原状态、当前状态、接纳结果和原因。
