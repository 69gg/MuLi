# 话题提醒

可以直接告诉沐璃：

> 下次我提到“露营”，提醒我带充电宝。

登记成功后，你在网页或归属主助手的主人私聊中第一次提到“露营”，网页通知中心就会提醒一次。已开启[桌面通知](notifications.md)时也会有桌面副本。通知只使用登记的标题和正文，不复制那条聊天内容；再次提到不会重复提醒。

匹配按你指定的原文字词进行，区分大小写，不猜测近义词。例如 `MuLi` 不匹配 `muli`。你亲自粘贴的文字也算原文。附件内容、文件名、识别文字、下载告警、旧消息、系统消息和队友报告不参与匹配；登记消息本身及登记前已收到的消息也不会触发。渠道移交给队友期间，那里的消息不触发主助手的话题提醒。

## 查看与取消

可以说“列出我的话题提醒”或“取消带充电宝这条话题提醒”。沐璃会确认准确记录。取消保留记录，已经收到的通知不会撤回。要再次提醒，请明确登记新的一条。

登记和取消沿用当前权限模式，`ask` 仍需批准；审批期间的新要求会使尚未开始的旧操作失效。触发提醒只生成本地通知，不调用模型、不执行提醒正文，也不自动向 QQ、微信等渠道发送。

服务需要保持运行；关闭网页不影响提醒。正常重启会继续处理登记后已收到但尚未检查的合格新消息，已发出的提醒不重复。

## 可选设置

通常无需调整。需要控制容量时，可以让沐璃修改配置：

```json
{
  "topic_reminders": {
    "max_active": 32,
    "max_keyword_chars": 120,
    "batch_size": 8
  }
}
```

三个值分别控制活跃提醒数、词语长度和每批检查的消息数，范围分别为 1–256、1–512、1–64。标题最多 120 字，正文最多 4000 字。列表只返回词语、标题和状态；超出工具输出预算时，减少每页条数。缩小输出预算也不会阻止取消已有长正文提醒。

后台只在收到新消息、登记或取消、修改配置及启动时检查，不轮询模型。若降低容量至已有提醒数量或词长以下，或发现损坏记录，会暂停检查并在管理状态中报告错误；先取消多余记录或恢复设置。连接留下未结束事务时，需要处理事务后重启服务，不会自动修复数据库。

降级到不支持本功能的版本时，提醒记录保留但休眠，需恢复目标版本对应的配置；旧版不认识 `topic_reminders` 配置节。恢复新版后，不会猜测补触发缺少原文标记的旧版消息。

相关工具为 `topic_reminder_create`、`topic_reminder_list` 和 `topic_reminder_cancel`。登记工具的 `key` 用于同一请求重试去重，不会重新启用已经触发或取消的记录。列表以末条 ID 作为 `after_id` 续页。

按时间提醒、任务复盘和定时委托见[提醒与主动事项](attention.md)。
