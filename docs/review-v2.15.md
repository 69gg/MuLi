## 原渠道回复

宿主在插件/模型等待前固定不可变 ReplyOrigin，团队树、持久报告及 ingress 原子交接保留原来源；Store 只认领连续相同完整目的地的 FIFO 前缀，原生工具调用/结果批次完整收尾后再认领下一来源。执行 principal 与任务约束不由回复目的地授权。原渠道不可用持久 blocked，管理重试复用同一记录并重验原目的地；unknown 仍需原有显式确认。

独立静态复审包含核心及 blocked 前端补充，无剩余阻断。新增 23 项与既有 168 项 Python 相关回归通过，最大峰值 170.8 MiB；10 项定向前端通过，峰值 36.9 MiB，均 swap 0。相关 Ruff、格式、6 份产品源码严格类型通过。测试为临时 Store、假模型/HTTP，包含重开恢复；未证明真实账号回复时效或真实进程重启。Workflow、主动默认渠道和记忆选路继续独立推进，不计入本版。

## 最终上下文组合复审

独立只读审查覆盖 `self_events` 的白名单证据与查询预算、ReplyOrigin 在连续来源 FIFO／Team 报告／完整工具批次之间的交接、渠道事件重放和 outbox 的 unknown/blocked 保留，以及压缩继续从原始档案取得宿主来源的路径。未发现新的路由越权或未知发送自动重试问题；真实外部平台仍不在本机验证范围。

发现一个发布阻断：查询函数虽然输出完整分页 JSON，`self_events` 未声明现有 `preserve_output`，通用上下文打包仍会在紧邻的下一次模型请求前裁剪该结果。以 20 条临时日志、2 条分页及可整体移出的已结束旧轮次，通过真实 Runtime→假 provider 复现；旧结果被压成 `{`、节选标记与 `}`，JSON 解码失败。反证 **1 项失败**，0.30 秒、service 0.907 秒、CPU 0.892 秒、峰值 75.1 MiB、swap 0。

修复只为 `self_events` 启用宿主现有完整结果保护，没有改通用打包规则。新增六例覆盖 Chat／Responses／Anthropic 三协议：完整页能放下时原样到达实际请求编码；确实放不下时在第二次模型请求前明确 `ContextLimitError`；完整结果仍持久保留，保护标记不泄露到工具 schema 或厂商请求。相关查询、系统事件、Attention、管理及上下文证据合计 **130 项通过**，0.89 秒、service 1.424 秒、CPU 1.385 秒、峰值 98.5 MiB、swap 0。修改文件 Ruff／格式及管理源码严格 mypy 通过，类型检查峰值 180.7 MiB。均经共享 guard 串行执行，不调用真实账号或模型；修复候选的整合和远端矩阵另记。
