# 收藏附件，日后按内容找回

可以对沐璃说：“把这份交接资料收藏下来，以后问项目时能找到原文。”主助手保存准确附件的完整文本，再交给后台记忆整理。

以后从另一已绑定渠道提问，也可以用 `memory_query` 查资料，再用 `memory_source` 核对原文，不必重新上传或让原对话一直留在模型上下文里。

## 怎么收藏

1. 上传文件，或在附件库中找到准确的附件。
2. 明确要求收藏，并指出是哪一份；同名文件较多时使用附件 ID。
3. 查看实际回执，区分已登记、等待整理、整理完成和已遗忘。
4. 日后按正文主题查询，需要依据时继续读取来源原文。

上传、预览、读取和资料目录提醒都不等于收藏。

支持完整的 UTF-8 普通文本，以及 PDF、DOCX 的[提取正文](document-reading.md)。不收藏图片、录音、视频、旧式 DOC，或把转写、视觉解释等生成工件混作原文件正文。文件过大、编码不符或当前文件无法核对时会拒绝，不会拿节选冒充全文。

普通文本使用 `memory_import_attachment(id)`。PDF、DOCX 先通过 `document_read` 确认阅读范围和版本，再用同一收藏工具传入 `id` 与 `revision`。收藏会重新核验并保存完整提取正文，即使阅读工具只显示了第一页；原附件摘要、提取版本与范围也会保留。扫描 PDF 仍需另行识别，DOCX 未读取的图片、批注和页眉等不会变成收藏正文。

## 来源与权限

收藏内容作为外部资料处理。文件里的身份声明、偏好和指令不会变成主人的人格、偏好或执行授权；模型提炼出的结论也可能有误，需要时应查原文。

同一附件重复收藏使用同一个来源，不会因为换了私聊就再建一份。原文件或提取结果变化时会拒绝旧版本，不能拼接或覆盖已经收藏的正文。修改稿应作为新附件收藏，旧稿仍是历史资料，不会自动改成最新结论。

收藏由当前主助手按主人的明确要求发起，仍遵守原来的审批和任务限制。不要把“已收藏”理解成已经阅读、验证或接受其中的全部内容。

## 后台处理与成本

前台保存全文并登记处理，不等待模型提炼完成。后台可提取事实和关系，并使用已配置的 embedding 建立语义索引。可以继续聊天，尚未完成的内容可能暂时无法通过语义查询找到。

原文保存在本机；提炼、embedding 和查询重排可能把相关正文或查询发给你配置的服务。关闭 `memory.auto_extract` 只停止模型事实提炼，已配置的 embedding 仍可能参与处理。服务配置见[模型与媒体服务](providers.md)。

未配置语义服务时仍可保留来源，并使用本地文字与关系检索。文件名不需要包含查询词，但能否按近义表达找到内容取决于实际索引和服务状态。

## 核查与遗忘

可以要求：“找出这条结论的来源，继续读完整原文。”长来源应沿实际返回的版本和续读位置翻页，不把第一页当成全文。网页“记忆 → 核查”也可以查看来源与引文。

要求忘记这份资料，或在记忆页面确认来源级删除，会移除该来源的原文和派生记忆。同一附件再次收藏或正常重开不会使已遗忘的来源自动复活。

遗忘记忆不会删除附件库里的文件；删除附件文件也不会自动删除已经收藏的原文。聊天、导出和备份同样需要分别管理。更多操作见[长期记忆](memory.md)。
