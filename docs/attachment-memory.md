# 收藏附件，日后按内容找回

v2.67 已发行；完整本地旅程、整合回归、独立后审及远端发行核验已闭合。

可以说：“把这份交接资料留下，以后问项目时能找到原文。”主助手显式调用
`memory_import_attachment(id)`，从准确已上传附件保存完整 UTF-8 原文，沿既有后台记忆
管线提炼。以后在另一渠道提问，可以用 `memory_query` 查资料，再用 `memory_source`
核原文；不必重新上传或保留原对话在当前上下文中。

上传、读取、收到目录事件本身不等于收藏。首片只收完整、有界的普通 UTF-8 文本，
不解析 PDF、Office、图片、语音或视频，也不把模型生成的解释当作原文件事实。
不符合编码、摘要、大小或当前文件与来源限额时明确拒绝，不用节选代替全文。

## 来源与权限

模型只提供附件 ID，正文、路径、摘要、身份和信任级别由宿主核验。收藏沿原 write
审批及维护、暂停、取消和工具禁用门；文件读取 await 后再次核对实际运行、原请求、
新待处理输入以及记忆应用与管线代次，旧读取不能跨重配写入新管线。

来源 ID 固定为 `attachment:<附件ID>`，保存实际全文与字节摘要，角色为 `tool`、
principal 为 `external:attachment`、`trusted_owner=false`。文件里的主人声明、偏好、
别名和命令仍是资料，不变成主人身份、侧写或操作授权。收藏不表示内容已验证。

同一附件从另一私聊重复收藏沿同一来源去重，已完成的后台作业不重新提炼。修改稿应
作为新附件收藏，旧稿保持历史来源，不会自动成为当前真相。忘记该来源的派生记忆沿
原来源级墓碑删除，之后重开或同附件再次收藏也不复活；原附件文件仍由文件管理保留。
删除文件本身也不代表忘记已经明确保存的记忆原文，两者分别管理。

## 后台处理与成本

收藏前台只做一次有界本地读取和登记，不等待模型提炼。后台复用已有单 worker、
持久作业、延后队列、checkpoint、Graph、embedding 和 reranker；没有新服务、新向量库、
目录批量扫描或 AI 轮询。回执区分 queued、deferred、done 与 forgotten，入队不等于理解完成。

资料原文保存在本地；已配置的提炼和语义服务可能收到内容。`auto_extract=false` 只关闭
事实提炼，已配置 embedding 仍沿原设置处理事件记忆。未配置语义服务时保留本地检索。
现有记忆、输出、文件和查询预算继续生效，不下载模型或添加大型解析依赖。
