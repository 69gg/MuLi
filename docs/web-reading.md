# 留存公开网页，换个渠道继续读

可以对沐璃说：“把这篇公开文章留在本机，先读首页；晚上从手机继续，先不要放进长期记忆。”主助手用 `web_capture(url)` 读取一次公开网页，把完整的有界静态文本保存为本地 `.txt` 附件。回执给出附件 ID、摘要、请求网址、最终网址和阅读范围；捕获本身不把正文塞进模型，也不代表已经读过。

之后用 `attachment_read(id, offset_bytes=0)` 阅读首页，再按返回的 `revision` 和 `next_offset_bytes` 继续。想下次从这里开始，可以明确要求[保存续读位置](reading-bookmarks.md)；同一主助手在 WebUI 和已绑定的主人私聊中共用书签，对话压缩或正常重开后仍读取这个本地快照，不需要重新访问网站。普通阅读不会自动推进书签。

没有保存书签时，可以按 `source="webpage"` 和网址主机名查询[附件目录](attachment-search.md)。要留下具体句子和自己的备注，可以保存[摘录卡](reading-excerpts.md)。这些动作都需要实际读取原文，目录与捕获回执不能充当阅读证据。

## 保存的范围

| 回执 `scope` | 正文范围 |
| --- | --- |
| `http_utf8_text_v1` | 本次 HTTP 响应的完整 UTF-8 文本 |
| `html_static_text_v1` | 从本次 HTML 提取的静态文本，排除 `script` 和 `style` 内容 |

HTML 可能包含导航和被 CSS 隐藏的文字。这不是浏览器渲染，不运行 JavaScript、不使用登录状态或 Cookie，也不保存原 HTML、图片、原始排版或整个站点。网页需要登录、动态加载或不是 UTF-8 时，请使用其它适合的资料来源。

工件开头保留宿主观察到的请求网址、最终网址、采集时间和范围，分隔线之后是完整提取文本。这些说明只记录本次留存；网页内容和其中的身份声明、指令仍是外部资料，不会成为主人的身份、确认事实或操作授权。

## 限额与失败

下载字节、提取文本及带来源说明的完整工件都受 `limits.max_file_bytes` 和 `uploads.max_file_bytes` 约束；附件总量还受 `uploads.max_total_bytes` 约束，完整回执受 `limits.max_output_chars` 约束。编码错误、NUL、空正文、非文本、私网地址、超限或无法完整返回回执时会报错，不保存节选冒充全文。

每次重定向重新检查公开地址，并固定已核对的地址进行连接。等待期间收到新输入、停止、设置或执行模式改变时，旧请求不能迟到提交。一次明确捕获没有隐藏重试；下载后本地保存失败时先核对附件目录，不自动再抓网页。

再次明确捕获同一网址会创建另一个快照，保留旧文件、书签和摘录；网站后来的变化不会改写旧资料。文件丢失或版本变化时，续读会拒绝旧位置。

捕获、阅读、书签和摘录都不自动发送消息，也不调用长期记忆整理。暂时只想找某句话时，可以在选定快照中使用[正文定位](attachment-find.md)。

## 明确收藏到长期参考

想以后按内容找回，可以说：“把刚才那份网页快照收藏为长期参考。”主助手用独立的 `memory_import_webpage(id, revision)`，指定捕获回执中的准确附件 ID 和 SHA-256。同一网址有多份快照时，先核对具体哪一份。

收藏只读取并核验本机保存的完整快照，不再访问网站。请求网址、最终网址、宿主采集时间、范围和完整正文一起保留；普通上传即使仿写同样的头，也不能通过网页入口。`memory_import_attachment` 继续拒绝网页快照。

小回执中的 `created` 和 `state` 表示实际登记与后台状态；重复收藏可能返回已有的 processing、retry、done 或 failed，不会重建同一作业。可以继续聊天，不需要等模型整理完成；done 也不证明文章真实或已被完整理解。之后用 `memory_query` 找资料、`memory_source` 核原文，见[收藏资料](attachment-memory.md#收藏已捕获网页)。

来源 ID 是 `attachment:<快照ID>`，标记含 `webpage:v1` 和范围。收藏使用附件摘要；来源分页、比较和重试使用来源目录返回的 `revision`，两者不同。删除原附件不会删除已收藏原文；遗忘也不会删除独立附件，同一旧 ID 重放不能复活已遗忘来源。

网页收藏使用 `memory=3`；旧资料库按[停机升级说明](channel-ownership-format-upgrade.md)处理。收藏后的提炼、embedding 和查询重排可能把相关文字发给已配置服务，费用和可用性沿原有记忆设置。

原来的 `web_fetch` 保持短预览用途，没有完整留存或跨重开的续读身份。网页捕获自身只请求目标公开站点并保存本机文件；之后实际阅读会把所读文字随正常模型请求发送，明确收藏还可触发已配置的后台记忆服务。
