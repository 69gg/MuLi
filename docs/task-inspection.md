# 按需核查长期任务

可以直接问沐璃：“这件事做到哪了？”“按哪些要求验收？”“还有谁在处理？”“这份成果的依据是什么？”沐璃会读取已保存的任务说明、队友状态、报告与成果记录，而不是仅凭聊天摘要回答。

核查只读资料，不确认方案、不恢复暂停任务、不唤醒队友，也不会重新执行旧操作。暂停、补充要求与继续任务见[任务控制](task-control.md)。

## 内容

先指出准确任务；不确定时，请沐璃先确认任务名称和目标。然后可以按需要追问：

| 想核查什么 | 可以这样问 |
| --- | --- |
| 当前完整要求 | “读这个任务的目标、限制、下一步和当前计划。” |
| 谁还在处理 | “列出这个任务的队友和工作流状态。” |
| 当前在等什么 | “核查这个任务谁在执行、等批准，或等命令结束后继续。” |
| 已有报告 | “查看队友报告，包括还没交回主会话的报告。” |
| 原始依据 | “任务引用了哪些消息或附件？哪些还能读取？” |
| 已登记成果 | “列出交付记录，区分文件事实、模型判断和未验项。” |
| 要求变化后的成果 | “对照这份旧成果与现在的完整要求，说明还需补什么。” |
| 指定队友的近期证据 | “核查这位队友最近的工具结果和状态，再决定如何接办。” |
| 相关记忆 | “查找与这个任务的某个具体问题有关的记忆和来源。” |

网页团队中的“查看任务说明”可用于先确认任务。详细核查可在聊天中让沐璃继续读取；不需要手工拼接记录或游标。

## 核查当前等待

“当前等待”将保存的队友状态与当前执行分开核对。它可以说明某位队友是否仍有真实运行、是否有正在等待主人决定的工具审批，以及是否登记着本次服务运行期间的命令完成续办。队友一轮已经结束时，仍可能在等原命令结束；命令已结束待续办与原队友已经开始下一轮也会分别说明。

需要批准时，沿现有 Web 待批准列表或[手机审批](channels.md#手机上的工具审批)作决定，再让沐璃核查一次。审批结束、命令结束或队友本轮结束，都不代表长期任务已经验收完成。核查不会代你批准、唤醒队友或重新执行命令。

资料缺失、关联不符、正在停止或超出预算时，会说明当前事实不可用，不能理解成“没有等待”。普通报告中的“等主人补充”仍是资料，本入口不会仅凭这些文字生成正式待办。

命令续办登记只在当前服务实例有效。正常重开后不会恢复许可；旧回执仍须沿原命令编号核查，不能据旧文字自动重做操作。

## 如何看待成果与验收

任务完成、队友报告、附件存在、验收通过是不同的事实。需要检查成果时，应同时核对要求和依据。

显式登记的交付验收单区分两部分：

- **文件事实**：登记时核对过的文本附件副本、大小和 SHA-256 等。它不证明内容正确，也不证明文件一定由该次执行新生成。
- **模型判断**：是否满足目标与限制、哪些未验、还需补做什么。这是模型判断，不代表主人已经接受成果。

查询不会自动登记新验收单，也不会重新读取附件并宣布复验成功。需要检查当前文件时，应明确要求继续读取准确附件。

任务要求或相关队友完成状态改变后，旧交付单会标为历史，仍可查阅。对照旧单与新要求时，沐璃可以说明文字变化、可能复用的成果和需要补做的部分；旧要求下的“满足”不会自动沿用到新要求。

## 分页

资料较多时，沐璃会分批读取目录和正文。目录只是定位入口，不等于已经读过报告、附件或全部原文。需要全文时，可以要求“继续读完，再给结论”。

为工具客户端保留的入口是 `commitment_inspect`：主助手指定任务 `identifier`，已绑定队友只能读取当前任务。常用分段有 `task`、`agents`、`reports`、`workflows`、`evidence`、`memories`、`handoff`、`deliveries`、`delivery_review` 和 `current_wait`。其中相关记忆需明确查询词，接办需指定队友，成果变更复核需指定准确旧单。

`current_wait` 只接受任务和目录参数，返回有限候选窗口；空 `items` 仍应按 `has_more` 和 `next_cursor` 继续。`unavailable` 包含无法核对的候选或当前事实，不是零等待计数。游标限定本次服务实例、任务与查询预算，重开或预算变化后从首页重新查询；每页重新核对实时事实，不能把多页当成某一时刻的完整快照。原审批参数、报告正文和命令输出不在等待页中返回。

客户端应原样使用返回的目录游标和正文版本、字节偏移续读，不从不透明 ID 推断含义。认证管理客户端也可通过 `GET /api/commitments/{id}/inspection` 查询。

## 变化与纠正

清单反映读取时的状态，活跃队友和报告可能随后变化。任务要求或正文已经改变时，应重新读取，不能拼接两个版本的内容。缺失、损坏或超出读取预算的资料会明确失败，不从旧摘要补猜。

报告只能提供实际保存的内容：如果入库前已经限长，核查不能恢复丢掉的部分。原消息可继续用会话证据读取，附件用附件工具，记忆原文用 `memory_source`；“相关记忆”不证明当时执行曾采用它。

发现问题后，可以更正或遗忘记忆，或暂停任务、追加要求并交沐璃重新规划。接办前尤其应区分“明确未执行”和“结果未知”：未知操作不能仅凭旧报告自动重试。

更多说明见[按最新证据接办](task-handoff.md)、[记忆与来源](memory.md)和[资料交接](teammate-attachments.md)。
