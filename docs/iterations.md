# 自主迭代记录

## 验收循环

每轮按“接口核实 → 并行实现 → 独立评审 → 故障回归 → 文档/版本/签名提交 → 远端 CI”推进。下一轮调研与上一轮评审并行；不同 agent 独占文件，接口由主 agent 协调。不会因为功能入口出现就结束验证。

## 第一轮：新运行核心

- 协议：三种原生模型 API，独立离线协议测试。
- 执行：统一权限、会话时间线、文件/网络/记忆/电脑工具。
- 协作：DAG 节点隔离会话、并行/步骤/时间预算，最终复核模板。
- 主动性：chiliarch 真正的 agent SSE 和持久回执，不假设不存在的公共 workflow API。
- 管理：简洁蓝色网页、Linux 用户服务和可编辑设置。

独立评审定位并修复 DNS 重绑定、重复信封内容冲突、遍历预算、取消后的子进程残留、无障碍节点身份等问题。实现、协议研究和界面验证并行开展，未修改参考仓库。

## 第二轮：长期使用能力

- 持久时间提醒：确定性调度，不用模型轮询；管理下一次触发、停用、重复周期与取消。
- 记忆生命周期：全历史倒排索引、旧记忆召回、变更记录、关系来源与级联忘记。
- 工作流模板和复核闭环：研究→行动→复核，节点会话、失败定位与父子生命周期关联。
- 可选 MCP 工具兼容和运行诊断，沿用同一个权限门；密钥脱敏、原位保存和显式删除。
- 工作台真实增删改、记忆图、提醒、导出和高级配置验收。

## 第三轮：上下文与发布可靠性

- 确定性上下文节选：保留最新用户输入、完整工具配对及原生模型回放；不改持久原文，不额外调用模型。
- 主会话和工作流分别限制未完成任务数；并行名额为一时父子任务仍能完成。
- 修复同会话并发启动、首次调度前取消、完成结果丢失、配置更新交错等竞态。
- 修复 AT-SPI stderr 警告污染 JSON，并在本机验证只读能力和 30 个有稳定身份的节点。
- UTF-8 配置与回收元数据，跨平台测试按真实能力区分；systemd 路径转义、退出期限与资源约束。
- 界面刷新恢复未完成回复，API 参考仅加载本机资源，不依赖 CDN。

首轮远端矩阵发现三处测试可移植性假设：Windows 文本写入/标准错误使用 CRLF，macOS 临时路径含 `/private/`，不能把路径中的普通单词当成密钥泄露。测试改为明确验证 LF/CRLF 字节保留、平台换行以及具体密钥字段脱敏；没有降低工具行为要求。CI 由 PR 更新和 main 推送触发，同一分支只保留最新运行。

第二轮仅 Windows / Python 3.12 的提醒测试失败。原测试以 50 次 5ms 休眠代替等待通知；CPython 定时器允许在一个时钟分辨率以内提前唤醒，短休眠次数不能保证实际已到期。Linux 模拟粗分辨率并持续提供就绪回调时，原循环在约 0.6ms 内结束而取消调度器，复现了零通知；改为等待通知事件后约 20ms 正常触发。这是计时机制复现，未声称测得远端 Windows 的真实时钟数据。测试现在等待可观察的通知事件，校验没有提前发送，并真正关闭、重开 SQLite 验证去重；另以受控墙钟覆盖提前唤醒和时钟回拨。超时仅用于检测卡住，不以休眠次数衡量正确性。生产调度逻辑未改动。计时依据见 [CPython asyncio 文档](https://github.com/python/cpython/blob/main/Doc/library/asyncio-eventloop.rst)与 [Python 3.13 Windows 时钟变更](https://github.com/python/cpython/blob/main/Doc/whatsnew/3.13.rst)。

未验证：真实模型供应商、chiliarch 实际配对、桌面点击/输入和 systemd 安装/启用。协议与故障测试不替代这些实测。AX、UIA、图像坐标后端和向量语义召回不属于 v1.0.0 已实现能力。

## 资源约束

不运行本地模型、不安装大型库、不进行真实桌面点击或破坏性测试。开发使用临时目录和假模型；模型和桌面联调若未实际执行，明确记录为未验证。依赖下载使用直连，避免代理计费流量。
