# 2.18 系统错误的真实请求来源

状态：已发布。本版接入统一系统事件的两种明确来源，不包含跨进程恢复或 A/B 安装。

主会话错误以当前任务和已构造的 PreparedRequest 为依据。请求构造、认领、工具批次与驱动收尾各边界清理作用域，子任务不能继承父来源；显式 notify=false 和注意事项自身失败的抑制保留。只有自主目录 watcher 的明确生产者可按默认渠道或记忆偏好创建独立通知，手动重载即使也经过 watcher，仍由请求代号区分。

独立审查修复三处窗口：busy/queued 状态变化不能让同一个目录错误重复生成事项；合法长路由及记忆证明的原证据读取预算增至 32 KiB，而公开查询输出预算不变；子 Task 清除父来源时仍保留显式通知抑制。事件与来源原子保存、canonical 反查、冻结地址与逐段发送核验继续复用已有链路。

作者经 guard 完成 24 项新增用例与 134 项既有相关回归、6 文件 Ruff/格式和 4 源码 mypy，最大峰值 124.5 MiB、swap 0。独立最终静态审查无阻断；全部模型、HTTP 和外部平台使用替身，无真实账号发信或设备操作。
