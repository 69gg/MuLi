# 连续终端会话

可以让沐璃或队友在自己的会话中连续执行命令，例如先切换项目目录、设置环境变量，再运行后续步骤。一次正常的模型回复结束后，终端仍可继续使用；不同助手会话各自隔离，不共用目录或环境变量。

这项能力使用服务进程的操作系统权限，不是安全沙箱。命令执行和停止终端都沿用当前 ask、auto、yolo 权限规则。不要把不可信网页或文件里的命令当作主人授权。

## 执行和查看

`shell_run` 支持两种互斥用法：

- `argv` 加 `cwd`：保持原有的一次性执行方式，不经过 shell 解释，最多执行 30 秒；不会保存环境。
- `command`：在当前会话的持续 shell 中执行一段命令。首次可指定 `cwd`，之后省略则沿用终端目录。`wait_seconds` 控制等待本次回执的时间，`timeout` 控制命令总期限，均受现有运行限制约束。

例如模型可以先调用：

```json
{"command":"pwd","cwd":"/home/example/project","wait_seconds":1}
```

回执带有 `command_id`、`state`、输出和续读游标。`running` 表示命令仍在执行，应使用同一 `command_id` 调用 `shell_read`，不要重复发送原命令。

预算连命令身份都无法容纳时，会在启动终端前拒绝，不清除已有终端和上一条回执。其余情况仍会在派发前核对完整回执预算。

`shell_read({})` 只查询当前状态，不启动终端。读取输出时传入 `command_id`，并将上一次的 `next_cursor` 原样作为下一次的 `cursor`。游标包含 `output` 和 `stderr` 两个字节偏移，省略游标则从两流开头读取。两项偏移之和小于 `observed_bytes` 时，还有输出可以续读。回执保留完整状态和分页信息；`truncated` 表示较早输出已经超出保留范围，并不表示可以重新执行命令。

只有 `completed` 的 `exit_code` 可用来判断已完成命令的退出状态。`unknown` 表示无法确认结果，先核查文件或实际状态，不要自动重做可能产生副作用的操作。终端输出不是交互式 TTY，同一终端一次只执行一条命令；需要交互输入或自行读取协议输入的程序不适合这种方式。

## 命令结束通知

主人可以明确要求：“先运行这个命令，这轮先结束，命令结束后在 Web 通知里告诉我。”主助手可在该次 `shell_run` 的 `command` 分支指定 `notify_on_finish: true`。省略或传 `false` 时保持原行为；一次性 `argv` 不接受该参数，队友不能登记完成通知。

回执中 `notify_on_finish: true` 和 `notification_destination: "web"` 仅表示已为这条命令登记通知，命令是否完成仍看真实状态。普通新输入和无关模型配置变更不会把选择挪给另一条命令。命令认证完成后，通知显示原命令编号和实际退出码；超时、主动停止和状态未知分别说明，未经认证的退出码不当作完成结果。退出码 0 也不代表任务成果已经验收。

通知保存在现有 Web 通知列表，可打开原会话核查；重复收口不会重复新增，也不会把已读通知改回未读。通知不包含命令正文、目录或输出，不自动读尾部、不启动模型回合、不向渠道外发。已有 Linux 桌面通知副本仍遵循原开关。需要结果时，再明确要求按原 `command_id` 调用 `shell_read`。

正常关闭会在数据库关闭前收口命令，并保留相应本地通知；重开后不重新执行或补登记旧命令。会话身份已经删除时，不生成迟到通知。崩溃、强杀或本地通知写入故障可能没有通知；这时按原命令编号核查回执与实际状态，不要因没有通知重做命令。通知选项不增加运行额度、模型调用或新的收费服务。

## 停止与保留范围

`shell_stop({})` 停止当前会话拥有的终端及子树，随后再次执行会建立新的操作系统会话。停止不会撤回已经发生的修改。

主人停止会话、任务暂停或撤销执行资格、模式变化，以及运行失败或取消时，宿主会收口相关终端。普通新输入会使尚未派发的旧调用留待重新规划，不会停止已经获准执行的命令。正常完成一个模型回合也不会销毁终端，因此可以在下一回合继续查询原命令的状态和输出。

队友已返回结果、其运行槽已释放后，主人停止该会话或暂停所属任务仍会收口它保留的终端。生命周期回归以真实命令的就绪输出和队友生产终态同步前置条件，并正常接收队友结果通知；命令和主流程仍有独立的硬超时约束。

终端进程和环境仅保存在当前服务进程中。正常关闭 MuLi 时会主动收口终端及其连接，不会等待空闲终端自行断开。关闭或重启后不会恢复旧 PID、环境变量或后台命令，也不会自动重放旧命令。维护操作需要终端收口后才能进入空闲状态。

## 正常重开后查回执

正常关闭成功时，会保留有限的命令回执，包括宿主已经观察并保留的双流 bytes、原 `command_id`、`os_epoch` 和终态。重开后，同一会话可按原编号及原双流游标调用 `shell_read`，核查上次尚未读到的保留尾部。结果的 `receipt_source` 为 `stored`、`shell_state` 为 `closed`、`shell_pid` 为 `null`；读取不会创建终端。空参数查询仍只描述当前进程，新实例尚未运行命令时为 `not_started`。

忘记命令编号时，可以明确要求“列出本会话正常关闭后保存的回执”。`shell_history` 只返回当前真实调用会话的回执目录，包括原 `command_id`、`os_epoch`、终态、退出码与是否截断；不会读输出正文，也不列当前内存里的运行命令。主助手和队友各查自己的会话，不能传入其他会话编号。

目录按回执的归档事件倒序排列，不代表命令实际执行时间。可传 `limit`，单页数量受现有搜索结果上限及完整输出预算约束；有 `next_cursor` 时将它原样作为下一次的 `cursor`，为 `null` 时本页结束。选中编号后，再用原 `shell_read` 完整核查保留输出；目录中的元数据本身不证明输出正文可读。目录不会创建终端或延长保留时间，仍经过当前 ask、auto、yolo 与工具启用检查。不存在的会话、无法核查的记录或不足的输出预算会明确报错；空目录仅表示没有可列出的保留回执，不能据此重新执行副作用。

原命令只有经过原认证完成通道及双流结束标记，才能保留为 `completed` 并带有效退出码。运行中的命令在正常关闭、确认收口后记为 `stopped`，退出码为 `null`；`unknown` 和 `timed_out` 不升级为完成。这里只承诺宿主已经观察并保留的 bytes，不保证关闭时仍在操作系统管道中的全部尾部。强杀、崩溃、掉电及归档失败没有这项保证；找不到记录也不能推断为从未执行或仍在运行，不要据此重做副作用。

内存命令和持久回执各自最多保留 `max_pending_runs` 条，持久上限由所有会话共用；输出沿用 `max_output_chars` 的 byte 保留上限。读取遵守当前权限和输出预算，不因为旧 epoch 取得新授权；调小上限后按当前额度裁掉较早 bytes，保留绝对游标及 `truncated`。归档按持久事件序号淘汰旧记录，读取不延长保留时间，没有新命令归档时不主动清旧回执。

回执保存在本机 SQLite 中，未读尾部可能首次落盘，包含命令输出里的敏感文字。Base64 只是保存原始 bytes 的编码，不是加密，也不自动脱敏。回执正文不会自动进入模型上下文或向渠道外发，只有当前获准的显式 `shell_read` 才交付内容。删除普通会话会同时删除其持久回执，随后关闭不会复活；容量淘汰不删除已经保存的旧工具消息。删除不承诺擦除 SQLite 空闲页、备份或已经送达的内容。

真实关闭、重开、未读中文双流尾部及不重放旅程首片限定 POSIX；纯持久 reader 的格式和分页回归不创建进程。Windows 原生 shell 的输出格式化与真实重开旅程仍需独立平台验收。

## 系统默认 shell

当前使用系统默认 shell，不需要新增配置：POSIX 使用当前用户的默认 shell；Windows 优先 PowerShell 7，否则使用系统 cmd。当前协议支持 sh、dash、bash、zsh、fish、PowerShell 7 和 cmd；默认 shell 不支持时会明确报错，不会静默换成另一种 shell。

Windows 上的工作目录、宿主程序和临时目录路径可以包含中文。cmd 会在派发命令前确认输入与输出均为 UTF-8；确认失败时不会执行命令。cmd 仍会拒绝包含双引号或百分号的宿主协议路径。

当前没有自定义 shell 选择项。更改模型等无关配置不会重建空闲终端；服务重启后新建终端时重新选择系统默认 shell。
