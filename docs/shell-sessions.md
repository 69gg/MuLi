# 连续终端会话

可以让沐璃或队友在自己的会话中连续执行命令，例如先切换项目目录、设置环境变量，再运行后续步骤。一次正常的模型回复结束后，终端仍可继续使用；不同助手会话各自隔离，不共用目录或环境变量。

这项能力使用服务进程的操作系统权限，不是安全沙箱。命令执行和停止终端都沿用当前 ask、auto、yolo 权限规则。不要把不可信网页或文件里的命令当作主人授权。

## 执行和查看

`shell_run` 支持两种互斥用法：

- `argv` 加 `cwd`：保持原有的一次性执行方式，不经过 shell 解释，最多执行 30 秒；不会保存环境。
- `command`：在当前会话的持续 shell 中执行一段命令。首次可指定 `cwd`，之后省略则沿用终端目录。`wait_seconds` 控制等待本次回执的时间，`timeout` 控制命令总期限，均受现有运行限制约束。

例如模型可以先调用：

```json
{"command":"pwd","cwd":"/home/example/project","wait_seconds":1}
```

回执带有 `command_id`、`state`、输出和续读游标。`running` 表示命令仍在执行，应使用同一 `command_id` 调用 `shell_read`，不要重复发送原命令。

预算连命令身份都无法容纳时，会在启动终端前拒绝，不清除已有终端和上一条回执。其余情况仍会在派发前核对完整回执预算。

`shell_read({})` 只查询当前状态，不启动终端。读取输出时传入 `command_id`，并将上一次的 `next_cursor` 原样作为下一次的 `cursor`。游标包含 `output` 和 `stderr` 两个字节偏移，省略游标则从两流开头读取。两项偏移之和小于 `observed_bytes` 时，还有输出可以续读。回执保留完整状态和分页信息；`truncated` 表示较早输出已经超出保留范围，并不表示可以重新执行命令。

只有 `completed` 的 `exit_code` 可用来判断已完成命令的退出状态。`unknown` 表示无法确认结果，先核查文件或实际状态，不要自动重做可能产生副作用的操作。终端输出不是交互式 TTY，同一终端一次只执行一条命令；需要交互输入或自行读取协议输入的程序不适合这种方式。

## 停止与保留范围

`shell_stop({})` 停止当前会话拥有的终端及子树，随后再次执行会建立新的操作系统会话。停止不会撤回已经发生的修改。

主人停止会话、任务暂停或撤销执行资格、模式变化，以及运行失败或取消时，宿主会收口相关终端。普通新输入会使尚未派发的旧调用留待重新规划，不会停止已经获准执行的命令。正常完成一个模型回合也不会销毁终端，因此可以在下一回合继续查询原命令的状态和输出。

队友已返回结果、其运行槽已释放后，主人停止该会话或暂停所属任务仍会收口它保留的终端。生命周期回归以真实命令的就绪输出和队友生产终态同步前置条件，并正常接收队友结果通知；命令和主流程仍有独立的硬超时约束。

终端仅保存在当前服务进程中。正常关闭 MuLi 时会主动收口空闲终端及其连接，不会等待空闲终端自行断开。关闭或重启后不会恢复旧 PID、环境变量或后台命令，也不会自动重放旧命令。维护操作需要终端收口后才能进入空闲状态。

## 系统默认 shell

当前使用系统默认 shell，不需要新增配置：POSIX 使用当前用户的默认 shell；Windows 优先 PowerShell 7，否则使用系统 cmd。当前协议支持 sh、dash、bash、zsh、fish、PowerShell 7 和 cmd；默认 shell 不支持时会明确报错，不会静默换成另一种 shell。

Windows 上的工作目录、宿主程序和临时目录路径可以包含中文。cmd 会在派发命令前确认输入与输出均为 UTF-8；确认失败时不会执行命令。cmd 仍会拒绝包含双引号或百分号的宿主协议路径。

当前没有自定义 shell 选择项。更改模型等无关配置不会重建空闲终端；服务重启后新建终端时重新选择系统默认 shell。
