# 主动通知的显式记忆绑定

状态：B 阶段已实现并完成独立复审与定向离线验证，纳入 2.17 候选；依赖[主动投递 A](proactive-delivery-v2.15-design.md)的配置、冻结目的地与出站撤销检查。完整整合与发行证据见 [2.17 审查](review-v2.17.md)，不代表真实平台账号已验证。

## 用户行为

主人可以让沐璃将一条已保存的偏好用于主动通知，也可以在设置中选择或取消。配置保留确切的 `memory_id`、`version` 和结构化 `destination`，空值表示使用普通默认目的地。外部目的地继续使用 A 的账号／收件人校验与一次保存启用流程。

选择只影响随后产生的独立事项。原会话回复优先；旧事项继续使用已经固定的目的地。偏好被更正、遗忘、进入冲突、取消绑定或记忆关闭后，新事项显示原因并使用配置默认；旧的依赖该偏好的待发项保持 blocked，只有显式重试并重新核对原依据才可继续。

记忆正文及逐字引用提供可供用户核查的理由，结构化配置承担选路含义。后台提炼不会自行改设置。新消息尚未提炼出合格偏好时，绑定返回未就绪；普通默认渠道仍可立即配置。

## 复用当前事实

`memory_meta` 已保存 `layer/source_id/trusted_owner/status/version`；`memory_sources` 保存原始 `role/principal/trusted_owner/digest`。记忆更正递增版本，冲突解决同时递增选中和被取代记录的版本；来源遗忘通过现有级联删除事实。无须新记忆表、迁移、向量查询、模型调用或后台扫描。

验证一次确切 ID，只从现有主键连接读有限元数据：事实和来源存在，事实是 active 的 preference，版本相符，双方 trusted_owner 为真，来源是 user/owner，且来源摘要格式有效。不读取全文、关系、图路径或冲突清单。当前 `Memory.get()` 会读取关系及冲突列表，不用于发送前检查；`MemoryEvidence.detail()` 可继续用于用户主动核查原文的界面，不混作自动投递校验。

配置输入只有事实 ID、版本与目的地。宿主在有效选择时取得来源 ID 和 digest，随 canonical routing 冻结为本次依据；模型不能提交这两个值代替来源验证。后续逐次点查比较来源 ID、digest、版本、状态和当前绑定。这里依赖现有来源登记的不可变摘要合同，不宣称可抵御直接修改 SQLite 的同权限插件。

## 连接点与顺序

1. 先增加单一严格的可选配置对象，沿用 A 的目的地类型。新建、更换或重新启用绑定时，在完整候选中校验；该操作排队到真正应用时再次核对，失效则保留原配置并报告原因。未更改的历史绑定失效不能阻止关闭记忆、撤销渠道权限、暂停外发、取消绑定或保存无关配置；这些操作允许生效，后续选择与发送按当前证据处理。按既有设计只对这一个判别对象使用整体替换，避免递归补丁残留旧渠道字段。
2. 增加小型只读验证函数，返回固定原因或不可变证据。没有副作用、await、独立缓存或长期 seen 集合；不调用 `Memory.get/query/owner_profile` 或 pipeline。
3. A 的独立事项选择器优先用有效绑定，其次配置默认。选择发生在首次 durable 事件前，证据与生产记录／事件一起保存。来源已绑定的事项不进入此选择器。
4. 同目的地批次还须具有相同依据：default 与 memory 分开，不同事实、版本或来源摘要也分开。复用现有连续前缀认领，不能只按收件人合批。
5. 自动外发入队及每个分段发送前都复核。取消当前绑定、关闭记忆、事实／来源变化、账号或收件人授权撤销均 blocked；默认目的地的普通变化不重定向原项。unknown 不自动重试。
6. 现有设置显示当前绑定、版本、有效状态和短原因；原文仍按需通过证据入口读取。状态和通知元数据不复制记忆正文、凭据或原文引文。

真实配置保存与事件生产各用自己的短事务；不跨 await 持有 SQLite 事务，也不使用嵌套 Connection 上下文模拟 savepoint。只读验证不自行提交调用方事务，所有实际写入仍由 A 或现有配置管理入口拥有。

## 有限回归

使用临时真实 Store，按原有来源登记／提炼／更正／冲突解决／遗忘 API 产生状态，证明有效绑定、同版本重复查询、更正版本失效、冲突解决旧绑定仍失效、来源遗忘、记忆关闭、手工不可信记忆拒绝。伪造工具参数中的 trusted_owner/source_id/digest 不能获得宿主证据。

以抛错替身阻止全量 Memory.get、检索、embedding/reranker 和模型入口，证明选择与发送前只做主键元数据点查；检查实际 SQL 计划的三张表主键访问，而不扩数据量做压测。只读验证前后资料库状态一致，原文与关系清单不进入返回值。

新增回归还覆盖完整配置候选／排队及关闭组件期间证据变化、连续批次依据差异、入队及附件读取后撤销、分段发送前撤销、重开后冻结路由保留、blocked 显式重试及 unknown 不重发。A 的普通默认、原会话回复与 WebUI 行为保持；定向检查使用 guard，完整数据与边界集中记录于审查文档。

方法已通过 Context7 核对 Python [sqlite3 参数绑定、fetchone 与事务上下文](https://docs.python.org/3/library/sqlite3.html)：固定字段选择、占位参数和一个现有连接足够，不新增依赖。
