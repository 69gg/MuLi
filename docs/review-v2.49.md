## 实现与权限

- 复用 Reminder、Attention、ReplyOrigin 和 Store，不增加调度器、数据库、模型轮询或主界面。仅两个既有内建提醒工具成为主助手协调工具，仍为 write；Attention 继续只允许 read。
- 创建关联按准确任务主键有界核对身份与状态，提醒只保存定位。到期实际用 `commitment_read` 与 `commitment_inspect(section=deliveries)` 读取最新要求及准确单，区分登记时的文件事实、模型判断与未验要求。
- 宿主绑定版本在任意显式编辑时递增，解绑仍保留计数，防止同任务重绑复活旧通知。通知冻结同一 current 快照的文案、绑定、发生次序与 routing，来源读取及原子接纳前各自复核；自然 disabled/next due 与任务 revision 更新不误撤发生事项。
- 删除、编辑和 done/cancelled 可拒绝尚未最终接纳的旧通知；已经接纳或开始的运行不承诺追回。暂停或未知不恢复、不批准、不派工、不重发，也不自动发送文件。回复发送时仍重核当前 owner。
- 七种持久格式、原 16,000/6,000 字符预算和 3 个 pending 槽不变。普通从未绑定提醒不增加绑定字段。

## 历史失败与处理

1. 首跑停在主会话未提供 `reminder_schedule`，1 failed，pytest 0.60 秒，守卫 1.290 秒、94 MiB。此为主协调能力缺口，尚未触及关联参数。仅登记两个提醒名称为协调工具后继续取红。
2. 随后取得准确绑定入口红：1 failed，pytest 0.60 秒，守卫 1.330 秒、91 MiB。真实 accepted 工具结果为 `ValidationError`，来自 schema 拒绝新参数；任务、要求修订、队友完成及验收前置均成立，不是 handler TypeError。
3. 首实现旅程末段重复游标观察超时：1 failed，pytest 4.67 秒，守卫 5.383 秒、96.4 MiB。Attention 跳过重复只保存游标，夹具却等待新总线通知。仅改用现有 Attention 的三秒有界观察 helper，未增加期限、模型轮数或出站数量；原 selector 随后完整通过。
4. 接纳十项首跑 9 passed、1 failed，pytest 1.26 秒，守卫 2.119 秒、128.4 MiB。缺失任务原 oracle 写 400，真实既有 `evidence_not_found` 映射为 404；只修此状态预期，其它拒绝与无创建断言保留，单 selector 随后通过。
5. C 独立源读取取得真实 OverflowError 红：1 failed，pytest 0.12 秒，守卫 0.643 秒、59.9 MiB。通知时间为 `10**400` 时 `math.isfinite` 的整数转浮点溢出；仅在该转换处受控返回 False，不设时间上限，不捕获整个存储流程，原独立 oracle 随后通过。
