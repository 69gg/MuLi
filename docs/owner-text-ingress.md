# 主人原始文字来源合同

持久 `ingress.payload` 可带宿主内部 `owner_text` 描述符：

```json
{"version": 1, "kind": "web", "chars": 8}
```

`kind` 仅为 `web` 或 `channel`，`chars` 是 Python Unicode 字符前缀长度，包含主人原样发送的前后空白、组合字符和换行；不做规范化，也不复制正文。正文及模型提示保持原有装配方式。

主 Web 消息端点在替换附件占位前，从非空白 `body.content` 取得长度。渠道接收器在追加附件占位、超额提示及下载告警前，从已绑定主人非空白 `message.text` 取得长度，经现有配置世代守卫和稳定渠道事件交给 Runtime。Runtime 仅在实际持久主会话、`owner` 身份、无路由及事件链的 Web 入口，或已核验稳定渠道入口接纳描述符；归属队友的渠道不带描述符。

私有 `_owner_text_chars` 默认 `None`。普通直接提交、onboarding、系统或工作流没有这份证明。空白原文及纯附件不标记；无效长度（含布尔值、零、负数和越界）不生成描述符。该字段不进入 `ChatInput` 或模型工具 schema。

消费者使用 `muli.owner_text.owner_text_prefix`。它严格检查字段、版本、来源类型与 `payload.source` / 渠道路由一致性、字符数及非空白前缀，只返回该前缀；缺失或损坏则返回 `None`，不能退回扫描整段正文。消费者仍须核验真实主会话、主人身份及自己的接纳条件；描述符不是执行或外发授权。

描述符与输入一同入库。渠道重复收据和旧 ID 收据恢复仍先返回原结果。相同稳定渠道输入保留首次接纳时有无该字段及其值，不改旧 payload、不补标旧输入、不制造第二个输入 ID。降级期无标记输入保持无资格，恢复后不能猜测其原文范围。

此基础合同不实现话题规则、提醒生产者、工具、配置或界面，不新增后台任务。
