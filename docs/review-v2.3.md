# 2.3 审查与验证

状态：本地整合与独立验收通过，等待最终远端 CI 与发布核验。2.2 已发布的证据见[上一版审查](review-v2.2.md)。

本轮在现有工作账本、SQLite 入站、团队生命周期和原生工具配对之上实现明确任务控制。目标是让主人能够暂停后续操作、完整追加要求，再交主沐璃重新规划。领域合同、管理接口分别见[任务控制](task-control.md)与[接口说明](task-control-api.md)。不增加模型分类器、后台轮询、平台依赖或新的 agent 身份系统。

## 独立审查

持久领域、运行器与界面分工作树实施；接口和写入边界预先约定，再由其他 agent 复核。主工作树整合 API，使用真实 LocalServices 与运行器进行联测，不以临时接口桩代替执行保障。

已经定位并纳入修复与回归的问题：

- 已暂停队友无法消费满邮箱；计划通知在精确校验后原子写入归档并排队，保留原 pending 输入，不扩容、不先恢复后补通知。
- 计划通知已送达，而旧模型请求随后才停靠；共用证明入口核对当前批准、执行代次、完成修订及真实 ingress/归档引用，只有匹配的通知可续排。普通消息、取消、新暂停和伪造来源不构成证明。
- 投递扫描期间唯一的邮箱容量释放事件可能被重入守卫丢弃；运行器记住真实重入事件，再进行一轮扫描，满邮箱且没有新事件时不自旋。
- 前端纯状态测试无法发现按钮数组被渲染为文字；真实浏览器预验发现后改为插入实际节点，并增加 DOM 回归。
- `run.paused` 与最后工具边界的未执行结果需要独立终态，不能让页面持续显示运行中，也不能显示为执行成功。
- 独立门控证明，最后一次执行检查后才暂停，仍可能产生完成报告并唤醒主助手；报告现在依据当前任务范围暂停状态延后，不能只判断报告本身是否为 `paused`。分页越过延后项，系统注意事项只等待可交接的报告；独立运行器的原反证已经全部转绿，包含真正启动 AttentionInbox 并接收到系统资料。
- 旧报告页在等待后可能已经被停止操作抑制；投递前重新读取持久状态，防止缓存页复活旧报告，同时保留后来新代次报告的交接。
- 热缩上下文预算后，已经知道任务暂停的队友仍先验证完整正文，可能误记失败；停靠只核对控制事实，准备新模型请求才检查正文预算。
- 新主人控制意图立即清除同任务的旧重规划选择，避免失效旧证据阻塞无关主聊天；旧回执的幂等重试不会清除后来合法选择。

## 验证记录

整合后单进程全量 Python 测试 **890 项通过**，前端状态与 DOM 测试 **93 项通过**。其中领域专项 81 项，运行器新增 29 项，管理 API 与原详情组合 16 项；这些属于全量或专项计数，不能相加当作更多独立测试。全部 Ruff、116 个 Python 文件格式检查、65 个源码文件严格 mypy 和离线锁文件校验通过，依赖版本未变化。

独立 reviewer 对冻结运行器候选 `c2fa525` 复核，另跑七项独立反证、正式运行器及原停止/工作流测试，共 85 项通过。核查范围包括真实主助手误唤醒、报告饥饿、系统注意事项、低预算停靠、停止交叠、失效选择、最后工具边界、原生调用配对与同代通知续办；未发现剩余确定阻塞。

候选 wheel/sdist 离线构建通过，临时隔离安装验证 CLI、静态模块、API 文档、提示词、应用生命周期和无模型暂停接口。发行名称、版本与 changelog 一致。前端先用本地 fake 响应验证真实 DOM、手机/桌面深浅主题、未知提交原 ID 重试、401 后迟到响应和工作流冲突。

最终浏览器连接整合后的真实 Runtime/API，主模型使用内存假客户端。实际点击暂停、补充多行要求并交主助手重新规划；网页依次显示暂停、已交沐璃但仍暂停、计划已确认。数据库保存三条对应回执，最终 revision=4、epoch=approved_epoch=2；三次模型请求依次读取、携带完整快照确认、回复，旧两条要求与新增多行完整保留且仅追加一次。此界面用例确认方案但未指定通知目标；队友实际续办由运行器的独立门控和重启回归证明，不能把空目标的界面验收当作成员已执行。

1280×720 浅色桌面与 390×844 深色手机均无页面或对话框横向溢出，浏览器无 JavaScript 错误。临时页面、假服务与进程均已关闭回收；无产品修复依赖更改真实配置。

验证使用假模型、事件门控、临时 SQLite 和本地浏览器服务。没有使用真实模型额度、操作用户桌面或安装/重启用户服务。活动 DAG 中途暂停、自然语言限制的形式化证明、已执行副作用回滚均不属于本版保障。远端 CI、签名标签、PyPI 文件与 GitHub Release 必须逐项核实；当前不宣称 2.3 已发布。
