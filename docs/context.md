# 长对话、压缩与查历史

已绑定并授权给主人的渠道，共用同一个持续的主会话。可以在网页开始，再从另一已绑定私聊继续；渠道授权仍须分别配置，陌生人的输入不会因此取得主助手权限。

当前模型能看到的上下文、已经保存的聊天记录、长期记忆是三种不同内容。上下文为了继续处理当前任务，记录用于核查原始消息，长期记忆用于以后检索相关资料。

## 运行中补充要求

正在处理时仍可以发新消息。收到排队确认表示已经接纳，不代表模型已经读到。补充内容通常在完整响应结束或当前工具返回后进入下一轮，不强行打断正在输出的文字和已经进入执行的操作。

主助手正在等待人工审批时，新的可信主人输入可以撤回尚未开始的旧主调用，让它作为“未执行”收口，再按新要求继续规划。这不会顺带批准或取消队友的独立审批。

附件以引用带入，发送附件不等于模型已经阅读全文。队友与系统通知也会保留各自来源，不会因为进入同一会话就变成主人授权。

## 后台语义压缩

长对话接近上下文容量时，沐璃会在后台整理较早、已经结束的内容。主助手、队友和工作流节点都使用这套机制，正常聊天不必等待每次摘要完成。

摘要重点保留目标和限制、已完成工作、证据位置、待办、未解问题，以及结果未知的操作。它可以帮助模型接续理解，但可能遗漏细节，不能当作新的授权或成功证明。

压缩不删除已经保存的原始消息，也不自动重做旧工具。最近输入和仍然必要的任务说明会保留；查看摘要发现疑点时，可以继续读取历史原文。

### 常用设置

| 配置 | 用途 |
| --- | --- |
| `compaction.enabled` | 是否启用后台压缩，默认开启 |
| `compaction.mode` | `auto` 使用摘要模型；`extractive` 使用本地摘录 |
| `models.compactor` | 单独配置摘要模型，留空则继承主模型 |
| `compaction.trigger_ratio` | 达到多少上下文占用时开始整理，默认 0.75 |
| `compaction.target_ratio` | 整理后的目标比例，默认 0.4，须小于触发比例 |
| `compaction.max_summary_tokens` | 摘要输出上限，默认 1600 |

使用模型摘要会把相应历史内容发给所配置的服务。选择本地摘录可避免这一步模型请求，但不能期待它具备语义归纳能力。摘要服务失败时会保留明确的摘录，不会无限请求模型。

## 最终请求打包

即使后台摘要尚未完成，下一次请求仍需符合上下文容量。较早的工具结果和普通助手文字可能显示为带头尾的节选；必要时，已经结束的旧轮次会移出本次模型上下文。

这只影响本次请求，不会用节选覆盖已经保存的原文。但工具输出在最初保存时也可能受输出限制，因此归档中实际保存的内容不一定包含工具最初产生的一切。

当前输入、必要任务说明或工具调用本身过长时，可能直接提示上下文不足。可以缩小问题、分批提供资料，或调整合理的上下文设置；系统不会为了继续运行而假装已经读完被省略的内容。

## 查找原始记录

可以说：“请查一下上次这一步的工具回执，不要重新执行。”

沐璃可以通过 `conversation_read` 先定位会话里的消息，再按实际消息 ID 读取正文。长正文按返回的位置继续读取，不能把第一页当成全文。它只读取已保存记录，不会调用旧工具、恢复任务或重新投递消息。

网页中也可以进入“运行记录”，按标题查找会话，使用“查看正文归档”逐段阅读。队友详情可查看对应任务记录。更多操作见[网页工作台](frontend.md)与[历史正文归档](history-archive.md)。

如果记录标明曾经节选，只能核查所保存的部分；入库前已经丢失的内容无法从摘要里恢复。原文来自谁、是什么角色，也应与正文一起核对。

## 完整任务说明

绑定任务的队友会得到完整目标、要求和证据引用。这类说明与普通聊天摘要分开保留，避免压缩后只剩一个模糊任务名。

任务暂停、更新要求和确认新方案是独立的控制流程。读到旧说明、旧完成报告或旧授权，不会让一个已暂停的任务自行恢复。具体用法见[任务控制](task-control.md)。

## 正常重开后如何继续

重开会恢复持久会话与已有摘要，但不会把未收口的工具猜成成功。旧调用没有可靠结果时会显示“结果未知”，继续前应先检查文件、平台或其他实际目标。

主助手的持续身份不等于旧工作已经自动继续。队友和工作流的中断状态、已保存结果都可以先查看，再明确决定是否续办。不要仅凭一段摘要重复付款、发消息或执行其他可能已生效的操作。

长期保留的偏好、事实和收藏资料由[记忆](memory.md)提供。自动带入的记忆只是补充背景，与历史原文一样，不会扩大当前任务权限。
