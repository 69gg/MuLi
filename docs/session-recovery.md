# 会话恢复与继续工作

正常重开 MuLi 后，已保存的聊天、工具结果、任务说明和任务记录仍可查阅。正在执行的操作不会从上次位置自动接着跑。

## 正在执行和等待批准的操作

服务重启后，上次尚未结束的运行会标为中断，会话回到空闲；原来暂停的任务仍保持暂停。

旧的运行中提示和审批按钮不会恢复执行资格。需要继续时，沐璃仍会按当前任务状态、工具开关和权限重新核对，旧审批记录不能代替当前授权。

中断前已确认完成、失败或未执行的工具结果保留各自状态。只有开始记录、无法确认结果的操作会显示为“结果未知”，不能据此认定未执行。

## 结果未知时先核查

请先检查原回执、输出和实际成果，再决定下一步。发送消息、写入文件或修改外部数据时，不要因为中断或没有通知就重复执行。

可以直接说：

> 请核对刚才任务的要求、已有回执和实际成果，说明哪些已经完成、哪些仍未知，再继续未完成的部分。

暂停中的任务，请通过[任务控制](task-control.md)补充要求并明确继续。已完成的步骤也应以可核查的成果为准。

## 终端命令与队友续办

终端进程、目录环境和命令结束后的队友续办登记只属于当前服务实例。重启不恢复旧进程、环境变量或后台命令，也不会自动恢复续办登记。

正常关闭成功时，MuLi 会保留有限的命令回执和已观察、保留的输出。可请沐璃先用 `shell_history` 查本会话保存的回执，再用原编号通过 `shell_read` 读取输出；读取仍按当前权限检查。

回执不保证包含关闭时尚未收取的全部输出。崩溃、强杀、掉电或归档失败可能没有完整回执，也不保证保留尚未落盘的尾部；找不到记录不能证明命令未执行。

完整用法和保留范围见[连续终端会话](shell-sessions.md)。

开发者资料见[会话恢复技术归档](../devarchive/session-recovery-design.md)。
