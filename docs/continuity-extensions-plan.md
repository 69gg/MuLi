# 持续扩展与可恢复运行

2026-10-20 新增要求。本文记录待实施合同，不代表下列功能全部已交付；每个切片仍经过独立审查、受限测试、文档同步和发行核验。

## 用户要求

- 兼容 MCP 和 Anthropic Skills，支持从 `~/MuLi` 下约定目录自动发现；MuLi 可以通过自己的工具配置，支持热重载。
- 自身配置、重启和更新的安全失败可恢复，参考手机 A/B 分区：准备候选、校验、切换、健康确认，失败恢复上一可用版本。重启中断尽量短，agent 状态和待办连续衔接。
- 更新可用、日志异常等内部事件抽象为统一的类渠道设施。可设置何种事件及严重程度提醒 agent；日志默认 `error`，可选 `warning` 以上。
- 支持设置主动发送的默认渠道。任务汇报优先回到发起指令的会话；没有来源时使用默认渠道或有效的记忆偏好。默认 WebUI，同一持续主身份不因渠道切换而中断。
- AI 可调用 ASR/TTS，保存、识别及发送语音；补充便于 MuLi 读取自身日志的工具。

以上要求补充既有功能，不取消低资源、非破坏性、未知副作用不得盲目重做、统一权限、有效 GPG 签名与直连小流量的约束。配置、持久资料、用户扩展仍位于用户数据根；目录由现有数据根推导，不能把用户主目录写死进实现。

## 交付顺序与审查门槛

1. 先完成正在收口的 2.11 / 2.12 远端核验，并独立修复重启后网页重放旧运行/审批事件的问题。持久状态、当前进程许可与历史显示分开；不能把没有结果的工具标成成功。
2. MCP / Skills 自动发现与热重载单独设计和实施。候选完整验证后才发布，运行中的调用使用原代，失败不移除仍可用能力；监听文件变化不启动模型轮询或自动下载依赖。目录外引用、文件变化竞争和不完整写入须有明确结果。
3. 复用当前事件、收件和渠道账本统一内部事件与汇报路由，先补有界日志读取和可配置 `error` 提醒。内部资料始终不是用户授权；回执、去重和失败不能反向无限生成新提醒。
4. 复用媒体服务补齐语音工具与发送路径，明确文本、音频文件及渠道 voice message 的区别；不在本机安装 ASR/TTS 模型，不操作真实麦克风验证。
5. 自身管理采用可恢复阶段状态机：候选准备、预检、交接、启动、健康确认、提交/回退。切换前保留可启动旧环境与状态；预检不能改真实用户数据。二进制回退不等于数据库回退，迁移不兼容时不得自动切换。

重启连续性的验收必须覆盖真实持久存储重开、发送结果未知、工具批次中断、团队报告交接、重复重启与失败回退；不以“启动成功”代替业务健康。用户请求的“尽量无缝”不构成对执行中外部副作用恰好一次的虚假保证。

## 资源与验证

本机所有检查继续通过 `scripts/check_local.py`：单次 1 GiB、跨 worktree/agent 共享 2 GiB、swap 0、共享单逻辑 CPU 等效时间、任务数及硬期限。优先临时目录、假服务和确定性门控；不启动真实外部账号、设备、下载器或用户更新。界面仍保持简洁，配置可由自然语言完成，详细诊断留在按需管理入口。
